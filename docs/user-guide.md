# 玩家使用指南

这份文档面向普通玩家，按真实使用顺序说明 d2-tools 怎么安装、登录和日常使用。

## 1. 安装与启动

1. 下载 Windows x64 安装器 `d2-tools-setup-<version>.exe`。
2. 运行安装器，选择安装位置。
3. 安装完成后启动 d2-tools。

d2-tools 不需要你手动安装 Node.js、Python 或 Docker。

## 2. 数据目录与升级

默认数据目录：

```text
%APPDATA%\d2-tools
```

这里会保存：

- Bungie 配置
- OAuth token
- 资料库缓存
- 仓库标签和备注
- DIM 愿望单导入
- 操作日志和诊断数据

安装或更新程序时，这些数据不会被自动删除。

## 3. 首次启动

首次打开时，你会先进入引导或配置状态。你至少需要完成两件事：

1. 填写 Bungie 配置
2. 登录 Bungie

保存配置后，资料库会自动在后台准备，不会阻塞登录。登录成功后会先读取账号原始数据；资料库完成后再补齐装备名称、图标、perk 和活动解析。

更详细的 Bungie Application 创建步骤见 [Bungie 配置指南](bungie-setup.md)。

## 4. 登录 Bungie

配置保存后即可：

1. 点击“登录 Bungie”
2. 浏览器会打开 Bungie 授权页
3. 登录并授权
4. 浏览器回跳后，软件会保存 token

如果授权完成后软件仍然没有进入首页，先看 [常见问题](faq.md) 里的登录章节。

## 5. 后台准备资料库

保存 Bungie 配置后，d2-tools 会自动准备资料库，不需要你再去其他页面寻找按钮。

准备过程中请保持程序打开。登录不需要等待这一步，账号原始数据可以先读取。若准备失败，当前配置不会丢失，页面会显示失败原因和“重试准备资料库”按钮；名称、图标和高级解析会在资料库恢复后自动补齐。

这一步会下载 Destiny 2 资料库，用于：

- 中文装备名搜索
- perk 搜索
- 来源摘要
- 资料库页查询

资料库可以重复更新，不会影响你的 Bungie 配置、本地标签和已登录账号。更新期间，依赖资料库的搜索、详情和活动解析会暂时提示等待，账号登录和原始账号读取不受影响。

## 6. 首页：今日 / 本周

首页主要用来快速看：

- 每日重置
- 每周重置
- 今日行动建议
- 本周重点
- 已接入并且可确认的数据来源状态

这里的原则很简单：只显示 Bungie API 或本地资料库能确认的内容。拿不准的数据会明确显示为空或未接入，不靠猜。

## 7. 账号页

账号页会自动读取当前 Bungie 账号数据，主要包括：

- 角色 tab 切换
- 当前光等
- 当前装备
- 角色背包（“其他”分类仅显示记忆水晶）
- 邮政官
- 材料与消耗品摘要

你可以在这里执行以下常用操作：

- 一键装备最高光等

“装备最高光等”会先刷新账号，再从当前角色、角色背包和仓库里找更高光等的装备。确认执行后，仓库转移和最终装备两个阶段都会在后台持续读取 Bungie 账号状态并逐件核对，不会反复触发账号页前台加载状态：Bungie 明确返回失败的实例立即计为失败；已受理的实例则保持同步确认状态并自动退避刷新，直到真实快照确认已经进入目标角色并最终装备。结果会明确显示成功、失败或部分成功。该操作不会直接分解装备。

角色切换区会同时显示当前光等和八槽最高光等，例如 `476 4/8`。点击“最高可装备”可查看三个武器槽、五个护甲槽的装备、来源、光等和正负差值，并可切换查看“八槽最高”：它按所选职业每个槽位的最高值计算，不要求这些装备能同时穿上，用于查看光等提升进度。账号最高可能包含其他角色持有的装备；当前一键装备只使用目标角色与仓库，两者不一致时界面会明确提示。

## 8. 仓库页

仓库页是 d2-tools 目前最接近 DIM 日常使用体验的部分。

你可以在这里：

- 按武器、护甲、装备、其他查看仓库
- 按位置、弹药、护甲属性、锁定状态、本地标签筛选
- 给装备加本地标签：保留 / 待定 / 清理
- 写本地备注
- 查看同名装备对比
- 复制清理清单
- 用清理模式把目标装备解锁并转移到角色背包

### 8.1 同名对比

“同名对比”模式适合处理：

- 同一把武器有多件不同 roll
- 同名装备分散在不同位置
- 想快速决定哪件留、哪件标成清理

你可以：

- 选中一件作为基准
- 选择其余候选
- 选择清理候选
- 直接点”保留这件，其余待定”
- 直接点”保留这件，其余清理”

### 8.2 清理模式

清理模式不会直接分解装备。它只帮助你：

- 批量解锁
- 批量转移到角色背包
- 生成更容易在游戏里核对的定位信息

最终分解仍然需要你进入游戏手动完成。

### 8.3 武器匹配数据

装备详情和仓库匹配可以读取以下本地证据：

- DIM Wishlist
- 用户明确确认后保存的“我的推荐”

在装备 AI 分析中输入的新知识默认只对本次分析生效；只有在保存确认框中明确确认后，才会写入“我的推荐”。详情推荐和 AI 上下文不会为此自动读取社区网页。

需要使用 DIM Wishlist 时，在“仓库 → 目标与匹配”中选择“导入 DIM Wishlist”：

1. 选择 Wishlist 文件，或按需展开“粘贴文本”。
2. 核对待启用预览中的名称、规则数和 PVE / PVP / 通用模式覆盖。
3. 明确确认启用或替换。保存完成后，当前账号匹配会立即重新计算。

移除已启用的 Wishlist 需要再次确认。历史版本中已经保存的自定义规则仍会兼容参与匹配，并在仓库中标记为“遗留自定义规则”，但应用不再提供新增或编辑这种 Hash / JSON / CSV 规则的普通入口。

### 8.4 装备目标

仓库“目标与匹配”中的装备目标用于保存长期想刷取或想保留的武器与护甲条件。新建目标会写入独立目标库；旧本地目标规则和 DIM Wishlist 在你明确保存或清空对应来源时单向同步，不会覆盖用户目标或 Armor Planner 目标。

武器目标按具体 Manifest 版本和 Perk 归属校验。发现多个同名版本时会保持待确认，不会自动选择；未通过校验的目标不参与仓库或详情命中。护甲待刷目标保存属性、职业和槽位等抽象条件，不会伪造装备 Hash 或实例 ID。Armor Planner 派生的缺口使用单件基础属性门槛进行提示，并保留框架、第三属性、调整、套装和大师杰作上下文；属性命中不代表完整身份已经满足，仍需回到 Planner 复核。

目标命中只在仓库筛选、同名整理和装备详情中提供证据，不会自动收藏、加标签、锁定、转移或改变整理决定。独立装备目标库已包含在设置页创建的便携备份中。

Armor Planner 缺口目标可以选择“查看 Planner 引用”。它会带着稳定的结果 ID 和候选 ID 进入配装页；完整求解结果并未持久化，因此只能用于核对来源并按当前账号、Manifest 和规则重新计算。

## 9. 资料库页

资料库页用于查资料，不直接读取你的仓库内容。

你可以：

- 搜索装备中文名
- 搜索装备英文名
- 搜索 perk
- 保存常用别名
- 看来源、基础说明和 perk 关联信息

它更像“本地 Destiny 资料查询”，不是仓库页的替代品。

## 10. 配装页成果审阅

配装页统一接收 DIM、攻略链接、攻略正文和 AI 整理结果。粘贴链接时，Desktop 会先安全读取正文；应用不会执行页面脚本，也不会绕过登录、验证码或付费墙。选择目标角色后，应用会解析职业、子职业、异域护甲、武器、护甲属性、模组、星相和碎片，并按当前账号核对可用装备。

- 审阅候选：区分确定命中、替代项和缺口，只把明确勾选的装备带入草稿。
- 复核条件：职业、护甲属性、模组预算、异域和套装条件仍可在配装工作台调整。
- 生成草稿：只创建未保存草稿，不自动写入本地方案。
- 保存草稿：写入本地方案；装备、转移或游戏内写操作仍需要你在界面里确认。

如果某个要求无法确认，配装草稿会放进“待确认”，不会当成事实。护甲属性按五件护甲的聚合目标进入 Armor Planner；旧六维名称、同名武器或异域多实例都需要人工复核。只有明确选中的真实候选会进入未保存草稿。旧版本侧栏任务入口保存过文本时，这里会自动恢复；只有成功生成草稿后才清除旧副本。

接受库存或升级候选后，本地方案会保存护甲结果引用、规则版本和来源版本。结果缓存过期时仍保留已经选择的真实实例，但再次调整护甲候选前需要重新计算。待刷模式的候选如果包含缺口，可以选择“保存待刷缺口”写入独立装备目标库；重复保存同一结果候选不会创建重复目标。

攻略链接、正文和 AI 整理结果只用于本次导入，不保存为独立攻略文章，也不建立返回原文的派生关系。装备目标带回的 Armor 结果引用只显示稳定结果 ID 和候选 ID，不能恢复未持久化的完整旧候选，必须按当前账号和规则重新计算。

本地方案中的每个装备目标都绑定当前账号真实实例后，可以在“方案应用”区域复制 DIM 链接。导出会再次核对实例 ID、装备 Hash 和目标 Plug 的插槽位置；理论上限、待刷目标、缺失实例或无法定位的 Plug 会直接显示阻断原因，不会生成伪完整链接。子职业技能、星相和碎片只有在保留原始插槽索引时才能完整交接，当前缺少索引的配置会在导出区明确提示。

应用本地方案时，确认后会先刷新账号并重新核对完整步骤。如果装备位置、实例、目标角色、可写 Plug 或方案缺口已经变化，应用会在任何写操作发生前停止，并要求根据最新账号状态重新确认。

开始执行后，每个转移、装备和 Plug 步骤会记录同一组计划、确认和执行引用。需要排查部分成功或失败时，可以在“设置 -> 诊断与操作日志”中查看执行引用，失败项还可以复制包含完整关联 ID 的脱敏诊断。

执行结束后会额外保存一条“执行验证”记录，结果分为通过、部分完成、不一致和不可用。它和逐步日志使用同一个执行引用，可以用来确认 Bungie 接口成功后账号状态是否也已实际更新。

## 11. AI 助手

AI 助手采用聊天框方式，而不是固定报告按钮。

它可以基于你当前已载入的数据回答问题，例如：

- 这周我优先该刷什么
- 我仓库里哪些装备疑似重复
- 哪些武器适合先保留
- 我现在最值得整理的部分是什么

当问题明确涉及装备定义、Perk、账号已拥有装备、当前商人库存、本地配装缺口或 Armor 3.0 护甲目标时，工作台会在发送给模型前自动运行对应的应用内只读能力。每轮最多运行三项，不会执行转移、装备、锁定或其他写操作；回答底部的“数据引用”用于标识本轮真实读取结果及状态。

Armor 规划问题必须同时写明泰坦、猎人或术士，以及至少一个当前六维目标，例如“术士护甲生命值 100、手雷 100”。库存、理论和待刷问题会复用配装页同一套 Armor Planner。旧六维名称、缺少职业、缺少数值目标或升级基线不明确时不会自动求解，需要先在配装页确认。

商人能力读取当前已缓存库存，不会代替商人页的手动刷新。能力没有命中、账号未登录、库存不可用或结果不完整时，助手应明确说明限制，不能把缺失数据补成事实。

每次成功问答都会创建一个轻量上下文快照，记录页面和账号范围、Manifest 版本、能力结果引用及实际提示内容指纹，不重复保存完整账号装备正文。恢复历史会话时，如果当前数据已经变化，顶部上下文入口会显示“已恢复历史快照”；继续提问会携带有限的历史对话，并基于当前数据创建新快照。失败的请求不会写入会话历史。

应用会在本机保留最近 100 条 AI 只读能力审计，只记录能力名、脱敏查询摘要、结果 ID、状态、耗时、警告码和证据 ID。设置页的“复制脱敏诊断导出”会附带最近的能力审计，不包含完整 AI 提示、账号装备正文、Token 或 API Key。

明确询问配装、构筑或攻略整理时，成功回答下方会出现“配装草稿”。选择“交给配装页”只会打开配装页的攻略文本面板，并带入 AI 目标、整理结果、上下文快照和数据结果引用；仍需选择角色、执行解析与账号核对，然后显式保存本地方案。AI 工作台不会直接创建方案或执行装备操作。

Armor 规划返回候选时会显示“护甲方案对比”，标明模式和达标候选数量。交给配装页后只预填原始职业与六维目标，候选最终属性不会变成新的目标；底层规划结果会作为证据保留，仍需重新检查模组预算、套装、位置范围和实例选择。

明确要求把某件装备加入配装、作为目标或准备刷取时，成功回答下方会显示“装备目标候选”。交给配装页后先逐项复选：账号中已有的候选会绑定真实实例，只有资料库定义的候选会保留为待获取目标。确认只生成未保存草稿，不会自动保存、转移或装备。

支持的模型接口：

- OpenAI Responses
- OpenAI Chat Completions
- Anthropic Messages

如果没配置 AI，页面会提示你先去设置页完成配置。

## 12. 设置页

设置页主要管理：

- Bungie 配置
- AI 配置
- 本地数据目录状态
- 操作日志与诊断信息

## 13. 写操作边界

写操作包括：

- 锁定 / 解锁
- 装备到角色
- 从仓库取出到角色
- 从角色移入仓库
- 一键装备最高光等

应用不再提供额外的本地总开关。写操作需要 Bungie 授权具备对应 Scope，并继续经过操作确认、目标校验和结果刷新；配装应用还会在执行前刷新账号并复核计划。

d2-tools 不支持直接分解装备。

## 14. 常见日常流程

### 14.1 初次跑起来

1. 配置 Bungie
2. 登录 Bungie（不需要等待资料库）
3. 资料库在后台自动准备
4. 自动读取账号
5. 进入仓库页开始整理

### 14.2 清理仓库

1. 进入仓库页
2. 用同名对比查看重复组
3. 保留一件，其他标成待定或清理
4. 进入清理模式
5. 批量解锁并转移到角色背包
6. 进游戏按清单手动分解

### 14.3 冲最高光等

1. 进入账号页
2. 选择角色
3. 点击“装备最高光等”
4. 确认操作

### 14.4 让 AI 帮你分析

1. 先在设置页完成 AI 配置
2. 读取账号和仓库数据
3. 打开 AI 助手
4. 直接输入你的问题
