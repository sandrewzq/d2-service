# 统一装备详情合同

> 本文件合并武器、护甲和共享档案骨架规格。功能语义补充参考 [`equipment-detail-and-knowledge-analysis.md`](../equipment-detail-and-knowledge-analysis.md)。

## 共享档案骨架

稳定契约：`detail.dossier`。

```text
detail-dossier
  dossier-toolbar
  dossier-scroll
    identity
    detail-sticky / section-nav
    dossier-workspace
      dossier-main
      instance-rail
  detail-state-layer
  rail-scrim
```

- 武器和护甲共用档案工具栏、身份区、页内章节导航、连续正文、实例栏、遮罩和状态层。
- 顶层装备详情必须由共享 Overlay Host 通过 Portal 挂到 App Shell 顶层、背景菜单内容树之外，并继续继承当前颜色模式、密度和安全区变量；打开期间 Shell 的其他同级区域设为 `inert`，只有最上层详情接收指针、键盘和辅助技术焦点。关闭后恢复背景原有 `inert` 状态，并把焦点返回触发入口。
- 单次打开周期只能存在一个 `data-overlay-root="item-detail"`。该 Overlay 内部使用 `closed → loading → ready / error` 状态机切换正文，Loading 与完整详情不得分别创建 Dialog、焦点陷阱或背景隔离生命周期。
- 每次打开以 Overlay Store 的 request revision 作为会话身份；关闭、切换对象或新打开命令必须立即使旧 revision 失效。旧异步结果或低优先级渲染即使晚到，也不得重新显示已关闭详情或覆盖当前对象。
- 详情打开、推荐返回、版本返回、实时获取状态和详情内部草稿只允许更新 Overlay 子树，不得使背景菜单重新执行页面 ViewModel、筛选或装备列表 commit；真实账号 Patch 和共享标签变更仍按各自 Store 事件更新受影响区域。
- 武器 Ready 首屏只挂载身份、当前配置、本件 Roll 和实例操作。推荐、属性与获取、升级和 AI 保留稳定章节占位，由 `IntersectionObserver` 在接近视口或玩家点击章节导航时挂载；已访问章节在本次 Overlay 会话内保留。章节导航状态由观察事件维护，不得在滚动事件中循环读取全部章节布局。
- 推荐章节挂载后才读取当前实例完整推荐证据；属性与获取章节挂载后才并行读取同名版本和实时获取状态。只有身份主图允许 eager，版本水印、Perk、来源和升级图标按可见性 lazy 加载。异步结果只改变对应章节数据，不得重新执行与该结果无关的武器配置分类。
- 章节导航只滚动定位，使用 `aria-current="location"`；只有目标来源等互斥内容使用 Tab。
- 宽度大于 `1360px` 时实例栏停靠在右侧；`1360px` 及以下转为 Drawer，必须有标题、关闭按钮、遮罩、`Escape` 和焦点恢复。
- 切换当前对象、版本或护甲类型时关闭 Drawer，避免旧操作上下文覆盖新对象。
- 正文和 Drawer 只允许纵向滚动；表格、导航、目标来源和对象摘要必须换行或重排，不得出现水平滚动条。
- 资料库定义详情的 Perk 池按实际内容容器宽度响应式重排；不能只根据外层窗口宽度决定列数，窄容器下不得把起源特性或其他 Perk 列压缩到逐字换行。
- 加载、空、失败、部分可用、禁用和进行中由真实 ViewModel 在所属区域表达，不使用常驻的通用状态卡覆盖整个档案。
- 武器和护甲身份区左侧只显示图标、名称、类型与游戏事实标签；右侧使用上下文账本。武器账号实例固定区分“入口 / 当前查看 / 所在位置 / 武器槽位”，账号实例称为“这件武器”，不得把仓库或背包实例统称为“当前装备”；版本只在资料库定义确有多个可选版本时出现。护甲沿用既有位置与版本语义。
- 武器资料库定义存在两个以上可确认版本时，身份区以“查看版本”下拉控件保留原 Hash 切换能力；单版本武器定义、账号武器实例和商人售卖武器不在首屏重复展示版本字段，相关定义证据保留在折叠信息中。护甲版本展示沿用护甲领域既有规则。
- 版本值统一包含可确认的年份、赛季和名称；当前选项由控件选中态表达，不追加“当前查看”文字。Manifest 定义版本、Hash、光等上限和实例 ID 只进入折叠追溯信息。
- “当前查看”属于对象选择语义，武器和护甲共用蓝色选中态；发布年份、赛季和版本名称是事实值，不使用绿色成功态。

## 对象模式

| 对象 | 事实边界 | 操作边界 |
|---|---|---|
| 资料库定义 | Manifest 定义级只读信息，不模拟实例 Roll 或属性 | 只读，可切换可确认版本或来源 |
| 商人 Offer | 当前 Vendor 销售配置、成本、限制和刷新边界 | 购买前不远程切换 Perk；只提供产品已有的真实 action |
| 账号实例 | Profile 中实际拥有、位置、插槽、属性和当前选择 | 满足 Bungie 条件时可装备、转移、锁定、切换可写 Plug 和本地标记 |

Manifest、Profile 和 Vendor 数据不得互相补造。DIM、推荐来源、个人目标和 AI 是独立来源，不合并成无来源的系统结论。

## 武器详情

稳定契约：`weapon.detail`。

固定章节：

1. 当前配置
2. 推荐 Roll
3. 属性与获取
4. 升级与锻造
5. AI 分析

真实能力：

- 身份、图标、类型、框架、槽位、弹药、伤害、勇士效果、版本和定义追溯。
- Manifest 标准属性、Profile 当前属性、待应用变化、官方来源、Vendor 价格/限制/刷新时间。属性首层使用紧凑数值矩阵：账号实例和商人售卖优先显示当前数值，资料库定义显示标准数值；不显示进度条，也不在每项重复“已读取 / 未返回”。存在待应用数值变化时仅用 `当前值 → 待应用值` 表达。
- 固定配置、当前实例配置、完整掉落池、真实拥有 Perk、待应用选择、提交和刷新。
- DIM Wishlist、推荐来源和个人目标按来源独立展示；DIM 保持无序且全部必需的组合语义，推荐来源保持逐栏语义，不交叉合并。DIM 只有在每个 Hash 能由当前武器官方 Socket 唯一归栏时才显示具体栏位；同栏多个必需项、跨栏歧义、未知定义和特殊异域插槽必须明确说明无法逐栏核对。
- 资料库定义详情按来源原始形态展示推荐资料：明确完整组合保持逐组展示，分栏候选保持 Perk 池展示；禁止从候选池计算笛卡尔积。资料库没有玩家实例，不显示命中、完整度、匹配分数或“未选择账号装备”。
- 资料库推荐候选优先消费推荐服务已解析的 Hash、同名跨版本 Hash、图标、官方说明和英文名；当前查看版本的定义池只作为缺失视觉信息的兜底。大师属性别名和关联版本候选必须保持可读图标与说明。
- 武器详情不提供个人知识录入、编辑、启停或删除入口；已有旧记录保持底层兼容，但不进入详情推荐或 AI 上下文。
- 大师杰作、模组、催化剂、强化、锻造等级和进度。
- 同 Hash 实例切换、装备、转移、锁定、标签、备注、复制摘要和加入配装草稿。
- 详情中的单件“清理”和同名批量“其余清理”必须复用仓库统一保护索引；锁定、精确配装引用、玩家手动保留、推荐冲突、推荐核对未完成或 Roll 不完整时保持原标签并说明原因。

首屏与实例栏：

- 武器详情默认定位“当前配置”，首屏先展示当前 Roll 摘要、真实插槽和至少一部分 Perk 配置；章节顺序固定为“当前配置 → 推荐 Roll → 属性与获取 → 升级与锻造 → AI 分析”，推荐 Roll 必须紧接本件 Roll，不得被属性或获取信息隔开。推荐章节使用独立顶部强调带、“推荐判断”短标签和“这件武器的推荐 Roll”标题，与本件配置形成清楚但连续的层级。资料库定义、商人售卖和账号装备分别显示完整 Perk 池、售卖 Roll 和本件 Roll。
- 账号快照已经提供 `weapon_roll` 时，详情首屏必须直接显示其中已确认的当前启用与实例拥有项；这些插槽首屏只读，不猜测远程切换能力。单件详情请求只负责补齐说明、属性、可写状态、催化剂和其他非首屏事实，不得让已有 Roll 等待第二次账号请求。
- 社区攻略和实例推荐证据只在推荐章节挂载后空闲读取；同名版本和实时获取状态只在属性与获取章节挂载后读取。旧对象的延迟请求不得覆盖当前详情。
- 打开命令必须立即提交可关闭的共享档案 Loading；基础详情准备完成后，通过低优先级 Transition 在同一个 Dialog 内一次性替换为完整首屏，不使用固定帧数或定时器猜测完成时机，也不先展示半成品 Preview。攻略推荐来源卡折叠时只挂载来源名和命中摘要，逐栏 Perk 对照、图片和说明只在玩家展开该来源后创建。
- 推荐来源或规则 revision 变化时，已打开详情若尚未访问推荐章节，只替换该章节的按需 loader；若已经访问，只定向重载推荐区，不刷新账号、定义或完整 Roll。旧 revision 的晚到结果不得覆盖新结论。
- Loading 阶段保留最终档案的稳定尺寸和关闭能力；身份、章节导航、配置摘要与 Perk 网格作为同一份 Ready 首屏提交，不能先出现一半内容再阻塞交互。未完成的可选数据不得显示“未返回”“没有可切换项”等终态文案。
- Ready 后的可选定义、完整实例、推荐、版本和实时获取数据按所属区域独立更新；完整掉落池不得冒充本件 Roll 或商人售卖 Roll，只有对应请求结束且确实无数据时才显示局部空态。这些局部更新不得把整份详情退回全屏 Loading。
- 武器详情右侧只保留当前装备的转移、装备、锁定、本地整理和备注操作，不再扫描或渲染“账号中的同版本武器”列表；同名装备比较与批量整理统一在仓库菜单完成。宽屏操作栏停靠，`1360px` 及以下转为 Drawer。
- 账号装备存在待应用 Perk 或未保存备注时，关闭详情或切换版本必须先确认；取消离开时保持当前详情和 Drawer 状态。

武器规则：

- 异域固定配置不显示随机池命中；传说武器区分完整掉落池、当前实例拥有项和当前可切换项。
- 武器配置按 Bungie 的真实 `socket_index` 排序，不按枪种硬编码固定列位；宽屏最多使用六轨，第一轨为固有能力，其后最多五个有效 Roll 插槽，候选数量只在列内纵向增长。
- Roll 列名从插槽类别生成：枪管、弹匣、电池、弓弦、箭杆、剑刃、护手、柄芯、握把、偃月杆、瞄具、枪托、核心升级和起源特性必须显示真实业务名称；只有普通特性列使用 `Perk 1`、`Perk 2` 编号。
- 当前实例配置和完整候选池共用同一列模型；实例区只展示 Profile 或 Offer 可确认的当前选择与可切换项，不把定义池候选冒充为实例已拥有项。
- 账号实例使用“推荐 Roll 核对”，顺序固定为 `攻略推荐 / 我的推荐 / DIM`。只显示当前有数据的来源并自动定位第一个非空来源；DIM 是最低权重辅助来源，固定放在最后，也不得混入攻略推荐卡。全部为空时显示单一短空态。攻略推荐以默认折叠的来源卡展示摘要，用户主动展开后才显示用途、评级、排名、说明、原始链接、更新时间和逐栏明细；来源显示名固定使用 `Aegis推荐 / LGpig推荐 / YXCRALLXY推荐表 / Sayalarry推荐表`。来源卡标题不得把结论压成一个小标签，必须把“核心 Perk”和“完整匹配”拆成两个独立数字块，例如 `核心 Perk 2/2` 与 `完整匹配 5/6`；存在真正不可比较的栏位时增加独立“无法判断 n 项”，只推荐武器时显示 `仅推荐武器 / 未指定 Roll`。展开后只为来源真正要求的栏位渲染完整对照，未要求栏位合并成一条短说明；Perk 1/2 行使用额外的非颜色视觉强调。宽屏逐栏采用紧凑三列：栏位与结果、来源要求、本件拥有；窄屏按同一顺序纵向堆叠。来源候选和本件拥有均使用“图标 + 常驻 Perk 名称 + 短状态”条目，名称不能藏进 Tooltip，也不能在图标缺失时退化为无法辨认的单字圆球；同名多 Hash 必须合并成一个玩家可见候选。图标、官方说明和名称必须由推荐服务在进入 UI 前补全：本件拥有项直接使用账号定义，旧账号缓存允许由当前资料库按 Hash 补齐；跨版本推荐同时读取规则关联版本，不能只查当前实例 Hash；大师属性按去除阶级前缀后的官方语义名称解析。UI 只保留缺失数据的可读占位，不负责猜测业务身份。同栏多个来源候选明确标注“满足其中一个即可”，只有本件实际命中的候选使用绿色边条和勾，当前启用在本件图标及对应来源候选上叠加独立蓝点并显示“当前”文字，其他合法备选保持正常文字对比度且不显示红叉。鼠标悬浮、键盘聚焦和触屏点击打开的说明浮层只用于补充中英文名称、官方说明、来源身份和完整状态，并支持 `Escape`、点击外部关闭。逐栏状态继续使用中性表面为主，绿色、红色和蓝色集中在 `4–5px` 左侧实色条、不同形状的状态点、高对比实色徽标和候选状态边条，不得使用大面积薄荷绿或灰粉红铺满整行，也不得只靠颜色表达状态。顶部命中数字块使用轻状态底、实色边条与数字文字共同表达。逐栏顺序仍按枪管/瞄具、第二列、大师、Perk 1、Perk 2、起源特性，保留“符合 / 不符 / 无法判断 / 来源未要求”文字状态；完整 Roll 没有来源要求的栏位时为“不符”，本件值显示“本版本无此栏位”。内部七种来源汇总状态只负责派生和冲突判断，不作为逐栏或标题主文案。推荐按武器身份归属，同名历史、复刻和高阶版本共享要求；普通玩家不显示 CSV 版本、Manifest 发布标签或“当前版本是否适用”，仓库实例与商人武器的首屏身份摘要也不展示“装备版本/售卖版本”。当前 Hash 只能补充 Hash 证据，不能删除其他同名版本提出的明确来源要求；名称未解析出当前版本 Hash 时，只要本件栏位完整，仍按规范化官方名称给出符合或不符。DIM 默认只展示符合的组合，未符合时展示最接近的最多三组；每套 DIM Roll 保持独立组合，组合内逐项使用相同的图标、常驻名称与命中状态，不跨组合拼接，也不使用拇指图标；组合摘要继续使用符合套数和最佳组合 `x/y`。
- DIM Wishlist 的原始说明默认只显示一行，超出内容使用省略号；完整原文仍保留在元素内容和悬停提示中，不挤占 Roll 对照区域。
- 同名版本只保留玩家可识别的官方发布定义；共享 `translationBlock.weaponPatternHash` 的收藏品主定义、Vendor 别名和内部变体必须合并，不能作为多个版本重复出现在筛选框中。
- 只有资料库定义存在两个以上可确认发布版本时才显示版本筛选；选项使用简短的年份、赛季、内容包或专家标记，不显示 Hash、Manifest 数组序号或 `releases.*.core` 等内部分类。
- 获取方式必须分开显示“历史获取途径”和“当前获取状态”：Manifest `sourceString` 只能说明 Bungie 记录的历史来源，实时商人和公共活动数据只说明本次检查发现的当前入口。
- “属性与获取”宽屏优先让获取方式获得正文宽度，武器属性保持三列紧凑数值矩阵；窄屏先显示属性矩阵，再显示获取方式，属性在小屏重排为两列，不恢复进度条或逐项读取说明。
- 玩家文案必须直接说明信息依据和时间含义，不显示 `Manifest`、`Vendor`、`Offer`、`未命中` 等内部术语；实时数据未发现入口不能表述为永久绝版或确定无法获得。
- 角色范围返回的同一商人条目必须跨角色合并；聚焦子商人必须显示“先锋武器聚焦”等完整业务名称，不显示孤立的“武器”“护甲”或内部库存序号。
- “当前有获取入口”和“当前可购买”必须分开：只有购买状态明确成功时显示可购买，条件失败时说明原因，接口无法判断资格时不得同时显示“可获取”和“无法购买”。
- 当前属性轨道和当前选中 Perk 使用蓝色选中语义；绿色只用于已确认改善、成功结果或明确可购买，橙色用于待应用和条件限制。
- 装备、转移、取回和锁定写操作由中央账号 Store 驱动：Bungie 受理后立即在账号页、仓库页和详情实例栏显示同一份预计位置，并持续标记“正在确认”；后台读取账号快照且确认目标实例位置或锁定状态后，才转为成功事实。旧快照不得覆盖待确认结果；确认失败时恢复服务器当前数据并在写操作区域与账号页同时显示可理解的错误或重试提示。Perk 配置仍以实例详情中的真实插槽结果作为确认依据。
- 浅色主题中的透明白色 Perk 图标使用深色承载底；对象卡仍使用当前主题表面。
- AI 主命令使用 AI variant；禁用命令使用可读的不透明中性状态，不通过整体透明度降低对比度。

## 护甲详情

稳定契约：`armor.detail`。

固定章节：

1. 属性与获取
2. 护甲配置
3. 目标匹配
4. 强化状态
5. AI 分析

护甲事实边界：

- 只显示基础值、当前实际值、基础总属性、当前总属性和强化状态。
- 资料库定义没有固定 Roll 时显示正常的随机属性规则说明，不模拟六维属性或错误式空态。
- 当前实际值只包含能确认归属于单件护甲的强化和已安装模组影响；不展示目标值、最高属性或角色级加成。
- 获取来源只使用当前游戏资料和实时商人数据；实时失败时不显示旧 Offer。
- 当前 Armor 3.0 玩家配置区显示一个通用/活动模组位、三个部位模组位和一个等级 5 解锁的调整模组位。原始 Socket 中的升级、定位、随机属性、着色器和外观不计入玩家模组位。
- 传说套装显示套装规则、兼容角色已装备件数、激活档位和真实插槽；异域显示固有能力、异域限制和真实插槽；永劫教派等官方可选异域能力必须展开完整能力组，资料库与聚焦商品显示支持项，只有商人 Offer 或账号实例返回真实 Plug 时才标记当前选择；其他特殊能力按定义显示。
- 不生成推荐模组，不把定义支持项冒充为已安装项。

目标匹配使用个人目标、配装与攻略、社区来源三个独立来源。每条只展示条件、事实和匹配结果，不自动生成购买、保留或升级结论。

实例规则：

- 列出账号中与当前游戏版本一致且职业兼容的具体护甲。
- 显示总属性、六维、位置、强化、锁定、标签和特殊插槽。
- 只允许装备或转移到兼容职业，不提供 Bungie API 不支持的拆解操作。
- 当前实例可执行产品已有的装备、转移、锁定、本地标签、备注、复制摘要和加入配装草稿。

护甲三对象首屏：

- 当前装备显示“当前查看 / 基础总属性 / 当前总属性 / 强化状态”，属性区区分基础值、当前实际值和已确认模组影响。
- 当前售卖显示“当前查看 / 售卖总属性 / 购买状态与价格 / 刷新时间”，没有基础属性拆分或强化状态时不使用账号式“未返回”占位。
- 资料库版本显示“当前查看 / 属性规则 / 固定内容 / 获取状态”；护甲定义没有固定六维属于正常规则，不模拟单件 Roll。
- 首次打开保持身份区、章节导航、四格摘要和所属区域稳定尺寸；定义与实例独立渐进更新，加载结束前不得显示最终空态。
- 配置区必须区分定义支持项、商人售卖配置和账号本件已安装配置；三者不得互相补造或回退替代。
- 右栏统一使用“我的同版本护甲”，资料库与商人模式可切换到账号已有护甲，默认玩家文案不显示 Hash 或实例编号。

## AI 与推荐来源

- 主观解释只出现在 AI 分析章节；事实章节不得被 AI 结论覆盖。
- 外部查询必须由用户明确选择，并保留引用和来源。
- AI 结果仅供参考，不写入个人知识、装备、标签或推荐数据。
- 未配置、运行中、失败和部分结果分别呈现，不能用假成功或无来源推荐填补。
