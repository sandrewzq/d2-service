# 应用工作区合同

> 本文件合并共享 Shell、设置、首页、账号、资料库、仓库、商人和配装的结构、真实数据与状态边界。视觉细节统一遵守 [全局视觉合同](global-visual-contract.md)。

## 共享 Shell

稳定契约：`shell.topbar`、`shell.status-strip`、`shell.sidebar`、`shell.page-header`、`shell.page-content`、`shell.assistant`。

| 区域 | 真实绑定 | 约束 |
|---|---|---|
| 顶部栏 | 品牌、主题、GitHub、设置、AI、窗口控制 | 单一连续 Shell chrome；无平台窗口能力时只隐藏窗口控制 |
| 状态组 | `ShellStatusItem[]` 与对应 action | 状态项组成连续边界；状态 key 负责逻辑，label 只负责文案，不使用独立胶囊卡片 |
| 侧栏 | 当前账号摘要、一级导航、底部动作 | 桌面侧栏保持固定展开，不提供手动隐藏入口；窄窗口由响应式布局自动切换为紧凑栏。一级导航使用稳定图标和 `aria-current`，紧凑栏隐藏文字但保留按钮 `title` 与可访问名称；账号摘要名称截断时可通过悬浮查看完整名称 |
| 页面标题 | `ProductShellHost` 页面元数据与真实页面 action | 内容页不得复制第二个页头 |
| 主内容 | 当前菜单共享页面 | 普通页面由主内容持有唯一纵向滚动；仓库宽屏是明确的双栏例外，页面标题与工作流固定，筛选栏和结果栏分别滚动且不得把滚轮传递给外层 |
| AI 助手 | 会话、页面上下文、只读能力结果与数据引用 | 宽屏停靠，`980px` 及以下转 Drawer；只保留单一 AI 工作台，不建立固定任务 Tab |

Shell、页头、页面 gutter、首层分栏和全局 token 由共享层持有；菜单 CSS 不得覆盖 `.shell-*` 或无菜单前缀的工作区规则。

页面可以向 `ProductShellHost` 注册单一离开保护，只用于确实会因菜单卸载而丢失的未提交用户输入。Shell 侧栏、页内跨菜单动作和自绘窗口关闭命中保护时必须停留在当前页面并显示共享结构化确认弹窗；刷新、系统关闭或其他原生卸载路径使用平台 `beforeunload` 保护。取消后焦点回到来源操作，确认后才执行原导航或关闭动作。确认弹窗通过顶层 Portal 脱离可能被抽屉设为 `inert` 的页面内容，显示期间隔离应用背景，并始终位于 AI 抽屉、详情或菜单内容之上。弹窗打开时初始焦点落在安全的取消操作，`Escape` 等同取消，`Tab / Shift+Tab` 不得离开弹窗。新增或改造的共享页面确认流程不得调用 `window.confirm`，也不得把已持久化状态或普通筛选条件登记为离开保护。

顶部状态按行动紧迫度分为 `quiet / standard / attention / critical`，不按状态项数量平均分配视觉权重。正常配置、健康确认和当前版本属于低权重事实；发现新版、下载进度、待重启安装、资料库修复和真实失败属于可操作事件。状态项位置必须稳定，不得因状态或权重变化重新排序；高权重事件只通过颜色、背景、图标和文字增强，并保持连续边界，不建立独立胶囊卡片。窄窗口的“状态”入口显示待处理数量，展开后继续保持相同顺序。

应用更新状态必须区分 `idle / checking / not_available / available / downloading / downloaded / error`：未检查不得显示“最新”；已是最新只显示中性版本号；发现新版显示目标版本并使用信息色；下载中显示目标版本和进度；下载完成显示“待重启安装”并升为最高操作权重；失败使用错误色。顶部更新项只负责进入设置页更新区，不直接触发下载或重启安装。

应用更新与资料库更新共用 `SystemUpdateProgress`：顶部状态持续显示对象、阶段和可用百分比，不因临时通知收起而消失；任务开始、等待重试、失败或阻断时，可在顶部栏下方显示使用紧凑模式的临时通知，并在并行任务存在时提示剩余数量。通知可手动收起，运行和等待重试状态会自动收起，收起只影响展示，不取消任务；任务状态类别变化后可重新出现。设置页与资料库页使用详细模式显示阶段说明、下载量、总量、速度、旧数据可用性和重试时间。正常检查、下载、解压、校验和索引使用 `pending` 信息态；只有等待重试或能力受限使用 `warning`，失败和阻断使用 `error`，明确完成使用 `success`。无法计算进度时使用不定进度，不得伪造最低百分比。所有进度条必须提供 `progressbar`、当前值或不定状态的可访问语义。

AI 工作台发送前可以按用户问题自动运行受控只读能力，每轮最多三项。当前覆盖装备定义、Perk、账号实例、当前商人 Offer、本地配装检查和 `armor.plan`；宽泛整理或推荐问题不得伪造实体查询。Armor 调用必须同时识别当前六维数值目标和明确职业，旧六维、缺职业、缺目标或升级基线不明确时不得猜测。确定性结果随完整 `result_id` 进入模型上下文，回答底部显示缩短后的数据引用和状态；失败、无结果、未登录或缓存不可用必须保留真实限制。AI 工作台不得调用写操作、后台刷新或把聊天文本当作确认。

AI 只有在设置页完成数据发送确认后才能接收游戏上下文。设置页必须常驻展示发送目标、会发送与不会发送的内容；启用协议但未确认时阻止保存，旧配置和便携备份恢复默认未确认，更换协议或 Base URL 后立即撤销确认。未确认时模型列表可以继续工作；底层连接测试只发送固定测试文本、不携带游戏上下文，但“保存并测试连接”仍受保存确认约束。AI 对话、装备分析、仓库建议和外部知识查询不得在未确认时发送游戏数据。模型上下文不得包含 Bungie / AI 凭据、账号名、Membership、角色、装备实例、物品或 Plug 标识。

每次成功问答必须创建轻量上下文快照，消息保存快照 ID，快照保存页面和账号范围、Manifest 版本、基础上下文指纹、实际提示指纹及能力结果引用，不保存完整提示、装备正文或凭证。恢复会话后，当前上下文与最近快照不一致时顶部状态显示“已恢复历史快照”，上下文抽屉显示快照时间；继续提问只携带有限前文并创建新的当前快照。请求失败时恢复发送前消息，不写入无回答的历史条目。

只读能力调用审计保存在 renderer 本地存储，最多 100 条，只记录能力名、脱敏输入摘要、结果 ID、状态、耗时、警告码、结果数量和证据 ID。设置页“复制脱敏诊断导出”在主进程诊断后附加最近能力审计；不得写入完整提示、能力完整结果、账号装备正文、Token、Cookie 或 API Key。

明确的配装、构筑或攻略整理回答可以在消息底部显示单一 `guide_capture` 成果行，包含草稿标题、确定性结果引用数量和“交给配装页”命令。成果行是消息内连续区域，不嵌套对象卡。交接后关闭 AI Drawer、打开配装页攻略导入区并预填未保存文本；玩家仍需选择角色、执行解析与账号核对并显式保存，不得直接创建方案或触发写操作。

`armor.plan` 返回候选时，消息成果行优先显示 `armor_solution_comparison`，标明规划模式和达标候选数量。交接文本只包含原始职业、六维目标、候选 ID 和结果引用，不复制候选最终六维作为约束；配装页显示“复核 AI 护甲方案”，重新解析并要求复核模组预算、套装、位置范围和真实实例。

页面动作权重由当前页面职责、人工使用频率、自动刷新覆盖和阻断状态共同决定。全应用主要操作统一使用绿色表面：手动刷新、同步当前数据和失败后的重新读取使用带刷新图标的 Refresh Control；下载、保存、创建、应用和登录等通用 Primary 使用同一绿色家族，但不显示刷新图标。不同动作依靠动词、图标、所在操作组和忙碌状态区分，不再用蓝绿按钮割裂页面风格：

| 页面与状态 | 主操作 | 次操作 |
|---|---|---|
| 账号正常 | 页头 `同步装备数据`；从游戏更新角色装备、背包、仓库和配装，并更新所有账号消费者 | 页头 `重新登录 Bungie`；仅用于登录失效、权限异常或切换账号 |
| 账号未配置 Bungie | 内容空态中的 `去设置 Bungie` | 不显示无法执行的刷新或登录动作 |
| 账号未登录 | 内容空态中的 `登录 Bungie` | 不显示无法执行的刷新动作 |
| 账号无数据 | 内容空态中的授权或刷新入口；直接恢复当前工作区 | 页头不重复显示相同操作 |
| 仓库正常 | 页头 `同步装备数据`；与账号页执行同一个完整装备同步并更新共享 Store | — |
| 仓库未配置 Bungie | 内容空态中的 `去设置 Bungie` | 不显示 `刷新账号` |
| 仓库未登录 | 内容空态中的 `登录 Bungie` | 不显示 `刷新账号` |
| 仓库无数据 | 内容空态中的 `同步装备数据`；直接恢复当前工作区 | 页头不重复显示相同操作 |
| 首页正常 | — | 页头次级 `刷新首页情报`；带刷新图标，启动、重置边界和失败重试已有自动机制 |
| 首页读取失败 | 错误 Callout 内的主操作 `重新读取首页情报` | 页头不重复显示同一刷新动作 |
| 商人正常 | — | `刷新商人库存`；进入页面、切换商人或收到明确数据事件时按需刷新 |
| 商人后台同步 | — | 页头刷新保持可点击；后台读取状态只在商人状态区反馈 |
| 商人读取失败且仍有缓存 | 页头 `刷新商人库存` 临时升权 | — |
| 商人完全无数据 | 内容空态中的 `重新加载商人库存` | 页头不重复显示同一操作 |
| 商人未配置 Bungie | 内容空态中的 `去设置 Bungie` | 不显示无法执行的刷新动作 |
| 商人未登录 | 内容空态中的 `登录 Bungie` | 不显示无法执行的刷新动作 |
| 设置账号分区 | `同步装备数据`；该行明确说明游戏内或其他设备发生变化后使用 | `重新登录 Bungie`；独立一行说明只处理登录失效、权限异常或切换账号 |

首次启动时仍挂载完整 `ProductShellHost`，但由共享启动门禁统一推进“Bungie 配置 → 登录 Bungie → 首页”；资料库与登录并行，未完成前只允许进入设置和当前步骤，不显示半可用首页。配置区必须提供 Bungie 官方 Application 页面入口、字段对应关系和固定 OAuth 回调地址。配置保存后自动在后台准备资料库，不创建独立向导页或第二套配置表单；资料库准备失败时保留明确原因和重试动作，不阻塞 OAuth 登录和账号原始读取，名称、图标及高级解析在资料库完成后补齐。

同一业务动作可以因页面职责不同使用不同权重。每个页面或局部失败状态最多突出一个主操作；空态或错误区已持有主恢复入口时，页头不得重复同一操作。进行中保持原标签和稳定宽度，通过 `aria-busy`、禁用状态和邻近反馈表达进度。

账号与仓库同步使用单一共享快照和事件驱动更新，不得由菜单私有资源请求只更新状态标签而不更新页面数据。应用启动或登录后执行一次可见的初始同步；应用可见期间每 10 分钟静默同步一次，重新回到前台、恢复网络且上次同步超过 2 分钟时补同步，不因切换页面触发请求。自动同步复用已有 in-flight 请求、不清空旧数据、不占用手动按钮，失败时继续显示旧快照。本地缓存只用于首屏和失败回退，必须明确显示“本地缓存”。所有菜单把这项操作统一命名为“同步装备数据”：账号页、仓库页、设置页、AI 空状态和配装状态不得再使用“同步游戏账号”“同步仓库”“读取账号数据”等不同名称。用户点击后必须绕过账号、Profile 和请求 Broker 缓存；若已有初始或后台请求，手动请求排在其后重新读取，完成后原子更新共享账号快照并让首页、账号、仓库、配装等消费者同时更新。普通快照超过自动同步窗口时显示“待同步”，不得称为游戏数据延迟。写接口成功后共享 Store 立即显示预计位置并登记逐实例 Pending；新 Profile 先更新最后确认快照，再重放尚未反映的 Pending，相同或更旧版本不得整份覆盖页面，暂时缺失实例也不得让成功写入的装备消失。全局账号状态持续说明“n 项待确认 / 等待游戏状态 / 正在核对最终状态”；只有写操作确认超过 90 秒时标记“游戏数据延迟”。只有 Profile 明确前进且仍与写入冲突时才能撤销预计位置；超时、网络不可用或 Profile 未前进不得伪装成已核对。后台确认不借用手动同步按钮的忙碌状态，玩家仍可主动发起权威同步。“重新登录 Bungie”只表达身份恢复或账号切换，不得与日常装备同步混为同一操作。

商人刷新必须区分后台同步和手动请求：进入页面、切换商人、账号页当前角色变化和明确数据事件属于按需后台同步，不使用固定间隔定时器或轮询；Xur 到访 / 离开边界属于低频明确事件，可以保留一次性边界定时器。后台同步不得清空当前库存，也不得禁用页头刷新。只有用户已经发起的手动刷新可以临时禁用该按钮。切换商人使用短防抖，快速浏览目录时只请求最后停留的商人；手动请求使用后发请求优先的现有序号机制接管后台请求。

## 设置

稳定契约：`settings.workspace`。

固定九个分区：概览、语言与外观、账号、资料库、Bungie 接口、AI 助手、数据备份与迁移、数据来源与鸣谢、诊断与操作日志。设置只承载应用配置和公开来源说明，不承载攻略导入、推荐数据导入或其他业务工作流。

“数据来源与鸣谢”公开区分 Bungie 官方事实、社区资料来源和已参考项目与功能；每项保留完整外部链接、用途、关系边界和许可提示。本地用户导入内容不进入公开清单。账号事实和实时轮换必须标明以 Bungie 为准，参考项目不得伪装成运行时依赖。

| 区域 | 真实字段与 action | 状态边界 |
|---|---|---|
| 概览与更新 | `appUpdateSnapshot`、账号/资料库/Bungie/AI/后台任务摘要、检查/下载/安装/诊断 | 未检查保持中性；只有发现版本后允许下载，下载完成后允许安装 |
| 语言与外观 | `languagePreferences`、`colorMode`、`density` | 界面语言与资料库语言分开建模；跟随开启时禁用独立资料库语言 |
| 账号 | `accountSummary`、同步状态、刷新时间 | 同步中禁用重复同步；未登录保留“重新登录 Bungie”入口；写操作由对应页面确认，不设置应用级总开关 |
| 资料库 | Manifest 状态、检查、更新、修复 | 失败时保留上一份可用资料；进行中禁用冲突操作 |
| Bungie | 官方 Application 入口、API Key、Client ID、Client Secret、回调地址和数据目录；保存后自动准备资料库 | 三个配置值均明文展示；三者都不进入仓库示例或诊断快照，诊断导出仍须脱敏；字段不完整时阻止保存；资料库准备失败不回滚已保存配置 |
| AI | 协议、Key、Base URL、模型、数据发送确认 | 常驻说明发送范围；无配置、待确认、已确认、加载、测试中和失败分别呈现；更换协议或 Base URL 后重新确认 |
| 备份与迁移 | 创建/恢复备份、清缓存、迁移说明、打开目录 | 调用真实平台能力，不伪造完成结果 |
| 诊断与日志 | `backgroundTasks`、`actionLog`、AI 只读能力审计、筛选、刷新、复制诊断 | 空日志保留筛选和诊断入口；失败项提供脱敏诊断；能力审计通过统一诊断导出附带 |

布局合同：

- `>1280px` 目录 `240px`，`981-1280px` 为 `210px`，`761-980px` 为 `190px`；`760px` 及以下目录置顶并限制高度。
- 状态摘要使用单一 `4px` `SurfaceFrame`，内部连续单元直角；三列，`1280px` 以下两列，`980px` 以下单列。
- 设置行使用弹性说明列和右侧控制列；宽屏控制列 `282px`，中屏 `260px`，`980px` 以下单列。
- 重复操作按钮使用 `34px × 144px`；Select 和 Field 填满控制列。
- 账号、资料库、更新和日志的精确时间使用本地时区 `YYYY/MM/DD HH:mm:ss`。
- OAuth token、Bungie API Key、Client Secret 和 AI Key 不得写入仓库快照。

## 首页

稳定契约：`home.workspace`、`home.vendor-stock`。

| 区域 | 真实绑定 | 关键状态 |
|---|---|---|
| 刷新节奏 | `dailySummary.daily_reset`、`weeklySummary.weekly_reset` | 使用本地系统时区；顶部刷新矩阵只展示每日和每周重置，绝对更新时间靠右，动态倒计时使用全应用统一时间强调色 |
| 核心活动 | `weeklySummary.priorities.*.entries` | 日落可独立展示；轮换突袭和轮换地牢只在 Bungie 账号已登录且角色活动数据成功读取时展示。未登录、读取失败、刷新中或数据过期时直接隐藏，不显示 pending、候选名称或旧缓存 |

## 账号

稳定契约：`account.slot-comparison`。

账号菜单长期定位为“角色状态与待处理中心”，优先回答当前角色是否安全、是否已准备好进入活动以及接下来需要处理什么。跨角色库存浏览、筛选与整理归仓库菜单；完整配装列表、编辑和执行归配装菜单；本周活动入口与全局摘要归首页；收藏、成就、催化剂和外观归资料库。账号菜单不得复制这些菜单的完整工作区。

- 容量、物品位置、光等、邮政官和角色进度扩展必须继续消费中央账号 Store 或明确拆分的共享异步资源，不建立账号菜单私有刷新、缓存或轮询模型。
- 页面必须区分请求完成、服务器 Profile 前进和目标状态确认；同步尚未确认时持续显示进行中或等待状态，旧 Profile 不能覆盖更新版本或本地仍在等待确认的预计状态。
- 三角色待处理对比是容量、光等、任务和进度能力的聚合视图。每项能力接入真实数据后再加入汇总，不创建独立假数据面板，也不预留静态数字和空壳操作。
- 新装备识别、历史记录和完整 Feed 归共享账号状态或仓库领域；账号菜单未来只允许消费已确认的摘要，不单独维护新装备状态。
- 强力、巅峰、赛季和声望等扩展进度使用独立异步资源、独立缓存和独立失败状态，不得加入装备首屏的阻塞加载链。
- 新增容量风险、光等成长、邮政官批量处理、任务待处理或角色进度能力时，必须先确认在现有目录中的位置；如需改变目录与信息架构，先更新本合同，不得直接隐藏或删除现有真实功能。

## 资料库

稳定契约：`library.workspace`。

- 上方使用资料库状态摘要，主体使用“查询侧栏 + 连续结果列表”的工作区。
- 装备与“Perk 与框架”是互斥模式，使用完整 Tab 语义；搜索、筛选和清空是普通 Control。
- 查询侧栏首屏只承载模式、主搜索、基础筛选和默认折叠的高级筛选；最近查询、收藏计数和别名管理统一收进默认折叠的“搜索辅助”，不得与主搜索并列抢占首屏高度。
- 摘要显示激活版本、最新版本、激活时间、检查时间、语言、定义数量和缺失组件。
- 装备、Perk、框架、历史和收藏来自当前 Manifest 与本地历史，不使用固定名称、别名或数量。
- 同名装备存在多个可确认发布版本时，结果行名称旁直接显示玩家可识别的年份、赛季、资料片或内容包摘要；不要求展开详情，不显示 Hash 或内部 release trait。
- 装备结果首层按“名称与版本 / 类型、槽位、框架、弹药和伤害属性 / 当前获取、账号持有和来源可信度 / 操作”排列；完整定义描述、起源特性、历史来源和实时渠道进入同一来源详情，不在首层重复铺开。收藏是低权重操作，武器和护甲的“查看详情”仍是唯一主操作。
- 定义对象与账号实例必须区分。只有匹配到真实实例时才显示位置、Roll 和账号详情入口。
- Perk 反查装备使用可追踪的具体 Hash / Manifest 关系，不按装备名称模糊扩展。搜索列表以 Logical Perk / Perk Family 为用户实体：家族身份由 Inventory Plug 的规范化名称、官方图标和 Plug / Item 类别共同确定，不把描述或 Sandbox Perk Hash 直接当作列表身份。普通、强化和其他官方变体在同一结果内保留各自 Sandbox Perk Hash、Plug Hash、描述和关联数量；例如“爆炸箭头”只显示一行，行内分别展示普通效果与强化差异。
- Perk 搜索结果只返回精确关联总数和分类；展开“关联装备”后按需分页读取完整装备摘要，并在 workspace 按 Perk key 缓存，折叠不清除，新搜索或 Manifest 版本变化时清理。展开区覆盖加载、失败重试、空结果和加载更多状态，不设置静默固定上限。
- 关联装备继续使用连续列表，每个具体发布版本独立成行。左侧显示约 `40px` 官方装备图标并叠加官方版本水印；名称旁始终显示玩家可识别的发布版本，缺失时显示“版本待确认”；概要显示稀有度、装备类型、框架、弹药、伤害属性、专家标记，以及该版本支持“普通 / 可强化”的哪种 Perk 变体，随后显示历史来源或当前获取状态待确认，并可直接打开统一装备详情。同一发布版本的技术重复定义通过 canonical Hash 合并，不同发布版本保留且相邻排列；家族关联总数按所有变体的 canonical 发布版本实体取并集，不把各变体数量直接相加。
- Renderer 与 Desktop main / preload 的资料库合同必须显式握手。合同版本不支持 Perk 家族、分页关系或变体匹配时，仍可显示基础 Perk 搜索结果，但关联装备区必须提示重新构建并重启，不得把旧版固定上限摘要渲染成完整结果，也不得用空图标和“版本待确认”伪装合同正常。
- 未初始化、部分组件缺失、更新中、检查失败、历史为空和搜索无结果分别呈现；更新失败保留上一份可用资料库。
- 搜索、实时来源、收藏和别名使用独立错误状态，只影响所属区域。搜索更新期间可以保留上一份可见结果以稳定几何结构，但必须明确标记为上一次内容并在结果区使用 `aria-busy` 和独立状态播报。
- 结果操作支持键盘方向导航：同一行左右切换操作，上下移动到相邻结果的对应操作；统一装备详情关闭后焦点返回来源按钮。`760px` 及以下查询区回到页面文档流，不设置独立高度和纵向滚动；Manifest 摘要保持两列，极窄宽度再转单列。

结果区使用连续 `SurfaceList`，每行只画 `RowLine`，不把普通结果改成对象卡。

## 仓库

稳定契约：`vault.workspace`。

仓库固定包含 `1 浏览装备`、`2 看推荐`、`3 整理同名` 三个 `tabpanel`，共同消费同一份账号实例集合。三个入口始终可见并允许直接跳转，它们表达玩家路径，不是必须顺序完成的向导。武器模式的实例集合覆盖仓库、所有角色已装备、角色背包和邮政官；护甲与其他装备仍只取仓库。清理不再维护独立工作台：玩家在浏览装备或整理同名中写入“清理”，后续转移和游戏内处理仍以该明确状态为边界。

宽屏仓库使用固定高度工作区：共享页面标题、工作流 Tab、推荐来源与结果筛选、账号状态和写操作反馈保持可见；浏览装备的左侧筛选与右侧结果各自拥有纵向滚动，滚动到边界后不继续推动外层页面。三个工作区分别保留自己的结果滚动位置，浏览装备额外保留左侧筛选位置。`850px` 及以下恢复仓库页内部单一纵向滚动，左侧筛选回到文档流，避免窄屏形成同轴嵌套滚动。虚拟网格必须订阅当前实际结果滚动容器，不能固定读取全局 `.shell-content`。

| 工作区 | 数据与操作边界 |
|---|---|
| 浏览装备 | 左侧常驻筛选、右侧紧凑装备网格；Profile 实例、Manifest 定义、玩家整理状态、锁定和排序共同参与筛选；保护证据只负责展示与阻止危险操作，不重复成为筛选入口 |
| 看推荐 | 内部分为“推荐结果”和“我的目标”；推荐结果直接按玩家决策显示账号实例，我的目标承接现有装备目标与跨页定位 |
| 整理同名 | 按规范武器名称和实例 ID 分组；左侧按整理进度选择同名组，右侧使用比较基准和单一推荐来源突出实例差异并暂存本组整理状态；护甲继续使用现有分组与比较逻辑 |

推荐数据入口位于“看推荐 → 推荐结果”，名称固定为“推荐来源”。推荐数据不可用时，结果区只显示原因、不会影响的账号数据和唯一主操作；数据可用时不常驻来源状态长列表。管理内容使用带焦点限制和返回焦点的覆盖层，不在结果列表中向下展开造成页面跳动。覆盖层首层按来源显示名称、启用状态、最近更新时间以及“更新 / 停用 / 移除 / 管理规则”；DIM 在线更新和正式中文推荐导入作为主要操作，本地 DIM 文件、粘贴文本、标准模板、revision、commit 和规则总数收入来源详情或“其他导入方式”。

发布方来源原始规则只读；玩家点击“移除规则”时写入可恢复的本地排除层。Aegis、LGpig、YXCRALLXY、Sayalarry 和 DIM 均可按来源停用或移除，且只影响该来源；整份数据删除必须二次确认。来源或规则变化通过推荐 revision 事件局部更新受影响武器，不触发 Bungie Profile。批量整理预览存在时禁止修改来源；revision 变化后旧预览立即失效。

武器推荐知识库 CSV 是主要中文推荐数据：选择文件后只展示文件名、武器数、来源记录数、来源数和错误摘要，完整校验成功后仍需明确确认才替换 SQLite 知识库。DIM Wishlist 是第三方辅助数据，不是攻略来源，也不转换成 CSV；普通玩家主入口是“检查社区更新”，界面显示当前短 commit、启用时间、规则数和武器数，检查后展示固定 SHA 对应文件的统计预览，明确确认后才替换 SQLite；原生 `.txt` / `.wishlist` 文件导入和粘贴文本继续作为离线、自定义回退。两种格式的导入或替换都必须先解析并展示预览，再由用户明确确认；失败时保持当前活动数据不变。保存、替换或移除后自动重新计算当前账号匹配，不要求刷新整个账号或重启应用。

推荐结果首屏只显示当前账号装备和可执行去向。主筛选固定为先选择一个已配置且启用的来源；人工来源再按核心 Perk 精确 `x/y / 未要求 / 无法判断 / 未收录 / 全部` 筛选，并可继续用下拉选择完整要求的精确 `x/y`；DIM 直接按最佳组合精确 `x/y / 未指定组合 / 无法判断 / 未收录 / 全部` 筛选，不显示人工来源的完整命中下拉。来源即使当前账号覆盖为 0 也保持可选，未选择来源时不显示多来源综合结果列表，只显示短引导空态。用途、位置、玩家标记等进入“更多筛选”。每行显示武器身份、真实位置、所选来源的精确命中摘要和“查看依据 / 整理同名”，其他来源、六项证据、用途与保护原因进入详情。没有推荐数据时显示中性空态和单一准备操作；不得把 Hash、JSON、SQLite 路径或 CSV 逐列规则编辑暴露给普通用户。历史版本已保存的自定义规则继续由 Core / Services 兼容读取，仅在确实存在旧数据时显示“遗留自定义规则”，不提供新建、替换或粘贴入口。通用 AI 外部知识查询不参与仓库批量扫描，只在用户明确打开单件装备分析并主动允许外部查询时调用；该能力只接受支持网页引用的 OpenAI Responses 兼容接口，不绑定特定社区网站。

正常状态保持安静：仓库页只显示账号最近同步时间和必要的推荐可用状态，不常驻“已核对账号武器 / 已有来源记录 / 存在符合项 / 需要人工复查”四格矩阵、来源状态长列表、规则总数、逐阶段扫描说明或重复结果解释。异常、部分可用或未配置状态使用固定高度状态区显示原因和唯一主操作。结果解释通过“如何判断”按需打开；核对数量、规则总数、revision、commit 和“复制验收报告”归入来源详情或设置诊断。

推荐数据中的独立装备目标按稳定目标 ID 接受跨页定位请求，并使用既有选中表面 token 聚焦目标行。Armor Planner 缺口提供“查看 Planner 引用”，只携带稳定 `result_id / candidate_id`，不承诺恢复完整求解结果。

筛选范围只提供武器、护甲和装备，不提供“全部”与“其他”入口。武器槽位只显示动能、能量和威能；武器模式另设“查看范围”，默认进入“仓库整理”，只向玩家提供仓库整理、当前背包、当前已装备、当前邮政官和其他角色。“随身待检查”与下方具体位置重复，“全账号武器”只属于内部跨页定位范围，二者均不显示为筛选按钮。跨页定位具体武器时允许临时使用内部全账号范围，退出定位或重置筛选后恢复仓库整理。切换到护甲时隐藏位置范围并保持护甲只读仓库数据的原有语义；护甲部位显示头盔、臂铠、胸甲、腿甲和职业物品。武器类型使用真实 `item_type`，稀有度使用 `tier`，装备阶级使用 `instance.gear_tier` 并包含 T0，伤害属性使用实例伤害类型；护甲职业使用 `class_type`。护甲套装选项目录来自当前语言 Manifest 的完整 `DestinyEquipableItemSetDefinition`，账号装备摘要中的真实 `equipableItemSetHash` 只用于匹配物品和计算持有数量；未持有的套装仍保留在目录中并允许选择，命中为空属于正常筛选结果。目录加载中或不可用时必须显示明确状态，不得回退成账号持有套装列表。缺少稳定账号字段的制作状态或框架不得用固定选项补造。

筛选列表保留现有左侧条件，武器与护甲按实际结果容器宽度布局。标准武器卡片默认最小宽度约 `264px`，紧凑模式约 `224px`，舒适模式约 `296px`，统一使用容器内 `auto-fill` 自动降列；AI 抽屉打开后按剩余宽度重排，不维护互相覆盖的固定列数。默认使用 `52px` 游戏图标，卡片保持固定高度和单一焦点目标，以便二维虚拟网格稳定测量、方向键移动和恢复焦点。纯护甲视图继续复用全局 `44px` 游戏图标和现有卡片内容；混合视图不套用武器专属宽度、字段或来源区域。装备阶级直接使用 `DestinyInventoryItemConstantsDefinition.gearTierOverlayImagePaths` 的官方覆盖图，并与 DIM 一样叠在图标左上区域；不得用 CSS 自绘竖条或从左下角堆点。T0 不显示覆盖图，缺失阶级在产品层按 T0 参与筛选和显示。

武器浏览模式在结果列顶部显示推荐筛选：先从已配置且启用的 Aegis、LGpig、YXCRALLXY、Sayalarry 或 DIM 中选择来源；人工来源继续显示核心 Perk 的真实 `x/y / 未要求 / 无法判断 / 未收录 / 全部`，再用下拉选择完整要求的真实 `x/y`；DIM 第二步直接显示最佳组合的真实 `x/y / 未指定组合 / 无法判断 / 未收录 / 全部`，不显示第三步。来源即使当前范围覆盖为 0 也不能从下拉中消失；未选择来源时显示全部当前范围装备，不用多来源综合结论作为默认筛选。“浏览装备”和“看推荐”共用同一来源、核心 Perk、完整命中状态与一次生成的实例轻量筛选事实索引，切换工作区后保留当前选择；核心 Perk 数量忽略当前核心与完整条件，完整命中数量基于已选核心条件计算。推荐核对尚未完成时，没有现成实例结果的武器不能计入“未收录”。数量为 0 的按钮保留位置并禁用。切换到护甲或装备时隐藏并重置全部推荐筛选。左侧不再显示“保护与匹配”：DIM 由结果列来源筛选承接，配装引用作为卡片与整理保护事实，个人目标由“看推荐 → 我的目标”承接。

仓库带数量的筛选项使用统一分面口径：物品范围标明账号总数；武器槽位、查看范围、武器类型和框架应用除自身维度外的其他已生效条件，展示切换该选项后可得到的数量。结果区标题、结果列推荐筛选的“全部”和当前选中范围必须使用同一最终结果基数，不能让同名“仓库整理”同时展示全仓库数量和当前条件数量。

仓库结果和分面共享同一实例查询索引。物品范围、锁定、槽位、位置、弹药、武器类型、稀有度、装备阶级、职业、伤害属性、套装和框架先通过 ID Set 交集缩小候选，再执行搜索文本、玩家标签、愿望单、个人目标和护甲属性阈值等精确规则；单件锁定或位置 Patch 只更新该实例的索引记录。结果、槽位、位置、框架和类型数量不得各自重新遍历完整账号装备。

武器对象卡固定分成身份、事实、推荐 Roll 匹配与状态四层：身份层显示图标、最多两行名称以及“槽位 · 类型”；事实层显示游戏化弹药图标、官方彩色伤害属性图标与光等；匹配层始终保留相同几何区域，标题右侧显示来源总数。正文按“来源名 / 结果”对齐展示，1～3 个来源必须全部显示；4～5 个来源显示前三个，并在标题明确显示“另有 n 个”。人工来源固定排在前面，DIM 无论匹配状态如何都作为最低权重辅助来源排在最后。人工来源摘要使用 `Perk 2/2 · 完整 5/6`、`Perk 1/2 · 完整 4/6` 或 `Perk 未要求 · 完整 2/3`；存在真正不可比较的要求时追加 `n 项无法判断`，只推荐武器时显示 `仅推荐武器 · 未指定 Roll`。DIM 保持组合语义，显示 `符合 1 套 · 最佳组合 5/5`、`符合 0 套 · 最佳组合 4/5` 或 `组合无法判断 · 最佳组合 x/y`；没有来源时显示“暂无推荐来源”。每条来源摘要使用小状态点和同色结果文字，来源名称保持普通文字，不能整张卡染色，也不能只靠颜色表达结论。状态层显示真实位置、玩家整理状态、锁定与配装引用；位置使用“仓库 / 泰坦 · 背包 / 猎人 · 已装备 / 术士 · 邮政官”等玩家文案。普通浏览时没有玩家整理状态就留空，进入整理模式后才显示“未整理”；保留、待定和清理继续常驻。卡片只保留对象外框，匹配区使用单一 `4px` 内嵌状态面，不在每层重复画分隔线。

非整理模式下，对有实例 ID 的装备卡在主入口下方提供快捷操作区。未锁定装备显示“加锁”，已锁定装备在同一位置显示“解锁”；只有仓库实例显示“取出”，目标固定为当前角色。单件加锁、解锁和取出不弹确认框，同时只能运行一个快捷写操作；成功后继续由账号 Patch 维护真实状态，不额外启动账号同步或后台确认，失败显示 Bungie 返回原因。快捷操作与卡片主入口必须是兄弟节点，支持 Tab，不能嵌套按钮；加锁或解锁后焦点回到原卡片，当前锁定筛选使卡片离开结果时焦点转移到相邻卡片；取出导致当前卡片消失时使用相同规则。虚拟网格必须按快捷操作后的固定卡片高度测量和恢复焦点。

人工推荐源按已证明的武器发布身份共享来源要求：同一 `release_group` 的普通版与专家、失时、痛苦或全息箔兄弟版可以共享未限定特殊形态的人工推荐；同名历史复刻、不同赛季版本和未知括号名称必须分开。正式知识库中保留的明确推荐项全部进入分母，同栏多个候选为任选其一、不同栏分别核对，实例实际拥有即符合、没有即不符，当前 Hash 的定义池不能删除要求。Perk 1/2 是核心；玩家首层先看实际要求的 Perk 栏位命中数，再看全部明确要求栏位的完整命中数，分母按来源真实要求计算，最大为六，不固定写死。`0/2` 只表示两个核心栏都已完整核对且均未命中；核心栏数据不完整必须显示“无法判断”，不能混入 `0/2`；来源未要求核心栏显示“未要求”，来源没有该武器规则显示“未收录”。内部继续保留“全部符合 / 核心符合 / 接近推荐 / 关键缺失 / 未符合 / 仅推荐这把武器 / 无法判断”七种来源汇总状态，只用于派生、排序、保护和冲突判断，不作为逐栏、筛选或标题主文案。同一来源的多条规则在卡片、结果行和筛选事实中只占一个来源名额，并按相同优先级选取最有帮助的一条，不能跨规则累计命中。DIM 保持一行一个完整组合、多行任选其一，不跨组合累计 Perk；卡片、详情与筛选只能消费真正的 DIM Wishlist 组合结果，并同时保留符合组合数和最佳组合命中数。多个来源不累计分数；同一用途出现明确符合与明确不符合时，推荐列表显示“部分符合”；存在真正无法核对的来源时优先显示“无法判断”。`general` 与 PVE、PVP 均视为用途重叠，PVE 与 PVP 之间不直接构成冲突。来源显示名固定使用 `Aegis推荐 / LGpig推荐 / YXCRALLXY推荐表 / Sayalarry推荐表 / DIM社区愿望单`。可选紧凑模式只缩减网格宽度和间距，不删除详情中的证据。护甲沿用现有身份、事实和状态结构，不接入 T20 来源摘要。锁定使用绿色锁形状态标记，固定在卡片底部状态行右侧并使用主题状态底板，不再覆盖装备图标；配装引用使用应用状态文字和既有选中边框，不使用右上角单字方块。完整 Perk、框架、品质、护甲能量、逐项推荐证据和长备注留在详情或同名整理，不进入普通网格。仓库页必须只生成一次实例来源摘要与轻量筛选事实索引，卡片、推荐筛选、推荐结果、账号紧凑摘要和同名整理共同复用派生结果，不得在每张卡片渲染或每次筛选时重新遍历 Wishlist 和来源记录。

玩家整理状态面向玩家只提供保留、待定和清理三种选择；未设置继续作为内部“尚未作出决定”保存，不显示为第四个筛选按钮，也不迁移或覆盖现有玩家数据。整理状态筛选使用可取消单选：没有选中项表示全部，再次点击当前项恢复全部。内部 `keep / review / junk` 分别显示为保留、待定和清理；`farm / loadout` 继续作为既有用途标签保存，但不进入整理状态控件。锁定、配装引用、愿望单、个人目标和社区推荐属于系统证据，只展示事实并参与保护，不自动生成玩家整理结论。普通装备单元只显示一份玩家整理状态，并保留锁定与配装引用角标。

结果区的批量能力与正式筛选分层：普通状态只保留一条结果命令栏，同时承载推荐来源、常用精确命中、其他特殊状态、完整命中、范围与结果数摘要和“批量选择”，不再为推荐筛选、结果标题、已生效条件或批量提示分别占用整行。搜索输入、来源、其他状态和完整命中依靠控件自身文字表达，不在上方重复标题；完整筛选当前值必须带“完整”前缀。核心 Perk 或 DIM 最佳组合的选项使用“命中 x/y / 未命中 x/y”和独立数量徽标，不能显示成难以断句的 `2/2 110`；悬停与可访问名称解释分子是命中数、分母是要求数。未要求、无法判断和未收录收入“其他状态”下拉。全部筛选的重置入口与左侧搜索输入同一行，不放在结果列最右侧；按钮始终占位并使用独立计数徽标，宽屏随左侧独立滚动保持可见，无条件时使用清晰禁用态，窄屏取消固定以避免覆盖顶部工作流。

左侧筛选不复用操作按钮外观：物品范围、槽位、装备阶级和整理状态采用整体外框、内部单线分隔的分段结构；查看范围采用带单选标记和右对齐数量的连续列表；稀有度、弹药和伤害属性使用低饱和游戏事实色并在选中时增强底色与内描边。字段边框弱于 Secondary 操作边框，焦点仍使用共享 `2px` 焦点环。进入批量选择后，在命令栏下方展开“已选 n 件 / 选择当前结果 / 清空选择”和独立批量操作区。不得保留“浏览 / 选择候选”伪 Tab、重复物品范围下拉或按清理、待定、目标、备注再次选候选的下拉。玩家先通过左侧与结果列推荐筛选形成当前结果，再显式选择当前结果。批量整理只提供保留、待定和清理；“清理”是可逆本地状态，不使用危险按钮表面。批量加锁、接收角色和移动仓库所选属于写操作，不得混入筛选。没有已标记清理装备时不显示清理转移说明；已标记清理装备的转移入口保持为独立已保存状态操作。

“推荐结果”按武器实例逐行展示，不按 `itemHash` 合并同名副本。结果主文案直接显示所选来源的精确事实：人工来源显示 `Perk x/y · 完整 x/y`，没有核心要求显示 `Perk 未要求`，DIM 显示 `最佳组合 x/y`；无法判断、未指定组合和未收录必须使用独立文字，不能再回退为“符合推荐 / 部分符合 / 未符合”三种模糊描述。来源之间不再互相改变筛选事实，多来源冲突只在综合摘要、保护判断和详情依据中保留。筛选只帮助玩家找到下一步，不生成保留或分解决策。用途、位置、玩家标记和更细状态作为“更多筛选”，允许重叠。只有完整核对状态才允许列出所选来源未收录的实例；部分或失败状态继续保留上次结果。每行只显示实例身份、真实位置、所选来源精确命中摘要，并提供“查看依据”和“整理同名”；人工标记、全部来源、六栏逐项证据、完整 DIM 组合和规则说明进入详情。“如何判断”解释这些是匹配证据而非系统评分，来源未收录与来源已有规则但零命中必须区分。

账号武器推荐核对仍维护 idle、scanning、partial、complete 和 error 五种运行状态；玩家文案固定为“尚未核对 / 正在核对推荐 / 部分核对完成 / 已核对 N 件 / 推荐核对失败”，不得使用容易与逐栏结果混淆的“待核对 / 部分可用”。正常完成态只更新短状态与时间，不占用独立统计区。只有已完成状态才能把空结果解释为当前账号没有来源记录；正在核对、部分核对完成和失败不得把未显示的武器解释为未收录。账号刷新后旧结果保留到新核对完成，重新核对失败继续显示上次结果并说明其状态，不得清空已有结果，也不得把推荐核对错误混入最近活动错误。资料库未准备、资料库版本落后和推荐知识库不可用使用稳定结构化原因，不从错误字符串推断。推荐扫描只处理武器实例，护甲不进入 T20 扫描；“复制验收报告”移入设置诊断，只读取当前账号和扫描结果，不写标签或游戏数据。

护甲多条件为 AND，同一属性只保留一条；总属性只作为排序维度。工作流栏只承担三个任务入口和必要运行状态；账号武器总数、当前结果数等重复统计不得挤占工作流栏。推荐筛选、结果摘要与批量入口按上述单条结果命令栏承载；重置全部固定归属左侧筛选区。

同名整理默认使用已标记保留的实例作为比较基准，否则使用本组第一件；基准只用于突出相同与差异，不属于系统推荐，不自动修改状态，也不限制一组只能保留一件。基准使用单选语义，切换后武器按真实 Socket 顺序和玩家可识别的插槽名称比较，护甲展示总值与完整六维；差异必须同时提供文字标记，不能只依赖颜色。武器首屏只比较账号紧凑快照已有的“当前启用”，打开详情、进入同名组和切换实例都不得自动读取完整 Roll；玩家主动选择“完整 Roll”后，才通过有并发上限的队列逐件读取并渐进填充，相同 `instanceId + rollFingerprint` 复用结果，失败允许单件重试。当前同名组存在实例级来源记录时，在同一标题区增加“比较内容”选择，并仅列出轻量实例摘要证明该组真实存在的人工来源。玩家选择一个来源后，才按当前同名组批量读取完整逐栏推荐证据；读取期间继续保留可操作的实例 Roll 表格，不显示空白或半成品来源矩阵，失败允许原位重试。证据就绪后，矩阵按枪管/瞄具、第二列、大师、Perk 1、Perk 2、起源特性的固定顺序，仅展开该来源有效且明确要求的栏位；每格同时显示来源要求、本件实际拥有、当前启用和“符合 / 不符 / 无法判断”文字，实例 Roll 或目标栏确实不完整时显示“无法判断”，完整 Roll 没有该栏位时显示“不符 / 本版本无此栏位”，其他来源继续在实例证据区显示独立摘要。只推荐武器但未指定栏位的来源显示中性说明，不伪造比较列；DIM 不进入逐栏来源选择；护甲不显示来源选择。完整 Roll 每列集合由当前启用项与 `reusable_plugs` 中来源包含 `instance` 的实际拥有项组成，排除只来自 `character / profile / manifest` 的解锁项和定义池候选；当前启用项只作为集合内状态，不参与完整 Roll 的相同判定。详情未齐时只能明确显示并比较“当前启用”，不得把账号紧凑快照中的 `socket_plugs` 冒充完整 Roll 或提前给出完整集合结论。集合关系显示为相同、部分重合或完全不同，同名整理只读比较，切换游戏内 Perk 仍在装备详情完成。比较矩阵采用“单元格差异状态 + 无框 Perk 行”两层结构：差异通过左侧状态条和短文字标签表达，不使用整格描边；Perk 行只使用分隔线，当前或可切换状态固定在右侧，仅此实例拥有的 Perk 在名称旁显示短标签。Roll 与来源要求列都应保证可读宽度并允许矩阵横向滚动，不得为了塞入视口压缩名称和状态。Roll 单元中的 Perk 图标必须复用资料库和武器详情的 `game-definition-icon` 原语，以主题适配底板、边框和 `contain` 保留透明官方图标的可读性，不得按普通装备缩略图使用 `cover` 裁切。

实例保护与匹配依据分开展示。锁定和精确实例 ID 配装引用属于实例保护；仅按 Hash 或部位匹配的配装需求明确标为“配装同款”，Wishlist、个人目标和历史社区数据保留在匹配依据中，不得让同 Hash 的每个实例都显示为精确配装引用。

同名组目录使用 roving focus：纵向布局可用上下方向键，横向布局可用左右方向键，`Home / End` 跳到首尾；选中项必须滚动到可见区域。单件整理状态先在当前组暂存，它是尚未写入本地标签的“待应用状态”，不是产品级草稿。左侧组目录和右侧行必须明确显示“待应用”；只有待应用状态与已应用状态不同时才开放“应用本组状态”和“撤销待应用”。切换仓库内部 `tabpanel` 时保留待应用状态；通过 Shell、查看 Planner 引用或窗口关闭离开仓库时必须提示待应用件数并允许继续整理或放弃离开，刷新与原生关闭使用平台卸载提示。存在待应用状态时不能直接进入下一未整理组。“填充：基准保留，其余待定”只修改待应用状态。锁定、任一应用配装或游戏内配装精确实例引用、玩家手动保留、同名组独特 Roll、来源冲突、Roll/官方名称不完整、推荐未覆盖及推荐核对尚未完成属于强制保护，不能被单件、批量或同名整理新设为清理；所有入口在最终持久化前还必须再次使用同一保护索引，受保护项保持原标签。批量清理必须用共享结构化确认弹窗预览所选数量和受保护数量，确认后只写未受保护实例的本地标签。推荐证据冲突继续复述冲突数量和真实写入边界。所选装备移动和清理装备转移同样由共享仓库 UI 完成结构化确认，Desktop adapter 只执行已经确认的写入。应用整理状态只写本地标签，不转移、不解锁、不拆解。

写操作继续调用真实 action / IPC，失败前不得提前修改锁定、位置或标签显示。

## 商人

稳定契约：`vendors.workspace`。

- 商人工作区使用“地点目录 / 商人详情”两栏结构，不保留重复的右侧上下文栏。来源、读取时间、重置边界、可见条目和当前角色库存上下文合并到商人头部与状态条；普通产品界面不显示角色长 ID，也不使用全局核验总量占据当前商人的决策空间。
- 商人页不单独维护角色选择器，角色视角由账号页的当前角色统一决定；账号页切换角色后，商人页通过新的 `character_ids` 请求重新读取并替换当前角色快照。商人页不得伪造账号合并库存、静默保留旧角色库存或把角色长 ID作为可见标签；当前角色上下文只显示玩家可识别的角色信息与机灵状态。
- 目录按真实地点和稳定 `vendorHash` / ID 分组，使用紧凑文字行，不显示头像或首字母占位。目录提供商人、物品和分类搜索，命中当前商人物品时详情同步收窄到匹配条目，命中商人名称时保留完整库存；搜索保留真实地点归属。正常商人行只显示条目数量，读取失败和部分可用才追加异常状态。窄屏目录转为单行横向滚动，方向键随布局切换为左右导航。
- 详情先显示声望与等级，其余章节保持商人结构定义的业务顺序；未配置的基础服务和任务位于已配置的主库存、周常奖励、聚焦等核心章节之后。不用分类摘要替代完整库存。声望面板必须明确显示等级上限、距离下一等级和“可领取下一等级奖励 / 已达等级上限”状态，不得把无法确认的奖励节点伪装成可领取按钮。商人状态条下方提供单行吸顶章节导航，滚动后固定在共享页面标题栏正下方，只定位现有章节，不切换或隐藏库存；当前章节必须有明确选中态，窄屏允许横向滚动。
- 每个商人章节标题必须显示真实业务作用域和动作（如“当前角色 · 游戏内购买”“账号 · 领取”“公会 · 获取”）；业务作用域来自 ViewModel 的 `scope`，动作来自 `action`，不得根据章节名称猜测或把账号级奖励写成当前角色库存。这里的业务作用域不是角色选择器，当前角色由账号页统一控制。
- 商人状态条提供局部“只看可负担”和“只看推荐”筛选，使用 `aria-pressed` 表达当前状态。筛选只改变当前详情的呈现，不修改快照、目录数量或真实库存；结果为空时保留清除筛选入口，章节导航只包含筛选后仍有内容的章节。
- Offer 网格中的可打开装备卡支持左右切换、按当前列数上下跳转以及 `Home / End` 首尾定位，焦点移动时滚动到可见区域；只读材料、任务和服务行不进入装备卡导航。
- 没有应用内操作能力的非装备直接库存和任务继续保留真实 Bungie 事实，但使用紧凑信息行并明确标记“游戏内使用 / 领取”或条件状态，不得显示成可在应用内点击购买的装备卡。
- 每个 Offer 显示真实图标或缺图态、名称、类型、摘要、成本、数量、购买状态和失败原因。成本在余额可用时同时显示“持有 / 需要”；购买能力必须写成“游戏内可购买”或对应失败原因，装备卡的应用内动作明确为“查看详情”，不得暗示应用可以直接购买。
- Offer 存在真实推荐判断时，在身份信息下方显示短推荐标签；推荐标签是决策证据，不替代购买条件、成本或详情入口，也不得仅用颜色表达。
- 角色相关库存显示当前角色上下文，不跨角色合并库存。
- 武器和护甲 Offer 可打开统一详情；材料、任务、解码器和其他对象只显示库存事实。
- 读取时间和重置边界使用原始时间字段在渲染时格式化，不保存预格式化文案。
- 加载、未开放和失败时清除过期轮换；部分可用时展示已确认销售数据并标记缺失属性或插槽。

Offer 使用响应式对象卡网格：宽屏五列，`1280px` 三列，`980px` 两列，`760px` 单列。章节和目录保持连续直角结构，不建立水平商品轨道。

## 配装边界

稳定契约：`loadouts.workspace`。本文件记录共享配装页必须保持的页面与交互边界；游戏内配装与应用配装是两种独立业务对象，应用配装的方案库、对比、决策工作区、自动配甲和安全穿戴共享同一产品实现。

当前领域能力已落地应用配装页面栈、方案库只读详情、2–3 方案差异矩阵、固定三武器/五护甲槽位、逐槽位实例选择、自动配甲、穿戴核对与保存到游戏内槽位后续动作。应用配装编辑器使用“完整构筑画布 / 实时摘要”两部分工作区；自动配甲、候选比较和更多规划方式在护甲区域原位展开，不替换完整构筑上下文。Desktop 与 Web 通过同一共享页面消费应用层 ViewModel。账号 freshness、未保存离开保护、焦点恢复和 `1280px / 980px / 760px` 响应式边界属于该稳定合同。

- 全局侧栏只保留一个 AI 工作台，不显示固定“任务”Tab 或攻略任务树。攻略链接、正文和 AI 整理文本统一从配装页的攻略导入区进入。旧侧栏保存的攻略文本只做一次性恢复，成功生成草稿后清除。
- AI 工作台的 `guide_capture` 交接会直接打开配装页并预填一份未保存的攻略文本；玩家继续选择角色、执行解析与账号核对，再决定是否保存方案。`armor_solution_comparison` 与 `equipment_target_candidates` 仍进入配装页对应的专用审阅。
- AI 工作台的 `equipment_target_candidates` 交接使用专用候选审阅，不经过攻略文本解析。候选列表必须区分账号真实实例和仅 Manifest 定义，允许逐项复选并显示目标角色；确认后只生成 `assistant-targets` 未保存草稿。真实实例绑定 `selected_instance_id`，仅定义候选只写 `item_hash` 并保持待获取、待选择，不能伪造实例或自动保存。
- 一级视图只保留 `游戏内配装` 和 `应用配装`。两者不是同一方案的来源筛选：游戏内配装是 Bungie 官方角色槽位，应用配装是本应用保存的完整构筑方案。自动配甲不是第三个一级页面、方案类型或来源。
- 游戏内配装显示 Bungie 官方槽位与官方应用能力；核心操作使用 `应用游戏内配装`、`复制到应用配装`、`用当前装备覆盖槽位` 和 `清空槽位`。复制只携带官方实际返回且可确认的字段，打开未保存的应用配装编辑器，不立即创建已保存方案。
- 应用配装默认进入已保存方案库，首屏提供搜索/筛选、只读详情、穿戴状态、`对比方案`、`新建配装`、`穿戴此方案` 和 `编辑方案`。目录只显示已经显式保存的应用配装；草稿不进入目录。
- 应用配装对比允许选择 2–3 个方案并默认突出差异。游戏内配装可以作为只读参照快照参与共同字段比较，但未知字段必须显示 `未返回`，不得因此转化为应用配装或与应用方案共用身份。
- 新建和编辑推入唯一的应用配装决策工作区。宽屏主区持续展示子职业紧凑摘要、三件武器和五件护甲，右侧持续显示最终六维、目标差值、缺口、浪费、套装、能量、缺失和可执行状态。六维、碎片、套装、实例限制和逐部位模组规则都在护甲区域展开；候选不会替换完整构筑画布。顶部保存状态、`保存` 和 `穿戴` 持续可见；点击槽位在当前画布上打开真实实例选择抽屉，关闭或选择后恢复来源焦点和编辑状态。
- 进入编辑、自动配甲、穿戴核对或发布等聚焦流程后，收起配装菜单外层的角色/视图/新建工具栏和常驻就绪状态，只保留当前任务需要的返回、方案身份、保存状态、保存与穿戴操作；错误和进行中状态仍在邻近区域显示。保存不得在顶部和底部重复出现。
- 装备槽位使用鼠标优先交互：空槽和已选装备的主体区域均为完整点击目标，悬停时明确显示选择方向；清空等破坏性较低的次操作保持独立按钮。点击槽位在当前构筑画布上打开右侧实例选择抽屉，抽屉提供槽位内搜索、候选数量、整行选择、遮罩关闭和 `Escape` 关闭；候选必须基于真实账号位置区分已装备、角色库存和仓库，当前已选实例置顶并显示“当前”，同时展示位置、光等、武器真实 Perk 或护甲最高属性等选择信息，搜索可以匹配 Perk 名称。选择后写入草稿、关闭抽屉并恢复原槽位焦点，不推入一张替代构筑画布的整页列表。
- 编辑头部的目标对象优先选择当前账号真实角色，并同步职业与目标角色 ID；账号不可用时才保留职业文本输入。方案名称、保存状态、保存和穿戴收敛在同一个吸顶编辑栏中。
- 新建空草稿不得只展示大面积空装备卡。中央先提供“从当前装备开始”“按属性目标自动配甲”“手动选择装备”三个真实起点；三武器使用紧凑横排，五护甲作为中央主要决策内容。子职业优先表达已确认的分支、星相、碎片和技能语义，Hash 只作为未解析诊断信息；没有真实编辑 action 时必须明确标记“当前仅记录”，保持静态对象样式，不伪装成可点击入口。
- 新建、当前装备复制、攻略链接或正文解析、AI 成果和游戏内槽位复制都进入同一个未保存应用配装编辑器；DIM 先完成链接读取与预览，再进入该编辑器。攻略导入区是配装页内的统一入口，不维护独立攻略页面或平行编辑 DOM。
- 武器和护甲必须选择真实账号实例；同名多实例不静默代选。子职业、目标 Perk、星象、碎片、技能和模组只有在稳定 Hash 与可写能力可验证时才进入执行计划，其余保持“仅记录”。
- 护甲规划位于应用配装编辑器的护甲区域，玩家入口文案使用 `按属性目标自动配甲`。它是护甲构筑主命令和编辑器内部状态，不新增第三个一级页面。展开后只保留“配装设置 / 推荐方案”两部分，方案摘要进入推荐方案顶部，不再维持第三个固定侧栏；接受方案后原位填入五个护甲槽位并收起规划区，不立即保存或穿戴。默认直接使用“当前库存”；“理论上限 / 待刷目标 / 升级路径”与套装、固定/排除、碎片变化和位置范围一起放入折叠的更多条件，不要求普通玩家先选模式。
- 属性模组输入以头盔、臂铠、胸甲、腿甲和职业物品五条独立规则为真相，每条使用 `自动 / 不安装 / +5 / +10`；固定 `+5 / +10` 后允许继续锁定具体属性。全局 `+5 × N / +10 × N` 只从五条规则和候选结果派生，用于摘要、比较和旧方案兼容，不得继续作为新方案的唯一输入。
- 属性模组输入分别使用 `+5 属性模组` 与 `+10 属性模组` 的精确数量，总数不超过五件护甲；T5 护甲调整由计算器逐件自动选择，零能量且不计入属性模组数量。库存与升级候选必须按五个具体部位的 Socket、草稿耗能功能 Plug、候选未覆盖 Socket 的现有耗能 Plug 和剩余能量分配属性模组；未安装属性模组的部位必须规划真实零能量清空 Plug。页面逐件显示护甲调整、属性模组、其他模组占用和最终能量，不得只展示五件聚合预算。
- 护甲约束支持 Manifest 可确认的 `2件 / 4件 / 2+2`、位置范围、固定异域、锁定和排除。理论模式不要求账号且只输出理论身份；待刷模式区分已有、待升级、待核对和待获取；库存与升级模式才允许选择真实实例组合。
- 护甲计算统一消费 `@d2-tools/app/armor` 的 `ArmorPlannerWorkspaceState`，页面不得继续直接调用旧 `solveLoadoutArmorCandidates`。Desktop Adapter 在主进程补齐当前 Manifest 规则集、套装目录和账号护甲快照；页面只提交职业、目标、约束、位置和实例选择条件。
- 修改六维、碎片、模组预算、优先级、锁定、排除或位置范围后，必须立即废弃旧候选。计算中可以保留上一结果作为内部恢复数据，但不得继续显示为可选择候选；`stale / error / indeterminate / unreachable / invalid` 必须分别显示真实状态和领域警告。
- 四种推荐方案共用逐属性比较、必须满足的要求、距离目标、模组用量、超出目标的属性和套装效果；首层直接显示六维、目标差值、距离目标、超出目标、套装以及转移/替换/缺失数量，展开后逐件显示部位、护甲、调整、属性模组、其他模组、能量和状态。理论方案显示框架、第三属性和调整身份，待刷方案显示缺失与已有匹配，库存方案显示位置与转移数，升级方案显示保留件、替换数和步骤。允许选择 2–3 个方案进行比较；比较不修改草稿，选择库存或升级方案只填入应用配装的五个护甲槽位并返回编辑器，不立即保存，也不触发 Bungie 写操作。

- 护甲设置中的五个部位直接提供 `自动 / 不装 / +5 / +10`；固定数值后才出现属性选择。属性优先使用可见的有序列表，不使用无序复选框保存隐藏点击顺序。数据尚未读取时只显示一条中性说明，确认安装冲突后才显示对应部位和玩家可行动原因。
- 普通玩家路径统一使用 `模组插槽 / 模组 / 当前游戏数据 / 具体装备 / 配装要求 / 必须满足 / 推荐方案`。英文 `Socket / Plug / Manifest` 仅保留在领域合同、诊断复制内容或显式技术详情中，不进入标题、表单标签、常驻状态或普通错误恢复文案。
- `保存应用配装` 只持久化应用方案；保存后才能稳定生成穿戴计划。`穿戴此方案` 使用 `plan / execute / refresh` 边界，包含真实转移、来源角色释放、当前装备替换和可验证 Plug 写入，失败时停止后续步骤并展示真实结果。
- 攻略链接、正文和 AI 整理文本只作为当前导入来源，不保存独立文章、正文快照或派生关系。来自装备目标的 Armor 引用只展示缩短后的结果与候选标识，并明确要求按当前账号和规则重新计算，不伪恢复未持久化候选。
- DIM 导出位于方案应用区，只对当前账号已核对的完整真实实例方案开放。导出使用当前 DIM `equipped / unequipped` 内联格式并保留可定位的 `socketOverrides`；理论、待刷、实例缺失、Hash 不一致或 Plug 无法映射时显示结构化阻断原因，不生成伪链接。
- 只有应用配装穿戴步骤已由轻量 Profile 确认在游戏内生效后，才开放 `保存到游戏内槽位`；覆盖已有 Bungie 槽位必须明确确认，应用配装不会因发布而自动删除或同步。发布必须生成独立不可变计划，绑定来源执行计划、账号、角色、已确认实例和目标槽位内容指纹；确认前再次核对当前已确认装备事实，装备状态或槽位变化时保持零写入。写入后按目标范围重新读取并核对槽位实例，使用发布计划、确认、执行和步骤 ID 写入验证记录。草稿变化必须立即废弃旧执行与发布报告。

状态矩阵必须覆盖：首次读取、空目录、链接读取失败、DIM 部分解析、候选计算中、无满足约束候选、方案未保存、方案有未保存修改、穿戴计划不可执行、穿戴部分失败、穿戴成功待发布、槽位覆盖确认和发布失败。已确认字段继续显示，缺失字段不得按名称或相似配置补造。

| 子职业与构筑 | `subclass_target`、`guidance` | 仅保存稳定 Hash 和已解析条件；不能证明可写的配置在产品中保持“仅记录”。 |
| 护甲规划 | `armor_constraints`、`ArmorPlannerWorkspaceState`、`armor_plan` | 模式、套装、锁定、排除、异域、位置范围、六维和五部位属性模组规则随草稿保存；全局数量只是派生摘要，临时候选不持久化。选择库存或升级候选后保存稳定结果 ID、可选缓存键、候选 ID、规则/来源 revision、真实实例 ID，以及逐件 slot、Socket、属性、数值、Plug、模组能量和最终能量账本；重新打开时从这些稳定字段恢复摘要，执行前按刷新后的实例、Socket 和能量重新预检。 |
| 应用配装详情与摘要 | `LocalLoadoutPlanMatch`、账号当前快照 | 匹配结果是即时派生值，不写入 `loadout-plans.json`；未读账号只显示等待核对。`穿戴此方案` 持续可见但按真实缺口禁用或降级。 |
| DIM / 攻略 / AI 成果入口 | `previewDimLoadoutImport`、`createDimLoadoutExport`、`readGuideSource`、`parseBuildGuide`、`matchBuildGuide`、`createGuideLoadoutDraft`、`equipment_target_candidates` | DIM 只接受包含 `loadout` 数据的自包含完整链接，在本地解析且不访问 DIM 分享接口；不支持需要联网解析的 `dim.gg` 短链接。导入必须先显示预览；攻略链接、正文和 `guide_capture` 直接进入配装页统一导入区，选择角色后解析并按账号核对。所有导入与成果交接都只生成未保存草稿，不直接写入方案。 |
| 穿戴与发布 | `createLocalLoadoutPlanExecutionPlan`、`createLocalLoadoutPlanPublishPlan`、实例级 write action、刷新核对与 Bungie 槽位 action | 保存应用配装、穿戴和保存到游戏内槽位是三个独立动作；步骤失败停止后续执行，只有真实刷新核对成功后才允许发布。发布前复核账号、已装备实例和槽位指纹，发布后核对目标槽位实例并记录验证。 |

- 攻略中的护甲属性是五件护甲聚合目标，必须预填到 `armor_constraints.stat_minimums`，不得按单件护甲属性筛选账号实例。
- 当前 Armor 3.0 六维可直接预填；旧六维名称必须显示映射说明并进入待确认，用户复核前不得伪装成已确认事实。
- 只有唯一且带实例 ID 的异域命中可以预填固定异域；同名多实例必须由用户选择。攻略没有明确给出逐部位属性模组安排时，五个部位保持 `自动` 并显示复核提示，不从聚合数量猜测具体位置。
- 接受库存或升级候选后必须保存稳定 `result_id`、候选 ID、规则版本、来源 revision 和真实实例 ID；`cache_key` 只用于短期复用。方案摘要显示缩短后的结果引用，缓存过期只提示重新计算，不得让已保存真实实例伪装成失效或自动替换。
- 应用配装穿戴计划必须显示计划引用和完整步骤。用户确认后、第一步写操作前强制刷新账号并重建计划；账号、目标角色、实例、位置、来源角色替换、可写 Plug 或缺口变化时显示“计划已失效”，不得执行部分旧步骤。
- 执行前复核失败与执行后刷新验证失败是两个独立状态；前者必须是零写入，后者显示逐项完成数、失败步骤和账号刷新核对结果。
- 用户确认后生成独立确认 ID 和执行 ID；应用配装的每个转移、装备与 Plug 步骤必须把计划、确认、执行和步骤 ID 传入操作日志。穿戴确认页显示缩短后的执行引用，设置页日志保留完整 ID 的悬停信息和复制诊断。
- 执行后必须写入同一执行 ID 下的验证记录，状态为 `verified / partial / mismatch / unavailable`。设置页提供“执行验证”类型筛选；部分完成和验证不可用使用警告状态，不得统一显示成普通成功或失败。

### 配装状态矩阵

| 状态 | 可见区域 | 允许操作 | 不允许伪造 |
|---|---|---|---|
| 首次读取 / 空目录 | 目录和创建入口 | 新建、当前装备复制 | 不展示旧模板或虚构方案。 |
| 未保存草稿 | 槽位式应用配装编辑器和实时摘要 | 编辑、选择实例、显式保存 | 不显示为目录中的已保存方案。 |
| 已保存但账号未读 | 方案详情和来源 | 编辑、删除 | 不声明装备已拥有或可执行。 |
| 多实例待选择 | 对应装备行和摘要 | 选择具体实例 | 不按名称、Hash 或最近位置静默选定。 |
| 目标 Plug 不可用 / 装备缺失 | 对应装备行 | 编辑目标、查看现有候选 | 不将不可验证 Plug 加入执行计划。 |
| DIM 完整链接本地解析失败 / 攻略解析失败 | 创建入口和操作状态 | 改用包含 `loadout` 数据的完整链接，或修正攻略链接与文本后重试 | 不联网解析 `dim.gg` 短链接，不创建半成品方案，不显示模拟预览或成功状态。 |
| DIM 导出阻断 | 方案应用区 | 选择真实实例、修正 Hash 或 Plug 后重试 | 不为理论、待刷、缺失实例或无法定位插槽的方案生成伪完整链接。 |
| 护甲计算中 / 过期 / 无候选 | 护甲章节和摘要 | 调整约束、重新计算 | 不显示旧模式候选，不把理论身份或待刷要求伪装为真实实例，不把无候选表示为已优化。 |
| 穿戴计划不可执行 / 部分失败 | 执行核对和操作状态 | 查看已完成、失败和未执行步骤 | 不回滚成功步骤或报告虚构事务成功。 |
| 穿戴成功待发布 / 槽位覆盖 | 发布区域 | 选择真实 Bungie 槽位并明确确认；确认后再次刷新并执行失效校验 | 不自动覆盖槽位，不使用已变化的装备状态或槽位内容，不同步或删除应用配装。 |

## 通用状态要求

所有菜单必须保留正常、首次加载、刷新中、空、失败、部分失败、无权限、禁用和进行中状态。状态只影响所属区域；已确认事实继续显示，缺失字段不补造，写操作成功前不更新事实值。
