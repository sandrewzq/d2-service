# 装备详情与知识分析规格

> 状态：装备详情的长期功能、数据与交互参考规格
> 更新时间：2026-09-03

## 目标

让资料库、仓库和商人入口分别复用稳定的武器详情与护甲详情能力，同时正确区分定义、当前商人售卖品和账号真实实例。武器与护甲共享详情外壳和基础设施，但使用不同的领域模型、章节结构和内容组件，不能合并成一套包含大量可选字段的通用详情模型。

本需求不重新定义商人页面结构，也不负责判断官方来源。商人和官方来源数据由 services 层的商人与官方来源模块提供。

## 术语约定

- **Perk**：一个独立的武器能力或插槽选项，例如“心无旁骛”。
- **Perk 池**：当前装备版本在 Manifest 中可能出现的全部 Perk 候选。
- **Roll**：一件账号实例或商人 Offer 实际生成的完整配置，包含枪管、电池、各列 Perk 和大师杰作。
- **已选 Perk**：Roll 中每个支持切换的插槽当前生效的 Perk。
- **推荐 Roll**：面向 PvE、PvP 或具体玩法目标的一套目标 Roll；同一装备可以存在多套推荐 Roll。
- **模组建议**：推荐记录中的独立附加建议，不属于 Roll。

界面统一使用“完整 Perk 池”“本件 Roll”“售卖 Roll”“已选 Perk”“Roll 内可切换”“PvE 推荐 Roll”和“PvP 推荐 Roll”。不再使用“当前启用 Perk”“实例 Perk”“推荐组合”或无法区分单项与整套配置的“当前推荐”。

## 玩家文案规则

玩家界面的标题、说明、按钮、空状态、状态消息和 AI 文案统一遵循 [玩家文案字典](../../player-facing-language.md)。该字典是内部术语到玩家用语的唯一对照来源；本需求不再维护第二份映射表。

Hash、Manifest 构建号、接口字段缺失原因和证据对象名称只能出现在开发者诊断工具中，不能作为装备详情的默认内容。

## 已确认原则

- 资料库、仓库和商人入口中的武器共用同一套武器详情架构。
- 资料库、仓库和商人入口中的护甲共用同一套护甲详情架构。
- 武器详情与护甲详情是两套独立领域架构，不互相复用 Perk、Roll、属性或插槽内容模型。
- 入口只决定默认查看对象，不维护三套详情页面。
- 资料库入口默认不选择账号实例。
- 仓库入口默认选择用户点击的账号实例。
- 商人入口默认选择用户点击的当前 Offer。
- 资料库中选择“我的同名装备”后，得到与仓库入口相同的实例内容和操作。
- 所有官方获取方式在资料库、仓库和商人详情中都保留，不因入口不同而隐藏。
- 本文件记录已确认的内容、数据边界和关键交互布局；[统一装备详情合同](ui-specs/equipment-details.md) 记录两类详情的稳定结构，正式代码以 `packages/ui` 的共享实现为唯一产品实现。

## 实现基线与验收约束

武器详情的信息层级、章节顺序和主要阅读方式已经确认。后续需要改变稳定结构时，必须在同一次收口中更新统一装备详情合同与本文件；正式实现进入 `packages/ui`，Web 和 Desktop 只能消费同一份共享组件。

武器详情的结构基线为：

- 五个章节在同一份可连续滚动的武器档案中完整渲染，顶部章节导航用于定位对应章节。
- 章节导航不能改成一次只显示一个章节的互斥 Tab；默认打开时先看到“当前配置”，其余内容必须能沿同一滚动区域继续阅读。
- 统一外壳包含武器档案标题区、当前对象说明、关闭操作和明确的内部滚动区；资料库、仓库和商人入口不得各自维护不同弹框外壳。
- 传说、异域、固定配置和随机配置武器共用相同外壳、章节顺序、导航、属性、来源、版本和实例结构，只在真实能力不同的位置切换局部内容。
- 资料库武器结果、仓库实例和商人 Offer 必须进入同一个共享武器详情组件。旧的资料库定义弹框不能继续作为武器详情的独立入口。
- 当本文件、统一装备详情合同与现有实现不一致时，先确认真实功能与当前合同；需要改变基线时必须重新进行视觉验收并同步更新文档，不能只让实现自行偏离。

## 武器与护甲架构边界

武器和护甲不是同一种详情内容的条件分支。领域层必须分别提供 `WeaponDetail` 与 `ArmorDetail`，不得创建一个依靠 `weapon?`、`armor?`、`perkPool?`、`armorStats?` 等大量可选字段维持的通用 `EquipmentDetail`。

两套架构只共享以下外层能力：

- 详情弹框或页面外壳、关闭行为、滚动容器和章节导航基础组件。
- 名称、图标、稀有度、当前 `hash`、版本选择和当前对象摘要。
- 资料库定义、商人 Offer、账号实例三种对象上下文的基础协议。
- 官方来源列表、当前售卖入口、账号拥有状态和同 `hash` 实例基础设施。
- 深色与浅色主题、加载、空状态、错误状态和无障碍基础规则。
- 用户知识、内置知识、AI 外部补充的优先级和证据展示基础设施。

武器详情独立持有：

- 武器栏位、弹药类型、元素伤害、武器框架和固有反勇士能力。
- Manifest 标准属性、Offer / 实例实际属性和待应用 Perk 差值。
- 完整 Perk 池、售卖 Roll、本件 Roll、已选 Perk 和 Roll 内可切换项。
- 普通大师杰作、武器模组、催化剂、强化、锻造和可塑形能力。
- PvE / PvP 推荐 Roll 及命中比较。

护甲详情独立持有：

- 六维属性、总属性、属性分布以及 Offer / 实例的实际属性 Roll。
- 异域固有能力、套装效果、诡计护甲能力和护甲特殊插槽。
- 当前已安装模组、护甲升级和大师杰作状态。
- 个人目标、配装与攻略、社区来源三个独立条件来源及其事实匹配结果。
- 兼容职业、当前角色套装件数和可确认的升级成本事实。
- 不存在武器式完整 Perk 池、本件 Roll、售卖 Roll 或推荐 Roll。
- 不存在目标属性值、最高属性、系统推荐模组、推荐大师杰作或自动生成的购买、保留、升级结论。

共享外壳保证资料库、仓库和商人入口体验一致；独立领域架构保证武器规则不会污染护甲，护甲属性和模组规则也不会被塞入武器配置分支。

## 统一护甲详情框架

传说套装、异域和其他具有特殊规则的护甲使用同一个护甲详情页面。页面固定为五个连续章节：

1. 属性与获取。
2. 护甲配置。
3. 目标匹配。
4. 升级状态。
5. AI 分析。

护甲详情的稳定行为以 [统一装备详情合同](ui-specs/equipment-details.md) 为准：

- 资料库定义、商人 Offer 和账号实例只决定当前对象，不替换页面骨架。
- 属性只显示基础值和当前实际值；资料库定义没有固定 Roll 时保持空状态。
- 套装效果、异域固有能力、诡计护甲、特殊规则、真实插槽和已安装模组按定义能力局部切换。
- 当前 Armor 3.0 护甲配置区显示五个玩家模组位：一个通用或活动位、三个部位位、一个等级 5 解锁的调整位；升级、护甲定位、随机属性、着色器和外观等原始 Socket 不计入模组数量。
- 模组位必须按当前装备 Hash 的 Socket / Plug 语义分类，不能复用旧版本同名护甲的插槽数量，也不能把原始 Socket 数组长度直接显示给玩家。
- 个人目标、配装与攻略、社区来源独立匹配，只显示条件和事实结果。
- 升级区只显示能量、大师杰作、插槽和可确认成本，不生成升级建议。
- 右侧栏只列出当前版本、当前 Hash 且职业兼容的账号实例；`1360px` 以下改为可明确关闭的抽屉。
- 主观结论只允许进入 AI 分析区，保存个人知识前必须由用户确认。
- 玩家界面不暴露 `Manifest`、`Profile`、`Vendor API` 和内部 Socket 类别；这些术语只允许出现在开发者诊断或技术文档中。

## 统一武器详情框架

传说武器、异域武器、固定配置武器和随机配置武器使用同一个武器详情页面、同一套公共组件和同一章节顺序，不按稀有度维护两套页面。统一顺序为：

1. 当前配置。
2. 属性与获取。
3. 玩法推荐。
4. 升级与附加能力。
5. AI 分析。

“我的同名武器”固定进入右侧实例栏，承载当前装备操作和同版本武器切换，不作为第六章在正文中重复渲染。

页面状态由两个独立维度组成：

- **武器能力**：随机配置、固定配置、可塑形配置、异域固有能力、催化剂、普通大师杰作、普通武器模组等。
- **当前对象**：资料库定义、当前商人 Offer、当前账号实例。

入口只决定默认对象。资料库默认查看定义，商人默认查看 Offer，仓库默认查看账号实例；切换对象不替换页面框架。

### 公共组件规则

以下区域必须由传说与异域武器共用，不能复制成稀有度专用版本：

- 武器身份、版本和 Hash 边界。
- 武器类型、弹药、伤害属性和基础信息。
- 基础属性、当前值、差值及修正来源。
- 全部官方获取来源、当前商人 Offer 和来源查询状态。
- 账号拥有状态和当前 Hash 下的同名实例。
- 实例位置、光等、锁定、装备状态、标签和允许的写操作。
- 知识来源优先级和 AI 分析入口。

属性表、来源行、版本选择、导航、实例表、弹框尺寸和滚动行为必须保持相同结构。异域金色只能用于稀有度徽标、异域固有能力和催化剂等局部强调，不能改变整个导航、版本区或页面布局。

不得在统一武器详情内部再打开第二层异域详情弹框。切换到异域武器时，必须在当前详情框架内替换对应数据和条件模块。

### 武器身份摘要

武器名称下方使用统一的快速事实行，按以下顺序显示：

1. 武器栏位，例如 `动能武器`、`能量武器`、`威能武器`。
2. 弹药类型，例如 `主要弹药`、`特殊弹药`、`重型弹药`。
3. 元素伤害，例如 `动能伤害`、`烈日伤害`、`电弧伤害`、`虚空伤害`、`冰影伤害`或`缚丝伤害`。
4. 武器固有反勇士能力，例如 `反屏障`、`反过载`或`反势不可挡`；当前武器没有固有反勇士能力时不显示。

栏位和弹药是两个独立事实：`威能武器`表示装备栏位，`重型弹药`表示弹药类型，不使用“威能弹药”。栏位读取装备槽位定义，弹药读取 `equippingBlock.ammoType`，不能根据其中一个字段猜测另一个字段。

弹药、元素和反勇士信息必须同时提供图标与文字，不能只依赖颜色或图标形状：

- 主要弹药使用白色，特殊弹药使用绿色，重型弹药使用紫色。
- 动能使用中性灰白；烈日使用橙色；电弧使用蓝色；虚空使用紫色；冰影使用冰蓝色；缚丝使用绿色。
- 元素图标优先使用 `DestinyDamageTypeDefinition` 的 Bungie 官方资源。
- 反勇士使用 Manifest / Bungie 官方图标，并提供效果名称和克制目标的悬停、键盘聚焦说明。
- 弹药枚举没有可直接使用的 Manifest 图标时，由应用维护统一的本地图标映射；本地图标只表达分类，不是装备事实来源。

身份摘要不显示“随机配置”“固定配置”或类似标签。配置类型由“武器配置”章节根据真实插槽能力表达，避免把定义能力重复成顶部徽标。

### 武器配置分支

- 武器框架或异域固有能力作为“武器配置”网格的第一列，与枪管、电池和 Perk 列处于同一层级；只有一个固有格子时不得单独占用整行。
- 传说显示武器框架，异域显示异域固有能力；两者使用相同列宽和说明结构，只用小型类型徽标区分。
- 桌面端使用最多六条对齐轨道：第 1 列固定为框架或异域固有能力，第 2 至第 6 列按真实 `socket_index` 承载最多五个有效 Roll 插槽。枪管、弹匣、特性和起源特性只是常见结构，弓弦、箭杆、柄芯、握把、偃月杆、枪托和核心升级等特殊插槽保持 Bungie 定义顺序，不强制移动起源特性。
- 完整 Perk 池不重复渲染框架，从第 2 列开始，与上方真实配置列逐列对齐；中等宽度降为三列，移动端降为单列。
- 反勇士图标和文字统一放在顶部身份摘要。固有区域负责解释框架或异域固有能力本身，不再重复同一个反勇士标签。
- 固有框架或异域固有能力只展示一次，不再复制进下方随机 Perk 池或固定配置列表。
- 资料库定义默认展示只读的完整 Perk 池，不显示“已选”“本实例拥有”或远程切换操作。
- 仓库实例直接在配置网格中标记已选 Perk 和本实例实际拥有的可切换项；不再额外显示一行 Roll 汇总。完整掉落池收进次级展开区域，未拥有的候选不可点击。
- 商人 Offer 默认展示只读售卖 Roll；购买前不能把 Offer 的 Perk 当成账号实例远程切换。
- 仓库实例选择其他已有 Perk 后先进入“待应用”状态，通过明确的“应用更改”提交；Bungie API 成功后才能更新“已选”，失败时保留原配置。
- 玩家可远程切换的前提是联网、完成 Bungie OAuth，且角色处于轨道、社交空间或游戏离线状态；界面使用“远程切换”，不使用容易被理解为断网的“离线切换”。
- 随机配置武器显示完整 Perk 池、本件 Roll、售卖 Roll、已选项和 Roll 内可切换项。推荐 Roll 集中在“玩法推荐”区域展示；Perk 池可以提供“当前推荐”筛选，但不再为单个 Perk 重复添加黄色边线或推荐徽标。
- 固定配置武器在公共固有区域之外显示其余全部固定 Perk，不显示随机 Perk 池、Roll 筛选或推荐 Roll 命中。
- 可塑形或存在可变插槽的异域武器继续显示真实可变配置；不能根据“异域”稀有度强制当成固定配置。
- 配置类型必须根据 Manifest 插槽和当前对象的真实能力判断，不能只根据稀有度判断。

### 推荐分支

- 随机配置武器展示 PvE / PvP 推荐 Roll，并与 Offer 或实例拥有的全部可切换 Perk 比较。
- 固定配置武器展示玩法、配装、催化和使用建议，不生成不存在的推荐 Roll。
- 两种分支继续使用用户知识、内置知识和 AI 外部补充的统一优先级。

### 升级与附加能力分支

- 普通大师杰作、强化 Perk、武器模组、锻造等级和催化剂都按当前定义真实存在的能力显示。
- 固定配置异域武器存在催化剂时，显示获取提示、账号进度、完成条件、完成效果和杰作状态。
- 异域武器没有普通模组插槽时隐藏模组选择，并明确记录当前定义不支持；不能显示一个不可用的空模组控件。
- 催化剂造成的属性或能力变化继续使用公共属性修正模型，不维护第二份异域属性表。
- 催化剂获取提示属于“升级与附加能力”，不作为武器本体的官方获取来源重复显示。

### 商人 Offer 规则

商人 Offer 适用于传说和异域武器。异域固定配置不代表不能被商人售卖：

- Offer 必须保留商人、库存路径、价格、刷新时间、购买条件和当前可购状态。
- 固定配置异域武器的 Offer 通常复用定义中的固定 Perk，但仍然是独立的当前售卖对象。
- 异域 Offer 不计入账号拥有数量，购买完成并刷新账号后才能切换为真实实例。
- 同一件武器存在多个商人 Offer 时全部显示，不能只保留当前入口对应的商人。
- 当前没有 Offer 时显示“当前未在售”，但不能隐藏其他官方来源。
- 异域同时只能装备一件属于写操作约束，只在执行装备时处理，不形成独立页面。

## 领域对象

### 装备定义

由当前 Manifest 中的具体装备 `hash` 决定，包含：

- 名称、图标、稀有度和说明。
- 武器类型、框架、槽位、伤害属性和弹药类型。
- 是否可锻造、支持强化、为专家版或异域装备。
- 基础属性。
- 完整 Perk 池。
- 官方获取来源。

### 当前商人售卖品

商人 Offer 中实际在售的武器内容，可能包含：

- 当前售卖 Roll 和可切换 Perk。
- 当前售卖属性。
- 实际大师杰作和已安装模组。
- 价格、刷新、职业限制、购买条件和购买状态。

商人售卖品不是账号实例，不计入拥有数量，也不能装备、转移、锁定或设置实例标签。

### 当前账号实例

玩家账号中具有实例 ID 的真实武器，包含：

- 实际属性。
- 拥有的全部可选 Perk 和已选项。
- 实际大师杰作、等级和当前模组。
- 光等、位置、锁定和装备状态。
- 本地标签、备注和配装引用。

## 装备身份与版本

装备名称用于发现知识和相关版本，当前详情的 `hash` 是资料库定义、基础属性、官方来源和完整 Perk 池的版本边界；人工来源推荐的适用边界由已证明的发布组决定，DIM 仍以精确 Hash 为边界。

同名但不同 `hash` 的普通版、专家版、复刻版或重新发行版分别保留。切换版本后，基础属性、官方来源、完整 Perk 池和当前版本上下文跟随当前 `hash` 更新；同一发布组的普通与高阶兄弟版可以共享未限定特殊形态的人工推荐，同名历史复刻和不同赛季版本不得自动共享。选中真实实例后，推荐结论按该实例实际 Roll 重新计算。

“我的同名装备”只统计当前 `hash` 的真实实例，不跨版本混合。

版本信息并入身份区右侧的当前对象摘要，不单独占用整条页面横向区域：

- 只有一个已知版本时，紧凑显示当前版本名称、赛季信息和“已选择”状态。
- 存在多个同名 `hash` 时，在相同位置提供“切换版本”入口，展开版本列表后再选择，不改变详情页骨架。
- 武器资料库存在多个可确认定义时才在身份区提供“查看版本”；单版本定义、账号实例和商人售卖不在首屏展示版本字段，发布与 Manifest 证据收入折叠定义信息。
- 版本选择和当前入口、当前对象、对象类型、配置摘要属于同一上下文区域，章节导航应紧随身份区，不再插入大型版本横条。

## 属性规则

### 三种数值

1. 基础值：Manifest 装备定义提供的官方属性。
2. 当前售卖值：基础值叠加商人 Offer 中实际生效的 Perk、大师杰作和模组。
3. 当前实例值：基础值叠加账号实例中实际启用的 Perk、大师杰作和模组。

资料库定义没有“当前实际值”，只显示资料库标准值。商人接口没有返回足以计算售卖属性的数据时，只显示资料库标准值并标记“Offer 未返回属性”，不能用标准值冒充当前售卖值。只有选中真实账号实例，或 Offer 已返回可追溯的完整修正数据时，才显示当前实际轨道。

售卖品或实例存在时，每项属性保存：

```text
基础值
当前值
差值
差值来源
改善或降低
```

不能简单把正数标为改善。充能时间和拉弓时间降低通常更好，射程、稳定性和操控性通常提高更好。

无法可靠计算时显示当前值暂不可计算，不能把基础值冒充实例值，也不能生成虚假差值。

### 属性范围

当前阶段只使用 Bungie 官方数值和可追溯修正，例如冲击、射程、稳定性、操控性、填装速度、射速、弹匣、辅助瞄准、后坐方向、缩放、空中效率、充能时间、拉弓时间和弹药生成。

暂不生成 DPS、TTK、首领总伤害、精确伤害衰减距离、实际换弹时间或击杀所需弹数。

## 官方获取来源

详情消费 services 层商人与官方来源模块产出的单一来源结果。

内容只保留：

- Bungie 商人和 Offer。
- Bungie 当前活动直接奖励。
- Manifest 官方来源提示。
- 来源查询是否完整和数据更新时间。

账号拥有、社区内容、知识库和 AI 均不能生成官方获取来源。

商人、价格、刷新、购买条件和售卖 Roll 只完整存在于来源 Offer。其他详情内容可以引用该 Offer，但不能再保存第二份商人摘要。

## 完整 Perk 池

完整 Perk 池只适用于存在随机配置的武器，并且只包含构成武器 Roll 的插槽：

原型和正式页面都必须展示当前武器真实的完整候选，不能为了排版只截取每列前几个 Perk；通用 PlugSet 中的强化副本、其他武器类型专用组件和 `currentlyCanRoll` 之外的技术条目则不计入当前武器基础候选。

- 固有特性或武器框架。
- 枪管或瞄具。
- 弹匣或电池。
- 特性列。
- 起源特性。
- 武器确实存在的其他 Roll 插槽。

不包含大师杰作、武器模组、着色器、装饰、击杀记录器、锻造纪念物或其他视觉和追踪插槽。

完整 Perk 池是定义级候选列表，即使从账号实例展开，也不标记“已选”、当前实例拥有或待应用状态，不提供点击切换。当前选择和实例可切换范围只在上方“本实例可切换项”中表达。桌面端不重复渲染框架卡片，从第 2 列开始按已确认的有效 Roll Socket 顺序对齐，不假设第五列一定是起源特性。

Manifest 和账号接口返回的原始 Socket 还可能包含染色器、武器模组、大师杰作等级、催化剂、击杀记录器、默认皮肤、战斗特效和装备强化阶级。正式实现必须先按 Socket / Plug 语义筛出有效 Roll 插槽，再使用真实 `socket_index` 排序，不能直接渲染全部原始插槽：

- 武器模组、大师杰作、催化剂和装备强化阶级进入“升级与附加能力”。
- 染色器、默认皮肤、战斗特效、击杀记录器和其他视觉或追踪插槽不进入武器配置，当前默认隐藏。
- 未识别的技术插槽默认不展示，并保留给开发者诊断；不能因为存在于 Manifest 或实例 Socket 列表就自动视为 Roll。
- 不使用“只保留前五个插槽”或固定删除某几个编号的方式。弓、剑、偃月、异域和可塑形武器必须继续按真实 Plug 类别保留有效配置。

强化 Perk 与普通 Perk 建立关联，不作为毫无关系的两个候选。

### 固有反勇士提示

武器详情必须在顶部身份摘要展示 Bungie 官方反勇士图标，并同时提供明确文字，不能只依赖颜色或图标形状：

- `贯穿护盾`：反屏障勇士。
- `干扰`：反过载勇士。
- `眩晕`：反势不可挡勇士。

凯旋纪念碑后的“反勇士 2.0”把基础反勇士能力整合进武器固有框架，命中后立即施加，不再按旧规则从神器武器模组推断。数据解析顺序为：武器自身 `breakerTypeHash`、已插入 Plug 的 `breakerTypeHash`、固有框架 Plug 的 `perks[].perkHash`。当前 Manifest 中常见的隐藏映射为：

- `3469621377` → 屏障 / `贯穿护盾`。
- `472686235` → 过载 / `干扰`。
- `2917776374` → 势不可挡 / `眩晕`。

图标使用 Manifest / Bungie 官方资源；鼠标悬停或键盘聚焦时说明效果与克制目标。反勇士图标和文字放在顶部身份摘要，固有区域不再重复同一标签；反勇士能力也不能被误列为随机 Perk，或重复放入来源、推荐和神器区域。

每个 Perk 可以引用以下事实：

- 当前实例拥有。
- 当前实例启用。
- 当前商人 Offer 使用。
- 知识库推荐。
- DIM 个人目标。

这些引用不复制商人价格、实例位置或推荐理由。

如果实例数据返回了当前 Manifest 池中没有解析到的 Perk，保留该 Roll 中的真实 Perk，并标记“未在当前 Manifest Perk 池中解析到”。

## 当前 Roll

当前实例显示该实例拥有的全部可选 Perk，并在对应卡片上用简短“已选”状态标记当前选择；不再单独显示“当前启用”汇总行。

- 当前属性只按启用项计算。
- 知识库和 DIM 匹配检查实例拥有的全部可选项，不只检查已选项。
- 大师杰作、模组、外观和记录器不算作 Roll。

当前商人 Offer 使用相同规则，但只能使用 Bungie Offer 明确提供的数据。接口没有返回完整属性或插槽时留空，不根据名称猜测。

属性轨道同时表达三个层次，不能只显示“基础值与当前值”：

- **当前实际值**：当前 Offer 或账号实例已经生效的最终数值。
- **资料库标准值**：当前武器定义未叠加实例 Roll、杰作、模组或催化修正时的标准值，以独立刻度标记。
- **待应用差值**：仓库实例选择其他已有 Perk 后，相对当前实际值的增减量和应用后的预览值；Bungie 写操作成功前不能覆盖当前实际值。

取消待应用操作后移除预览差值；写操作成功后，预览值转为新的当前实际值。资料库和只读 Offer 没有待应用状态时只显示前两层。

## 固定配置与异域武器分支

固定配置异域武器只在统一框架的“武器配置”和“升级与附加能力”区域使用条件分支：

- 武器配置区优先展示异域固有能力及其生效方式。
- 使用“固定配置”展示全部固定 Perk，不提供随机 Roll 筛选和推荐 Roll 命中判断。
- 催化剂独立展示获取提示、完成条件、进度和完成后的属性或能力变化。
- 属性区域同时展示基础值、催化增加值和最终值。
- 账号状态区分未拥有、已拥有、催化进行中和催化已完成。
- 推荐区提供 PvE / PvP 使用方式、配装方向和催化建议，不生成不存在的推荐 Roll。
- 获取方式、外观和账号中的同名武器继续复用统一来源与账号能力。

普通大师杰作、武器模组、催化剂、锻造等级和强化能力都按实际插槽存在性显示。异域武器没有普通模组插槽时直接隐藏该项；异域同时只能装备一件属于写操作约束，不形成独立页面。

异域武器并非全部固定配置。存在可变 Perk 或可塑形配置的异域武器时，仍优先展示异域固有能力和催化剂，但可变插槽复用随机 Roll / 配置编辑能力；不能因为稀有度为异域就隐藏真实可变插槽。

统一武器原型的异域场景使用本机中文资料库和仄库存中的真实“血色浪漫”：固定配置为“禁用武器 / 小口径枪膛 / 精确弹药 / 残忍疗法 / 重型握把”；当前仄 Offer 为 23 奇异硬币；催化完成后射程增加 20。账号实例和催化进度仍为匿名交互样本。

## 大师杰作与模组

没有选择商人 Offer 或账号实例时，只显示推荐大师杰作和推荐模组。

选择当前商人售卖品时显示：

- Offer 实际大师杰作、等级、模组和真实属性影响。
- 知识库推荐大师杰作和模组。
- 当前售卖内容与推荐的差异。

选择当前账号实例时显示：

- 实例实际大师杰作、等级、模组和真实属性影响。
- 知识库推荐大师杰作和模组。
- 当前实例与推荐的差异。

未满级大师杰作只计算当前等级的实际加成。无模组时明确记录为空，不能把推荐模组当成已经安装。

需要兼容锻造武器等级、强化固有特性、强化 Perk、专家模组、固定大师杰作和没有对应插槽的武器。

## 我的同名装备

“我的同名装备”包含当前 `hash` 下所有具有实例 ID 的真实装备：

- 已装备。
- 角色背包。
- 仓库。
- 邮政官。

不包含收藏解锁、已经失效的配装引用、没有实例 ID 的记录或其他同名不同 `hash` 版本。

用户可以在同版本实例之间切换。切换后同步更新：

- 当前 Roll 和已选项。
- 实际属性和差值。
- 大师杰作和模组。
- 光等、位置、锁定和装备状态。
- 标签、备注和配装引用。
- 推荐匹配和 AI 分析对象。

只要选择了真实账号实例，不论从资料库还是仓库进入，都提供相同实例操作：装备、转移、锁定或解锁、本地标签、备注、同版本比较、复制摘要和加入配装草稿。游戏 API 不支持的拆解操作不提供。

## 推荐知识

### 来源优先级

推荐来源按字段使用以下优先级：

1. 用户指定并确认保存的个人知识。
2. 内置知识库。
3. AI 查询的外部知识。

用户未指定的字段可以由内置知识补充，内置知识也缺失时才使用外部知识。不同来源冲突时明确说明，不能静默拼成一条不存在的推荐。

DIM Wishlist 保留为用户手动导入的个人目标，不属于系统默认推荐，也不依赖 DIM API。

### 名称解析

知识库按武器和 Perk 名称维护，不要求人工维护 `hash`。`hash` 和 Manifest 发布记录只作为后台追溯与精确识别证据，不限制同名历史版、复刻版、专家版或高阶版共享来源推荐。

使用时：

1. 当前详情先确定具体实例和官方武器身份。
2. 查询来源推荐时依次使用 Hash 精确身份、官方英文名称和唯一的官方中文名称；中文名称存在歧义时不猜测。
3. 同名历史版、复刻版、专家版和高阶版共享同一来源要求。
4. 当前 `hash` 的定义池只用于补充 Perk Hash 和插槽证据，不能删除正式知识库中已经清洗保留的来源栏位。
5. 按实例实际拥有的 Perk 和大师杰作判断符合或不符；只有实例 Roll 未完整读取时才显示数据异常。

### 推荐内容

一条推荐记录可以包含：

- 武器名称。
- PvE、PvP 或通用模式。
- 推荐 Roll 名称和优先级。
- 各 Perk 插槽候选，单个插槽允许多个替代选项。
- 推荐大师杰作。
- 独立的模组建议。
- 使用场景和推荐理由。
- 更新时间。

不保存虚构采用率、Light.gg 排名或没有出处的社区热度。

人工整理来源按“符合栏位数 / 来源要求栏位数”展示，并逐栏说明符合或不符；DIM 按命中的愿望单组合数展示，未命中时显示最接近组合的 Perk 命中数。只有真实 Roll 未完整读取时才进入数据异常状态，不把跨版本定义池差异展示为“待核对”或“当前版本不适用”。

## AI 分析

AI 允许使用三类知识：

1. 用户指定知识，优先级最高。
2. 内置知识库。
3. AI 自行查询的外部知识，优先级最低。

外部知识必须保留网站、链接和查询时间。无法提供出处时只能标记为 AI 推测。外部知识只用于 Roll、模组、大师杰作和玩法分析，不能修改 Bungie 官方获取来源。

AI 可以结合 Manifest、商人 Offer、账号实例、同版本实例和知识库进行解释与比较，但不能虚构采用率或把低优先级内容覆盖高优先级知识。

分析对象由当前查看内容决定：

- 资料库装备：解释武器定位、完整 Perk 池、知识库推荐和官方来源。
- 当前商人售卖品：比较售卖 Roll、属性、大师杰作、模组、账号已有实例和知识库，回答是否值得购买。
- 当前账号实例：比较实际 Roll、属性、同版本实例和知识库，回答是否值得保留及如何使用。

知识库没有当前武器时，AI 可以查询外部知识或解释官方 Perk 效果，但必须明确来源，不能把外部结论伪装成内置知识库推荐。

## 用户知识持久化

用户在对话中提供的新知识可以立即用于当前分析，但不能自动持久化。

持久化流程：

1. AI 识别新的武器知识。
2. 提示当前只在本次对话生效，并说明可以保存到个人知识库。
3. 保存前列出武器、模式、Roll、大师杰作、模组、理由和将覆盖的内置字段。
4. 用户明确确认后才保存。
5. 保存后个人知识优先级最高，并支持查看、修改、删除、禁用和恢复内置知识。

AI 外部查询结果默认只缓存。用户明确确认保存后，才以“用户确认的外部知识”进入个人知识库，并保留原始链接。

- 属性轨道已区分定义、Offer 和实例语义；支持标准值、当前值、当前修正来源、正负待应用变化和属性方向感知。
- 武器原始 Socket 已通过共享语义分类器拆分；配置区只消费框架与五列 Roll，升级区消费模组、杰作、催化剂和强化阶级，外观与记录器不再混入 Perk 池。
- 强化 Perk 副本不进入定义级基础掉落池；账号实例返回强化版本时会关联对应普通 Perk，并在本件 Roll 中标明“强化版本”。
- Web 和 Desktop 已直接挂载共享武器详情，覆盖定义、Offer、实例、传说、异域和现有明暗主题，并保留非武器商人商品的通用详情。
- “我的同名武器”已提供当前实例与另一件同 `hash` 实例的明确比较，覆盖 Roll、升级、位置、锁定、装备、标签、备注和配装引用。
- 只有真实账号实例显示装备、转移、锁定、本地标签、备注、复制摘要和加入配装草稿；定义与 Offer 保持只读。
- 共享详情的实例选择和装备操作已接入可执行状态，不再使用无事件占位按钮。
- DIM 愿望单已从应用默认推荐中拆出，作为独立“个人目标”展示，不参与内置知识优先级。
- 商人 Offer 已显式承载商人、库存路径、价格、刷新、购买条件和失败原因，并与其他官方来源同时展示。
- AI 分析可由用户选择是否查询外部知识；外部结果保持最低优先级，并返回网页链接和查询时间。IPC 已转发定义、Offer、实例、属性、Perk 池和同版本实例上下文。

武器与护甲的代码实现已经分别收口。护甲详情保持五个连续章节、基础值与当前实际值、获取来源、自适应护甲配置、三个独立目标来源、事实升级状态、同 `hash` 兼容职业实例和 AI 分析；资料库无实际属性时保持明确空状态，商人和账号入口只展示可追溯的实际数据。共享 UI 必须按该合同维护，不能回退到此前六章节或推荐模组结构。

此前 backlog 中记录的真实账号验收结果继续有效：

- 商人入口和资料库入口已经能对同一件装备读取相同定义和账号拥有数据。
- 仓库中的“海盗之怒”能按 `hash` 精确定位实例。
- 只在术士背包中的“升华”能正确显示背包拥有数量。
- 商人“海盗之怒”能保留仄的来源路径和当前售卖 Roll。

但现有“Perk 优先双栏方案 A”、`current / historical / unknown` 获取分类、独立 `vendorContext` 摘要和 Light.gg AI 网页读取不再代表最终需求，需要按本文件重新收口。

## 开发切片

### 切片 1：拆分武器与护甲详情领域模型

- 分别建立 `WeaponDetail` 与 `ArmorDetail`，禁止使用可选字段堆叠成通用 `EquipmentDetail`。
- 两个领域分别拆分定义、商人 Offer 和账号实例。
- 武器建立标准值、售卖值、实例值、Perk 修正和待应用差值。
- 护甲建立定义能力、Offer / 实例属性 Roll、模组和升级状态。
- 共享来源、当前对象、版本、同 `hash` 实例和知识证据基础协议，但不共享武器与护甲内容模型。

### 切片 2：资料库与仓库共用详情

- 资料库默认展示装备定义，不自动选择实例。
- 仓库默认选择点击的实例。
- 资料库选择“我的同名装备”后复用完整实例能力。
- 相同 `hash` 实例支持切换和同步分析。

### 切片 3：商人 Offer 接入

- 商人入口选择当前 Offer。
- 使用 Offer 实际 Roll、属性、大师杰作和模组计算售卖值。
- 与基础值、知识库和账号实例比较。
- 购买后刷新账号数据并切换到真实实例。

### 切片 4：知识库与推荐匹配

- 以名称维护内置和个人知识。
- 按武器身份共享同名不同 `hash` 的来源推荐，当前定义池只补充 Hash 证据，不删减来源要求。
- 人工整理来源支持逐栏候选和“符合栏位数 / 来源要求栏位数”；DIM 支持愿望单组合命中和最接近组合。
- 按实例实际拥有项判断符合或不符，只有 Roll 未完整读取时标记数据异常。
- DIM 只作为个人目标，不作为默认推荐。
- 移除 Light.gg 网页读取和虚构社区采用率依赖。

### 切片 5：AI 与个人知识

- 按用户、内置、外部顺序组合知识。
- 为外部知识保留出处和查询时间。
- 根据资料库装备、商人售卖品或账号实例选择分析对象。
- 用户确认后才保存到个人知识库。

### 切片 6：UI 设计与跨端落地

- 传说随机配置与异域固定配置共同遵循已经确认的 [统一装备详情合同](ui-specs/equipment-details.md)。
- 正式页面使用同一个组件结构、章节顺序、属性组件、来源组件和实例组件；只在随机 Perk 池 / 固定配置、推荐 Roll / 使用建议、大师杰作 / 催化剂处切换局部内容。
- 五个章节必须同时存在于同一滚动档案中，章节导航使用锚点或等价定位能力，不得改成一次只渲染一个章节的互斥 Tab。
- 正式页面必须覆盖深色与浅色主题；状态不能只依赖背景颜色，已选、待应用、只读和可远程切换均需文字说明，并在两种主题下保持足够对比度。
- 传说与异域护甲参考 [统一装备详情合同](ui-specs/equipment-details.md)。护甲内部共用五章护甲页面骨架，按定义能力显示异域固有特性、诡计护甲、套装效果和特殊插槽；没有 Offer 或账号实例时不得展示虚构属性 Roll。
- 武器和护甲不是同一个内容组件的两种皮肤。正式实现只共享外壳与基础设施，武器配置和护甲内容分别进入独立组件树。
- 所有页面都使用玩家可理解文案；真实资料与预览账号状态必须明确区分。
- 正式页面进入 `packages/ui`，Web 和 Desktop 共用，不维护第二套实现。
- 资料库、仓库和商人必须通过同一共享武器详情入口传入不同的当前对象，不能在任一入口保留独立武器详情页面。
- 需要调整已经确认的布局或交互时，必须重新进行视觉验收，并同步更新统一装备详情合同和本文件。

## 完成标准

1. 资料库、仓库和商人入口分别消费统一的武器详情架构或护甲详情架构；两者不合并为通用内容模型。
2. 装备定义、商人售卖品和账号实例的数据不会互相冒充。
3. 官方来源、账号拥有和 Perk 数据各自只有一份事实来源。
4. 基础值、售卖值和实例值能够比较并追溯修正来源；无法计算时明确降级。
5. 完整 Perk 池不会混入大师杰作、模组或外观插槽。
6. 同版本实例能够切换、比较和执行允许的账号操作。
7. 推荐只按用户、内置、外部优先级生成，所有来源可追溯。
8. 用户知识只有明确确认后才持久化。
9. AI 不会虚构推荐采用率，也不会用外部知识修改 Bungie 官方获取来源。
10. 武器详情五个章节在同一滚动档案中完整渲染，顶部导航只负责定位，不使用互斥 Tab 隐藏章节；“我的同名武器”固定进入右侧实例栏。
11. 资料库、仓库和商人武器入口使用同一个 `packages/ui` 武器详情组件和统一外壳，不再保留独立的旧资料库武器弹框。
12. 定义、Offer 和账号实例使用各自正确的属性轨道语义，负向变化和“数值降低更好”的属性能够正确表达。
13. 同名实例完整展示并同步光等、位置、锁定、装备、升级、标签、备注和配装引用。
14. Web 和 Desktop 直接消费共享武器详情，并可验收定义、Offer、实例、传说、异域和明暗主题状态。
