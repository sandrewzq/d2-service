# T25：商人购买决策工作区产品需求

> 文档状态：草案，可持续扩展
> 所属任务：[T25 商人购买决策工作区](T25-vendor-purchase-decision-workspace.md)
> 文档职责：记录完整产品需求、状态语义、交互规则和验收场景；不记录阶段进度和具体代码文件清单

## 1. 背景

当前商人菜单已经能够完整浏览 Bungie 当前角色商人、成本、购买条件、声望、任务、服务以及装备 Roll，但玩家仍然需要自行完成多次判断：

1. 售卖 Roll 是否符合推荐。
2. 账号是否已经拥有或解锁。
3. 与账号里同名装备相比是否有新增价值。
4. 刷新后真正变化了什么。
5. 护甲是否能改善当前构筑。
6. 是否需要持续关注某种售卖条件。

因此后续方向不是增加更多库存卡片，而是把商人页已有事实组织成可解释的购买决策。

## 2. 产品目标

### 2.1 核心目标

- 玩家进入商人页后，可以快速发现真正值得检查的 Offer。
- 每个决策结论都能追溯到 Bungie 事实、账号事实或明确推荐来源。
- 低频商人更新发生后，玩家能直接看到具体变化。
- 商人物品可以安全参与比较、规划和关注，但不会被伪装成账号已拥有实例。
- 推荐、收藏、比较或通知等增强资源失败时，基础商人库存仍可使用。

### 2.2 成功标准

- “只看推荐”不再等同于“只看异域”或品质过滤。
- 玩家无需离开商人页即可判断拥有情况和同名 Roll 差异。
- 刷新后无需重新浏览全部库存即可定位变化内容。
- 商人护甲进入规划后不会污染自动穿戴和实例写操作。
- 提醒只由明确刷新事件触发，没有持续轮询。

## 3. 非目标

- 不恢复商人页角色切换器。
- 不提供“账号全部”库存合并。
- 不增加固定间隔轮询或每分钟刷新。
- 不在应用内直接购买商人物品。
- 不自动分解、转移、锁定或替换玩家已有装备。
- 不把异域、稀有品质、高属性总和或单一来源自动解释为必买。
- 不复制 DIM、Today In Destiny 或其他工具的页面与代码。
- 不通过第三方服务读取玩家账号、Token、Cookie 或私有库存。

## 4. 用户与核心场景

### 场景 A：检查本周推荐武器

玩家进入 Xur 或其他商人，希望只查看实际符合推荐来源的售卖武器，而不是所有异域或所有带随机 Roll 的物品。

预期结果：

- 卡片显示短推荐结论。
- “只看推荐”能过滤到真实命中项。
- 打开详情可以查看来源、命中 Perk 和未满足条件。

### 场景 B：避免重复购买

玩家看到模组、着色器、异域装备或武器，希望知道账号是否已有，以及“已有实例”和“收藏已解锁”是否为同一事实。

预期结果：

- 显示账号实际拥有数量。
- 收藏数据可用时独立显示已解锁或尚未解锁。
- 收藏未知时明确显示未知，不从库存猜测。

### 场景 C：比较商人 Roll 与已有装备

玩家希望确认当前售卖 Roll 是否补齐账号内没有的组合，或者只是重复已有内容。

预期结果：

- 详情展示同身份实例数量和位置。
- 可比较 Perk、属性、推荐命中和数据完整性。
- 没有稳定证据时不宣称“绝对升级”。

### 场景 D：查看本次刷新变化

商人刷新频率低，玩家只想知道本次新增、变化和下架了什么。

预期结果：

- 显示新增、Roll / 属性变化、购买条件变化和下架数量。
- 新增或变化卡片有文字标记。
- 无变化时明确显示“库存无变化”。

### 场景 E：评估商人护甲

玩家发现一件高属性护甲，希望知道它是否适合当前 Armor 3.0 规划。

预期结果：

- 卡片显示完整属性摘要与当前机灵模组上下文。
- 可以作为“待购买候选”进入规划。
- 含待购买护甲的方案不能直接穿戴。

### 场景 F：关注目标售卖

玩家希望关注指定武器、Perk、收藏缺口或护甲条件，并在应用确认商人库存更新后收到一次提醒。

预期结果：

- 规则可创建、停用和删除。
- 同一 Offer 不重复提醒。
- 提醒能定位到具体商人和 Offer。

## 5. 信息架构

现有“地点目录 / 商人详情”结构保持不变。新增能力按以下位置承载：

| 区域 | 承载内容 | 不承载内容 |
|---|---|---|
| 地点目录 | 商人、条目数、异常状态、可选变化提示 | 账号角色切换、完整推荐证据 |
| 商人头部 | 地点、刷新时间、同步状态、当前角色、相关材料和变化摘要 | 全账号库存合并、长诊断字段 |
| 局部筛选 | 可负担、真实推荐、未拥有、后续可选未解锁 | 全局设置、角色选择 |
| Offer 卡片 | 短推荐、拥有摘要、Roll 摘要、购买条件、新增 / 变化标记 | 完整来源说明、复杂比较表 |
| 统一详情 | 完整推荐证据、账号同名实例、比较、关注入口、护甲规划入口 | 应用内购买 |
| 后台任务 / 通知 | 关注命中、刷新异常和必要状态 | 高频库存播报 |

## 6. 功能需求

### 6.1 真实推荐

#### REC-01 推荐输入

- 只对能够确认物品身份和实际 Roll 的武器生成 Roll 推荐结论。
- 输入至少包含 `itemHash`、实际 Socket / Plug 和 `rollFingerprint`。
- 使用现有五来源推荐和 DIM Wishlist，不新建商人专用推荐真相。

#### REC-02 推荐状态

推荐状态至少区分：

- 完整符合推荐。
- 部分符合推荐。
- 接近 DIM 推荐，并说明缺少项数。
- 来源只推荐武器，没有指定 Roll。
- 明确未符合。
- 推荐未覆盖。
- Roll 数据不完整，无法判断。

卡片可以压缩为短标签，统一详情必须保留完整来源级解释。

#### REC-03 推荐筛选

- “只看推荐”只保留有正向推荐证据的 Offer。
- “未覆盖”“未符合”和“数据不完整”默认不进入该筛选结果。
- 后续如需查看接近推荐，应使用独立明确选项，不能静默混入完整推荐。

#### REC-04 真实性

- 异域品质不得自动标记为高质量 Roll。
- 品质、武器稀有度和来源热度不能替代实际 Perk 匹配。
- 推荐失败不改变 Bungie 的购买状态。

### 6.2 账号实际拥有与收藏解锁

#### OWN-01 实际拥有

- 汇总仓库、所有角色已装备、背包和邮政官中的同身份实例。
- 卡片显示“账号已有 N 件”；为零时可显示“账号未拥有”。
- 数量必须来自中央账号实体 Store，不建立商人页私有账号快照。

#### OWN-02 收藏解锁

- 使用 Bungie Collectibles 状态表达“已解锁 / 尚未解锁”。
- Collectibles 未读取、失败或不适用时显示未知或隐藏，不根据库存反推。
- Collectibles 必须设计为独立异步资源，不阻塞账号装备和商人库存首屏。

#### OWN-03 状态区分

以下事实不得合并为一个“已拥有”勾选：

- 当前账号存在真实实例。
- 收藏中已解锁。
- 商人 API 标记 Owned。
- 当前 Offer 因购买上限或已领取而不可购买。

#### OWN-04 未拥有筛选

- “只看未拥有”使用账号真实实例数量。
- “只看未解锁”只有在 Collectibles 数据稳定后才开放。
- 筛选不修改底层快照和目录总量。

### 6.3 同名实例比较

#### CMP-01 比较入口

- 武器和护甲统一详情显示账号内同身份实例数量。
- 可以打开同名比较；商人 Offer 作为只读候选参加比较。

#### CMP-02 武器比较

- 比较实际 Perk、推荐来源命中和数据完整性。
- 显示账号实例真实位置。
- 可以说明“新增了账号内没有的推荐组合”，但没有确定性规则时不得显示“绝对升级”。

#### CMP-03 护甲比较

- 比较总属性、各项属性和同职业同部位实例。
- 普通比较不等于完整 Armor Planner 结论。

#### CMP-04 Offer 身份

- 商人 Offer 没有玩家实例 ID。
- 比较、详情和规划使用独立 Offer 标识，不得生成伪实例。

### 6.4 刷新与库存变化

#### DIF-01 明确刷新事件

允许触发当前角色商人同步的事件：

- 进入商人菜单。
- 切换商人。
- 账号页当前角色变化。
- 用户手动刷新。
- Xur 到访或离开边界。
- 应用恢复前台且确认已跨过当前商人的 `nextRefreshAt`。
- 权威账号快照更新且可能影响材料、声望或购买条件。
- 资料库激活新版本且商人或物品定义需要重新水合。

不得增加固定间隔轮询。

#### DIF-02 请求合并

- 多个事件短时间内发生时，按账号、角色、商人详情范围和资料库版本合并请求。
- 切换商人继续使用短防抖，只读取最后停留的商人详情。
- 手动刷新使用后发请求优先，能够接管已有后台请求。

#### DIF-03 变化类型

- 使用稳定 Offer 身份和 `rollFingerprint` 比较新旧快照。
- 区分新增、Roll / 属性变化、购买条件变化和下架。
- 成本变化可作为购买条件变化的子原因展示。

#### DIF-04 变化表达

- 商人头部展示本次变化数量。
- 卡片用文字标记“新增”或“Roll 已变化”，不能只使用颜色。
- 玩家查看后可以清除本地新内容状态。
- 无变化时明确显示无变化。

#### DIF-05 持久化

- 只保存最小 last-seen Offer 指纹、刷新边界和已查看状态。
- 不长期保存完整历史库存或建立无限增长日志。

### 6.5 商人护甲与 Armor Planner

#### ARM-01 候选资格

- 只有职业、装备部位和属性数据完整的真实售卖护甲可以进入规划。
- 使用严格定义识别或受控商人白名单，排除服务、占位物和伪护甲。

#### ARM-02 卡片摘要

- 显示总属性、主要高值属性和当前机灵护甲师模组。
- 高属性总和本身不能自动解释为适合当前构筑。

#### ARM-03 待购买候选

- Planner 使用独立“待购买商人护甲”候选类型。
- 候选保留商人、成本、刷新截止时间、职业、部位和属性。
- 结果明确区分账号已有装备与待购买装备。

#### ARM-04 操作隔离

- 含待购买护甲的方案不能直接执行穿戴、转移或锁定。
- 玩家在游戏内购买并完成权威账号同步后，真实实例才能进入正常配装流程。
- Offer 过期后方案必须标记过期，并要求刷新或重新计算。

### 6.6 关注与提醒

#### WAT-01 可关注对象

- 指定武器身份。
- 指定 Perk、推荐来源或 DIM Wishlist 组合。
- 指定异域装备、模组或尚未解锁物品。
- 满足职业、部位、总属性或关键属性条件的护甲。
- 指定商人或全部可读取商人。

#### WAT-02 触发规则

- 只在 DIF-01 的明确商人刷新事件完成后运行匹配。
- 不为通知新增固定轮询。
- 推荐、收藏或护甲数据不完整时不得发送肯定命中通知。

#### WAT-03 去重

- 使用关注规则 ID、Offer 身份、`rollFingerprint` 和刷新周期去重。
- 同一 Offer 在同一刷新周期只提醒一次。
- Roll、购买条件或刷新周期变化后可以重新评估。

#### WAT-04 提醒表达

- 应用内提醒包含商人、物品、命中原因、购买状态和截止时间。
- 系统通知为可选能力，遵循现有通知设置。
- 点击提醒后定位到账号页当前角色对应的商人和 Offer。
- Offer 已过期或角色上下文变化时，打开页面必须重新确认。

#### WAT-05 管理

- 关注规则可以创建、查看、停用和删除。
- 规则本地持久化，不上传账号隐私或完整库存。

### 6.7 材料摘要与可选降噪

#### CUR-01 商人相关材料

- 商人头部只展示当前商人 Offer 实际使用的材料。
- 显示持有数量与主要缺口。
- 不根据余额推断“可购买 N 次”，因为购买上限和其他条件可能独立存在。

#### CUR-02 隐藏银币商品

- 只有永恒之诗内容造成明确噪声时再开放该选项。
- 必须使用官方银币 Hash 和真实成本判断，不根据中文分类名猜测。

## 7. 状态模型

### 7.1 当前角色

- 当前角色由账号页统一决定。
- 角色变化后，旧角色快照立即退出可见状态。
- 新角色数据读取期间显示加载状态，不静默保留旧角色库存。

### 7.2 Offer 稳定身份

建议使用：

```text
账号 + characterId + vendorHash + vendorItemIndex + refresh boundary
```

`rollFingerprint` 用于判断同一销售位置的内容是否变化，不能单独代替 Offer 身份。

### 7.3 资源独立性

以下资源应独立加载和失败：

- 商人基础库存。
- 当前商人完整 Roll 与属性。
- 推荐摘要。
- 账号拥有摘要。
- Collectibles 状态。
- 同名比较数据。
- 关注规则匹配结果。

增强资源失败不得把整个商人页降级为不可用。

## 8. 数据真相与来源

| 数据 | 真相来源 | 说明 |
|---|---|---|
| 当前角色、账号实例和位置 | Bungie Profile / 中央账号 Store | 不通过第三方中转 |
| 商人、销售、成本、失败原因、声望 | Bungie Vendor API | 当前角色实时事实 |
| 物品、Perk、分类和定义关系 | Destiny Manifest | 本地资料库水合 |
| 收藏解锁 | Bungie Collectibles | 与实际拥有分开 |
| 武器推荐 | 本项目五来源与 DIM Wishlist | 社区决策证据，不是官方事实 |
| 护甲规划 | 本地 Armor 3.0 规则与账号快照 | 商人候选保持待购买身份 |
| 变化和提醒 | 本地派生 | 必须能追溯到新旧官方快照 |

## 9. 交互与可访问性

- 保留现有地点目录、章节导航和 Offer 网格键盘导航。
- 新筛选使用 `aria-pressed`，并提供明确可见标签。
- 新增 / 变化 / 推荐 / 拥有状态不得只依赖颜色。
- 详情打开后继续使用统一 Overlay 与既有焦点陷阱，关闭后恢复到原 Offer。
- 筛选导致当前 Offer 消失时，焦点移动到可预测的相邻结果或清除筛选入口。
- 窄屏继续使用单列 Offer，不增加水平商品轨道。
- 动态刷新通过礼貌级 live region 宣布摘要，不逐张卡片播报造成噪声。

## 10. 性能与缓存

- 商人列表只消费轻量推荐和拥有摘要，不加载完整来源证据。
- 推荐匹配进入现有 Worker 或领域索引，不在 React 渲染中遍历完整 Wishlist。
- 账号拥有摘要按身份或 Hash 建立可复用索引，位置 Patch 不重算无关 Offer。
- Collectibles 独立缓存和过期，不加入每次装备写操作的同步链。
- 变化追踪只保存有限指纹，不维护完整历史快照集合。
- 关注匹配只在明确刷新成功后运行，并复用推荐、拥有和护甲派生结果。
- 快速切换商人时，只为最后停留项加载详情。

## 11. 隐私与安全

- OAuth Token、Cookie、API Key 和完整账号库存不得发送给第三方推荐站点。
- 外部推荐只使用本地已导入数据或不含账号身份的公开物品 / Perk Hash。
- 关注规则默认只保存在本地。
- 系统通知不展示角色长 ID、会员 ID 或敏感诊断字段。
- 应用不自动购买、不控制游戏客户端，也不伪造购买成功。

## 12. 整体验收场景

### A. 推荐真实性

- 一个不符合任何推荐的异域武器不会进入“只看推荐”。
- 一个完整命中 DIM Wishlist 的传奇武器会显示推荐摘要，并能在详情查看完整依据。
- Roll 缺失时显示数据不完整，不猜测推荐。

### B. 拥有与解锁

- 账号中存在三个同身份实例时显示“账号已有 3 件”。
- 收藏已解锁但账号无实例时，两个状态分别显示。
- Collectibles 请求失败时，账号实例数量仍然可用。

### C. 比较

- 从商人 Offer 可以打开账号同名比较。
- 售卖 Offer 不出现转移、锁定、穿戴等实例操作。
- 同名但不同发布身份的武器不会错误合并。

### D. 刷新差异

- 同一销售位置更换 Roll 时显示“Roll 已变化”。
- 新增和下架数量准确，无变化时显示无变化。
- 账号页切换角色不会显示旧角色差异或旧库存。

### E. 护甲规划

- 完整商人护甲可以作为待购买候选参加规划。
- 含待购买候选的方案不能直接穿戴。
- Offer 过期后方案要求重新确认。

### F. 关注提醒

- 明确刷新后命中规则时提醒一次。
- 同一刷新周期重复进入商人页不会重复提醒。
- 通知点击后能定位到正确角色、商人和 Offer。

## 13. 待继续细化的问题

- “只看推荐”是否包含“接近 DIM 推荐”，还是另设筛选。
- 卡片最多同时显示多少个状态，避免推荐、拥有、变化和购买条件争夺视觉层级。
- Collectibles 应按账号一次读取还是按当前商人涉及的 Collectible 按需读取。
- 同名比较默认选择账号内推荐最强实例，还是只按位置和时间排序。
- 商人护甲进入已有规划时，如何选择目标草稿以及如何处理职业不一致。
- 关注规则是否需要复用装备目标，还是保持独立的“售卖关注”模型。
- 应用恢复前台时，如何用 `nextRefreshAt` 和缓存边界避免重复请求。
- 变化标记保留到玩家查看、下一次刷新，还是固定时间后自动消失。

这些问题在进入对应切片前继续补充到本文；确认后的稳定页面约束再同步到 `docs/work/references/ui-specs/application-workspaces.md`。
