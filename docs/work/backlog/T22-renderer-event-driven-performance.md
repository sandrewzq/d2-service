## 3. 已验收待发布成果：T21 武器发布版本身份

### 3.1 目标与身份模型

T21 解决普通版推荐无法稳定覆盖同一发布版本的专家、失时、痛苦和全息箔版本，同时避免错误合并正式括号名称、同名历史复刻和不同赛季版本。

```text
weapon_family
  → release_group
    → variant_kind
      → itemHash + instanceId
```

- `weapon_family`：玩家认知中的武器家族。
- `release_group`：由官方 `releases.*` trait 证明的同一轮发布与 Perk 池。
- `variant_kind`：`standard / adept / timelost / harrowed / holofoil / named_variant`。
- 玩家实例继续由 `itemHash + instanceId + 实际 Roll` 独立核对。

只有 `Adept / 专家`、`Timelost / 失时`、`Harrowed / 痛苦` 使用官方后缀白名单；全息箔读取官方 `isHolofoil`。未知括号名称保留为正式身份，不自动剥离。

### 3.2 已实现的匹配规则

```text
精确 itemHash
  → 精确特殊版本名称
  → 同一 release_group
  → 无法证明时不匹配
```

- 普通人工推荐可以覆盖同一发布组的专家、失时、痛苦和全息箔兄弟版。
- 来源明确限定高阶版本时，不反向套用给普通版。
- `BRAVE version`、玖的仪式版本等来源文字只允许精确 Hash 或精确名称。
- 同名历史复刻和不同赛季专家版保持独立。
- DIM 保持原始 `itemHash + perkHash` 完整组合，不参与发布组扩展。
- 不修改 CSV，不要求玩家重新导入，保留已有来源停用和规则排除记录。

### 3.3 已验收结论

- 普通版与同发布版本高阶变体可以共享未限定特殊形态的人工推荐。
- 显式特殊版本推荐不会反向套给普通版。
- 德兰格（巴洛克）、旅者之选（破损）和未知括号名称不会错误合并。
- 同名历史复刻和跨赛季专家版不会串联推荐。
- DIM、已导入数据和玩家纠错设置继续有效。
- 当前代码已由用户验收，但不属于 v0.0.22 标签内容；本文件不再为 T21 增加新业务范围。

## 4. 公共问题定义

当前同步、推荐来源筛选、单件取出、加锁 / 解锁和打开武器详情都曾出现卡顿。这些现象不是互相独立的功能 Bug，而是同一架构问题的不同触发方式：

> 事件只改变一件装备或一个局部区域，但当前状态通知、派生计算和 React 渲染经常扩大为整账号、整页乃至产品根更新。

当前真实账号约有 1361 件已知物品、1131 件仓库物品和 882 件武器。在该规模下，任何与装备总量成正比的前台重建都会变成可感知的主线程停顿。

### 4.1 已确认的公共根因

1. `useDesktopProductShell` 同时持有账号、推荐、资料库、商人、配装、设置、后台任务、AI 和装备详情状态。
2. `DesktopMenuSession` 每轮重新创建；普通 React Context 的任意字段变化都会通知当前菜单 Provider。
3. `accountEntityStore` 已有 `itemsByKey` 和位置 ID 列表，但页面仍订阅完整反规范化 `AccountSummary`。
4. `VaultPageContentView` 将筛选、排序、选中、批量、快捷操作、推荐和整理状态放在同一组件，并多次全表派生。
5. 推荐同步按实例读取同步 SQLite、解析完整 `match_json`，再把约 900 份完整来源证据传回 Renderer。
6. 装备详情没有独立 Overlay Store / Host，首屏挂载全部章节，多个异步结果分别推动产品根更新。
7. `requestIdleCallback`、延迟、transition、虚拟列表和 `content-visibility` 只能调整时机或绘制，不能替代订阅范围隔离。

### 4.2 目标架构

```text
Bungie / SQLite / 推荐知识库
              ↓
主进程专用 Worker 与领域索引
              ↓
实例级增量事件
{ revision, changedItemIds, changedCollections }
              ↓
Renderer 细粒度 Store
├─ ShellStatusStore
├─ AccountEntityStore
├─ VaultQueryStore
├─ RecommendationSummaryStore
└─ ItemDetailOverlayStore
              ↓
独立渲染区域
├─ Shell Chrome
├─ 当前菜单页
└─ Overlay Stack
```

目标不是替换整个状态框架，而是扩展已有 `useSyncExternalStore` 和实体 Store，使事件粒度、选择器粒度和渲染粒度一致。按照 `$game-ui-ux` 的菜单栈原则，顶层详情 Overlay 独占输入和焦点，背景菜单保持挂载但不得继续消费详情更新。

## 5. 实施阶段

### S0：建立可比较的性能基线

> 代码状态：✅ 低开销诊断接线完成；⏳ 待真实账号复现并保存基线结果

#### 实现

- 记录“玩家点击 → Overlay 骨架首次提交 → 当前配置可交互”的分段耗时。
- 记录单件写入的 Bungie 网络、主进程处理、账号 Patch、Renderer 消费和 React commit 耗时。
- 记录关键 Store selector 重算次数、背景菜单 commit 范围和大于 50ms 的主线程长任务。
- 诊断只使用开发工具和轻量性能标记，不建立长期高频日志或让诊断本身引入卡顿。

已接入的记录边界：

- `item-detail-open.overlay-commit`：玩家点击到详情 Overlay 首次 commit。
- `menu:<page>`、`item-detail-overlay`：当前菜单与详情子树的 React Profiler commit。
- `vault-item-write.request`：加锁、解锁、单件快速取出和批量取出的 Bungie 请求。
- `account-patch.apply`：Renderer 应用单件账号 Patch 与发出 Store 通知的同步耗时。
- `long-task`：Renderer 主线程大于 50ms 的浏览器长任务，并关联最近交互原因。

诊断默认关闭，不写磁盘、不进入 React 业务状态。真实账号采样步骤：

```text
1. 在 Renderer DevTools 执行：window.__d2Performance.enable()
2. 重载页面后执行：window.__d2Performance.clear()
3. 连续打开三件武器详情，再执行一次取出、加锁和解锁
4. 查看摘要：window.__d2Performance.summary()
5. 导出明细：copy(window.__d2Performance.snapshot())
6. 完成后关闭：window.__d2Performance.disable()
```

#### 完成标准

- 能区分网络等待与 Renderer 主线程停顿。
- 能分别看到详情打开、详情异步回写和单件账号 Patch 影响了哪些渲染区域。
- S1、S2 完成后可以使用同一组指标进行前后对比。
- 基线结果保存后将 S0 标记完成，并以同一组操作作为 S1/S2 的回归样本。

### S1：详情 Overlay 与产品根隔离

> 代码状态：✅ 已由用户验收；单 Overlay 状态机、Transition 完整首屏、一次关闭和晚到任务失效均确认正常

#### 玩家问题

从仓库等页面打开武器详情时，弹窗可能需要数秒才能稳定响应；推荐、版本和实时获取状态陆续返回后，还会继续影响滚动、关闭和切换。

当前调用链为：

```text
useDesktopProductShell
  → useDesktopProductWriteActions
    → useItemDetailWorkspace
      → useItemDetail
```

详情状态变化会重新执行产品根 Hook、重建 `menuSession`，并可能让被遮罩的仓库页重新执行推荐和筛选派生。详情首屏还会一次挂载当前配置、推荐、属性、获取、升级、锻造和 AI 等全部章节。

#### 实现

- 将装备详情打开态、推荐态、版本态、实时获取态和内部操作态迁出产品根菜单会话。
- 建立共享 `ItemDetailOverlayStore / Host`；顶层 Overlay 独占输入与焦点，背景菜单设为 `inert`。
- 详情结果只通知详情子树；保持菜单 Provider、仓库 ViewModel、装备列表和无关 action 引用稳定。
- 先隔离渲染边界，不用巨型 `useMemo`、延时或 CSS 裁剪掩盖产品根重渲染。
- 为 S5 保留章节按需挂载接口，本阶段不改变推荐、升级、AI、实例操作和完整 Roll 语义。

当前实现结果：

- 新增实例级 `ItemDetailOverlayStore`，菜单只发布稳定的 `open / close` 命令，不订阅详情状态。
- `useItemDetailWorkspace` 已从 `useDesktopProductShell / useDesktopProductWriteActions` 迁入独立 `HomePageItemDetailHost`。
- 推荐、版本、实时获取、AI、备注草稿、详情错误和详情操作反馈只在 Overlay Host 内更新。
- 账号页、仓库页和资料库页不再消费详情 loading key；首屏由 Overlay 直接表达加载和错误。
- 最近浏览先持久化，Overlay 关闭后再更新资料库内存状态；详情写入不再立即刷新设置页操作日志，进入设置页时读取。
- 共享详情通过 Portal 挂到 App Shell 顶层并继承主题变量，打开期间恢复性地将背景同级区域设为 `inert`，关闭后恢复原状态和入口焦点。
- S0 的点击计时起点已前移到 Overlay 命令发布处，可直接验证“菜单点击 → Overlay 首次 commit”全链路。
- 详情 Host 不再用 `requestAnimationFrame`、定时器或第二个 Dialog 延迟创建 Preview；打开命令立即显示唯一共享 Loading Overlay，基础详情准备完成后使用 React Transition 在同一 Dialog 内原子替换完整首屏。
- Overlay Store 的 request revision 同时作为打开会话身份；关闭与切换对象立即使旧 revision 失效。Loading、Ready 和 Error 共用同一关闭命令，已排队的旧任务不能在关闭后重新打开详情。
- 攻略推荐来源默认折叠时只保留来源摘要；逐栏 Perk 对照、图片和说明在玩家展开该来源后才挂载，不再为不可见内容预创建大量节点。
- 武器 / 护甲 ViewModel、来源和推荐证据按真实输入复用；AI 状态、操作提示等局部更新不再无条件重建整份详情模型。

#### 验收

- 点击武器后 100ms 内出现可关闭的 Overlay 骨架；基础详情准备完成后，身份、本件 Roll、章节导航和首屏正文在同一 Overlay 内一次性替换，不展示半成品正文。
- Loading、Ready、Error 任意阶段点击关闭、遮罩或按 `Escape` 一次即关闭；快速执行“打开 → 关闭”后旧任务不得重新弹出详情。
- 单次打开周期只有一个 `data-overlay-root="item-detail"`，Loading → Ready 不重复安装焦点陷阱、背景 `inert` 或焦点恢复。
- 未点击“读取完整 Roll”时不请求完整实例详情。
- 打开详情及推荐、版本、实时获取状态返回期间，背景仓库额外 commit 为 0。
- 玩家可以持续滚动、关闭弹窗和操作已挂载区域，不出现连续数秒主线程停顿。
- 推荐来源、`Perk x/y`、完整 `x/y`、DIM、版本范围和实例操作语义保持不变。
- 关闭详情后最近浏览能够更新；进入设置页能够读取最新操作日志，且二者不会在 Overlay 打开期间推动背景菜单更新。

### S2：账号实体与单件写入细粒度化

> 代码状态：✅ 第二轮稳定 ID 渲染岛完成；⏳ 待真实账号确认产品根、虚拟网格和非目标卡片不 commit

#### 玩家问题与发布关系

玩家点击“取出”后，Bungie 网络请求约为 0.74～1.79 秒；网络等待不应阻塞页面。当前额外卡顿发生在请求成功后：账号 Store 提升整份 revision、重新反规范化全部装备，仓库页随后重建推荐、筛选、排序、整理保护和重复分组。

本阶段曾是下一版本的首要发布阻断。当前已按用户决定把 S1–S5 全部代码收口后再一次性验收，因此 S2 不再单独触发中途 Release。

#### 实现

- 增加实例、仓库 ID 列表、角色容器 ID 列表、账号身份和单件位置选择器。
- 账号 workspace 和仓库 Provider 不再默认订阅完整 `AccountSummary`。
- 卡片按实例 ID 订阅自身数据；单件取出、存入、装备、加锁和解锁只更新目标实例及受影响容器。
- 快捷操作进行态只更新目标卡片，不向全部卡片广播变化中的操作对象。
- 物品仍在当前结果时保留焦点；只有离开筛选结果时才定位相邻物品。
- 仓库操作后不立即把设置页操作日志写回产品根，进入设置页或显式刷新时再读取。
- 推荐摘要按实例 ID、Roll 指纹和推荐 revision 保持稳定；位置变化不得触发推荐重新扫描。
- 保留后续权威 Profile 的单调校准，不恢复写后完整 Profile 轮询。

当前实现结果：

- `AccountEntityStore` 已补充实例实体、仓库实体键和角色容器实体键读取 / Hook；转移时只复制实际包含目标实例的角色容器，未受影响容器继续保留原引用。
- 仓库菜单激活时，产品根账号订阅只跟随接受的新权威 Profile generation；加锁、解锁、转移等本地单件 Patch 不再反规范化完整账号，也不再推动 `useDesktopProductShell`、商人、首页派生和详情保护索引重跑。离开仓库后会立即读取最新实体快照，其他菜单的现有写入语义不变。
- 仓库 Provider 改用不包含材料、装备分组、锻造数据和仓库样本的轻量账号快照；其他菜单仍按各自真实需求订阅账号 Store。
- 仓库位置对象按原始装备实体与位置复用；单件锁定或移动后，未变化装备继续保持卡片 `item` 引用稳定，现有 `memo` 可以跳过非目标卡片 commit。
- 快捷操作进行态迁入按 `itemKey` 分发的 `VaultQuickActionStore`；开始与结束只通知目标卡片，其他卡片不再接收变化中的全局操作对象。
- 仓库写操作不再修改产品根的全局 `isRunningItemAction / itemActionMessage`，也不在完成后主动刷新设置页操作日志；仓库批量面板和目标卡片分别表达自身进度，设置页挂载时读取日志。
- 推荐摘要索引按实例集合、Roll 指纹、推荐结果 Map 和 Wishlist 引用复用；锁定与位置变化不再重建来源摘要及其筛选事实索引。
- 共享仓库 UI 新增按 `itemKey` 分发的 `VaultItemCollectionStore`；实例对象引用变化时只通知对应卡片，移除实例也只通知目标 key，不再把整组装备对象作为卡片 props 广播。
- 武器虚拟网格只接收引用稳定的 `itemKey[]` 和稳定 render callback；结果 key 集合未变化时，单件锁定或位置 Patch 不再推动网格重渲染，可见卡片自行订阅目标实体。
- 非武器列表的“加载更多”只在结果 key 集合真实变化时重置；单件对象引用变化不会把玩家重新打回前 200 件。
- 无 `instance_id` 的特殊装备不进入实例 Store，继续由原对象直接渲染，避免同 Hash 物品共用 `hash:*` key 后串卡片；其选择、标签和定位仍保留原业务 key 语义。
- 普通浏览页不再提前构建清理保护和重复组全表分析；清理保护只在批量选择或同名整理页计算，重复组只在推荐页需要“去整理”定位或实际进入同名整理页时计算。

本轮仍需通过真实账号确认：

- 快捷取出、加锁、解锁的网络等待期间页面可以持续滚动。
- `account-patch.apply` 后产品根和虚拟网格额外 commit 为 0，当前仓库只提交目标卡片、必要计数和位置结果，非目标卡片 commit 为 0。
- 如果记录仍显示仓库筛选、facet 计数或重复分组存在明显长任务，使用 S0 记录定位剩余全表派生，并归入 S4 查询索引阶段；不再把操作 busy 状态退回页面级 React state。

#### 验收

- Bungie 请求等待期间页面仍可滚动，非冲突界面保持响应。
- 请求成功后只更新目标卡片、必要计数和受影响位置，未变化卡片不 commit。
- 取出、加锁和解锁不触发社区推荐重新扫描或 T21 发布身份查询。
- “仓库”范围下取出后正确移除物品并转移焦点；包含角色背包时不发生多余跳转。
- 推荐来源、核心 `x/y`、完整 `x/y`、DIM、清理保护和整理标签保持不变。
- 约 1300 件物品、900 件武器规模下，操作完成后不再出现数秒 Renderer 停顿。

### S3：推荐摘要与详情证据拆分并迁入 Worker

> 代码状态：✅ 完成，待整体验收

- 定义列表专用 `RecommendationCardSummary`，只包含来源、核心 `x/y`、完整 `x/y`、DIM 最佳组合和整理结论。
- 定义选中武器专用 `RecommendationDetailEvidence`，按需读取六栏依据、候选 Perk、说明、链接和 DIM 规则。
- 推荐索引与缓存匹配迁入专用 Worker；主进程不再按实例执行大量同步 SQLite 查询和 JSON 解析。
- SQLite 按账号和实例 ID 集合批量读取，更新后只返回 revision 和变化实例。
- Renderer 的卡片、筛选和清理保护只消费轻量摘要，不保存约 900 份完整来源证据。

当前实现结果：

- Core 已定义 `RecommendationCardSummary / RecommendationCardSourceSummary / RecommendationCardDimSummary`，明确排除逐栏候选、图标、说明、链接和 DIM 规则明细。
- `community:vault:match` 在完整匹配完成后同步生成 `card_summaries`；旧服务或测试适配器未返回新字段时，App 层可从当前匹配结果兼容生成摘要。
- 账号 workspace 为卡片摘要维护独立实例 Map，并支持推荐来源局部变化时只替换受影响武器 Hash。
- 账号页和仓库页构建推荐来源摘要、核心 `x/y`、完整 `x/y` 与 DIM 最佳组合时优先消费轻量摘要，不再为每件卡片遍历完整逐栏证据。
- 账号后台扫描通过 `include_evidence: false` 只把轻量摘要传入 Renderer；`useAccountWorkspace`、账号页、仓库页和产品根已移除全账号 `VaultItemInstanceMatchInfo` Map。
- 清理保护、推荐筛选、覆盖数量和 DIM / 人工来源用途冲突判断只消费轻量摘要；DIM 摘要额外保留已命中用途，避免清理保护语义退化。
- 详情 Overlay 使用 `community:vault:evidence:get` 按单实例读取完整证据，晚到结果只更新当前详情会话，不再依赖账号常驻 Map 回退。
- 同名整理使用轻量摘要列出可比较来源；玩家真正选择某个人工来源后，才批量读取当前同名组的完整逐栏证据，读取期间继续保留实例 Roll 表格。
- “复制验收报告”改为显式操作时批量读取完整证据；普通推荐页浏览与筛选不会为报告预加载约 900 份规则明细。

最终实现：

- 新增长生命周期推荐 Worker，缓存分区读取、旧 `match_json` 解析、缺失实例 Definition / 发布身份准备、匹配计算、摘要生成和缓存写入全部离开 Electron 主进程。
- Worker 批量扫描返回 `revision + card_summaries + changed_instance_ids`；只有详情、当前同名组和显式验收报告返回完整 `matches`。
- Renderer 按变化实例复用未变化摘要引用，并按本轮完整结果集合移除已消失实例；来源局部变化继续只替换受影响武器。
- 资料库激活和应用退出会同时关闭推荐 Worker，激活完成后与 GameData Runtime 一起恢复，避免持有旧 SQLite 连接。

### S4：仓库查询索引与渲染岛

> 代码状态：✅ 完成，待整体验收

- 将静态物品、推荐、整理和位置事实建立为按 revision 维护的索引。
- 筛选使用 ID Set 交集和预计算 facet 计数，不再为每个筛选维度重复遍历全部装备。
- 拆分筛选命令区、结果计数、装备列表、批量操作和重复整理子树，各自订阅最小状态。
- 虚拟网格只接收稳定 ID 数组，可见卡片自行读取实例数据。
- transition / deferred value 只用于保持输入响应，不能替代索引化。

最终实现：

- 新增菜单私有 `VaultQueryIndex`，按稳定实例记录维护范围、锁定、槽位、位置、弹药、类型、稀有度、阶级、职业、伤害、套装和框架 Set；单件对象或事实变化只替换该记录。
- 结果、槽位、位置、框架和武器类型分面复用索引交集与同一推荐允许集合，再对缩小候选执行原有完整筛选，保留搜索语法、标签、愿望单、目标和护甲阈值语义。
- 现有 `VaultItemCollectionStore + VaultQuickActionStore + VaultVirtualWeaponGrid` 继续构成稳定 ID 列表与可见卡片自订阅渲染岛；清理保护和同名整理仍按访问计算。

### S5：详情按需挂载与后台事件合并

> 代码状态：✅ 完成，待整体验收

- 武器详情首屏只挂载身份、当前配置、本件 Roll 和实例操作。
- 推荐、属性、升级和 AI 按玩家访问或接近视口时挂载，已访问章节保留状态。
- 使用 `IntersectionObserver` 维护章节可见性，不在滚动期间同步读取全部章节布局。
- 只有身份主图 eager 加载；Perk、水印和推荐图标按可见性加载。
- 推荐、版本和实时获取结果由对应局部区域消费，不重建完整详情 ViewModel。
- Shell 后台进度只订阅短摘要，高频字节和中间进度按帧或有限频率合并。

最终实现：

- 武器详情只在首屏挂载身份、当前配置、本件 Roll 和实例操作；其余章节保持稳定占位，由 `IntersectionObserver` 在接近视口或点击导航时挂载并在当前会话保留。
- 推荐章节激活后才空闲调度完整推荐和实例证据；属性与获取章节激活后才并行读取同名版本与实时获取状态。推荐回写只组合推荐字段，不重新运行武器配置分类。
- 推荐来源 revision 在详情打开期间变化时，未访问推荐章节只重装 loader，不提前请求；已访问章节只重载推荐区。旧 revision、旧实例和关闭后的晚到结果都不能覆盖当前对象。
- 删除详情滚动事件中的逐章节同步布局读取；除身份主图外的水印、Perk、来源和升级图标全部使用 lazy 加载。
- 主进程后台任务广播限制为约 12.5 次/秒，Renderer 再按动画帧只发布最新快照；Shell 使用不含字节与速率的整数百分比短摘要，完整进度留给设置页。

## 6. 实施边界

- 本任务解决状态粒度、计算所有权、IPC 体积、Overlay 栈和渲染边界，不增加新的推荐来源、筛选维度、装备操作或视觉风格。
- T21 已验收语义是必须保持的业务基线，不因性能重构改变人工来源匹配、DIM 精确 Hash 或玩家数据兼容性。
- 不替换 React，不复制 Desktop 专用页面，不引入第二棵详情或仓库 DOM。
- 共享 UI 继续由 `packages/ui` 唯一实现；平台壳只负责真实 adapter、IPC 和本地能力。
- 不以删除功能、降低推荐语义、隐藏真实状态或降低数据准确性换取性能。
- 不创建长期共存的新旧 Store 双写；每个阶段必须有可观察的独立结果。
- `HomePage.tsx`、`ItemDetailModal.tsx`、`useItemDetailWorkspace.ts` 等属于高冲突公共接线文件，修改保持小而分层。

### 一次性整体验收清单

1. 启动后等待账号与推荐后台同步，同时连续滚动仓库、切换来源和 `x/y` 条件；页面不能因 Worker 匹配或后台任务进度连续卡住。
2. 在仓库整理、当前背包、当前已装备和其他角色之间切换，组合槽位、类型、框架、锁定和推荐命中；结果数与各分面数量一致，清空筛选恢复默认仓库武器。
3. 连续执行一件武器的取出、加锁、解锁；等待网络期间仍可滚动，完成后只更新目标卡片与必要数量，焦点不丢失。
4. 打开武器详情，确认先出现单一可关闭 Loading，再原子展示身份、当前配置、本件 Roll 和操作；不滚动时不应提前请求或渲染下方全部重型章节。
5. 点击或滚动到推荐、属性与获取、升级、AI，确认章节按需出现；推荐命中、完整证据、版本、实时获取和 AI 语义完整，返回期间可持续滚动并可一次关闭。
6. 在资料库更新或应用下载存在高频进度时继续操作仓库与详情；顶部/浮层进度按稳定节奏更新，页面不随字节变化连续重渲染。
7. 快速执行“打开详情 → 关闭 → 打开另一件”，旧推荐、版本、实时获取或 AI 结果不得覆盖新对象，也不得让已关闭详情重新出现。
