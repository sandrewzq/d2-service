# T40：账号容量与风险摘要

> 状态：✅ 已完成，真实账号验收通过
> 优先级：P0
> 类型：只读账号状态
> 账号菜单合同：[应用工作区账号章节](../references/ui-specs/application-workspaces.md#账号)

## 1. 目标

让玩家在账号菜单中立即知道当前角色和整个账号是否存在空间风险，不需要逐个展开武器、护甲和邮政官清单计算剩余位置。

参考 DIM 对容量与邮政官风险的处理目标，但不复制横向库存布局、跨角色拖拽或自动搬运模式。

## 2. 范围

- 当前角色邮政官真实容量、占用和剩余位置。
- 仓库真实容量、占用和剩余位置。
- 当前角色各武器与护甲背包槽位的占用和剩余位置。
- 正常、接近满、已满和可能发生邮政官覆盖的稳定风险等级。
- 三角色容量风险摘要，允许快速定位需要处理的角色。
- 数据时间、同步阶段和是否等待服务器确认。

## 3. 数据与实现约束

- 容量必须来自 Bungie Profile、Manifest bucket 定义或经验证的稳定容量规则，不能根据页面已渲染卡片数量猜测。
- 角色背包、已装备、仓库和邮政官必须使用真实容器字段区分。
- 所有页面继续消费中央账号 Store，不创建账号菜单私有刷新或缓存。
- 两台设备拿到不同 Profile 版本时，旧快照不能覆盖新快照。
- 如果 Bungie 数据暂时无法确认容量上限，应显示“容量上限待确认”，不能填固定示例值。

## 4. 非目标

- 不自动移动、拆解或装备物品。
- 不在本需求实现邮政官批量取回。
- 不实现仓库筛选、跨角色拖拽或整理工作台。
- 不增加独立于账号同步的轮询请求。

## 5. 验收标准

- 页面容量与游戏内相同，刷新后不会因旧快照回退而出现物品忽隐忽现。
- 玩家能区分当前角色风险和整个账号仓库风险。
- 三角色摘要只展示已确认的真实容量状态。
- 同步尚未确认时持续显示进行中或等待状态，不提前表现为完成。
- 容量数据缺失、部分失败和过期均有明确状态，不显示误导性的 `0 / 0`。

## 6. 已实现

- 账号快照始终请求仓库、邮政官、三武器和五护甲的 Manifest bucket 定义，空容器也能读取真实容量上限。
- Core 为每个角色保留容量上限；占用数不写死进快照，而是从中央账号 Store 当前的已装备、背包、邮政官和仓库数组即时派生。
- 角色携带槽位按“已装备 + 背包”统计，与游戏内携带容量口径一致；邮政官同时支持稳定 Hash 识别和本地化名称回退。
- 账号首屏增加容量与风险摘要，展示当前角色邮政官、仓库、三武器、五护甲以及三角色风险短摘要。
- 风险使用文字、数值和进度共同表达；容量未知时显示“容量上限待确认”，不显示 `0 / 0`。
- 刷新中保留上一次结果；中央 Store 存在写操作预计状态时明确显示“等待游戏状态确认”，不提前伪装成同步完成。

## 7. 验收结果

- 2026-09-09，用户使用真实账号完成验收并确认通过。
- 页面正确显示邮政官 `6 / 21`、仓库 `1128 / 1300`，并给出真实剩余容量。
- 当前角色三武器、五护甲共八个携带槽位均按真实占用显示，汇总状态为“8 个槽位正常”。
- 容量摘要、风险文字、进度表达和最高光等操作区在同一账号首屏稳定展示。
