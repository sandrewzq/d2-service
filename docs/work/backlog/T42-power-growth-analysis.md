# T42：光等成长分析

> 状态：📝 候选方案，待排期
> 优先级：P0
> 类型：只读领域计算
> 账号菜单合同：[应用工作区账号章节](../references/ui-specs/application-workspaces.md#账号)
> 后续依赖：T44 的奖励价值判断使用本需求提供的真实掉落基准

## 1. 目标

让玩家理解当前装备光等、最高可装备光等和掉落基准之间的差异，并明确哪些槽位正在拖累提升、哪些高光等物品需要保留。

参考 DIM 的 Gear Power 决策信息，但继续使用本项目的真实实例、职业限制、异域规则和统一账号 Store，不复制 DIM 的库存页面结构。

## 2. 范围

- 当前角色已装备光等。
- 遵守职业、装备槽位和异域限制的最高可装备光等。
- 当前掉落基准及其计算依据。
- 八个装备槽相对掉落基准的 `+N / -N`。
- 每个槽位当前可用的最高光等实例、真实位置和是否能直接装备。
- 拖累整体光等的槽位和高光等保留提示。
- 三角色摘要逐步增加当前光等与最高可装备光等差距。

## 3. 计算与展示约束

- 神器加成、装备基础光等、显示光等和掉落基准必须使用明确术语，不能混成一个“光等”。
- 邮政官是否参与计算必须由产品规则明确；当前最高光等规则继续遵守既有账号合同。
- 跨角色持有但不能直接执行的一件装备可以参与账号最高值分析，但不能进入当前角色的一键装备计划。
- 所有候选实例使用真实实例 ID、位置、职业限制和装备规则，不能只按物品名称或 definition hash 选取。
- 计算结果应由确定性领域函数产生，Web 和 Desktop 不分别实现公式。

## 4. 非目标

- 不在本需求增加新的批量装备写操作。
- 不提供无法直接执行的伪一键方案。
- 不预测 Bungie 未公开的掉落结果。
- 不把活动奖励列表混入光等计算面板。

## 5. 验收标准

- 当前装备、最高可装备和掉落基准三者有清晰、稳定且可解释的区别。
- 每个槽位差值可以追溯到真实实例和位置。
- 职业不符、槽位不符或异域冲突的装备不会进入可执行方案。
- 两台设备基于同一服务器 Profile 版本时得到相同计算结果。
- 玩家能够据此判断下一步需要提升的槽位以及不能误拆的高光等物品。
