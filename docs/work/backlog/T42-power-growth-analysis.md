# T42：光等状态与缺口

> 状态：✅ 已完成，真实账号验收通过
> 优先级：P0
> 类型：只读账号计算
> 账号菜单合同：[应用工作区账号章节](../references/ui-specs/application-workspaces.md#账号)
> 后续依赖：T44 使用本需求的真实光等基线判断奖励价值

## 1. 玩家要解决的问题

玩家需要知道自己的账号目前处于什么光等状态，以及为什么不同角色、仓库和当前装备显示的数字不一样。

本需求回答：

- 当前角色现在穿了多少光等？
- 当前角色合法搭配后最高能穿多少？
- 整个账号的奖励掉落参考是多少？
- 哪些装备和槽位影响了这个结果？

本需求不回答“今天应该刷哪个活动”；具体提升路线由 T44 负责。

## 2. 已有能力（复用，不重复开发）

- 当前角色实际装备的八槽光等。
- 遵守职业、槽位和异域同时装备限制的最高可装备组合。
- 只使用当前角色与仓库的可执行最高光等方案。
- 最高光等方案的八槽实例、来源、光等和相对方案均值的 `+N / -N`。
- 现有“最高光等方案”浮层和“一键装备最高光等”写操作。

这些能力继续使用现有账号 Store、ViewModel 和页面入口，不建立第二套光等页面。

## 3. 本需求新增或统一的内容

### 3.1 三个光等概念

- **当前装备光等**：当前角色此刻实际穿戴的八个装备槽平均值。
- **可装备最高光等**：当前角色按职业和异域同时装备限制，能够合法组成的最高组合。
- **账号奖励掉落基准**：整个账号每个装备槽分别取最高有效实例后计算的平均值，不要求八件装备可以被同一个角色同时穿戴。

页面必须使用不同名称展示这三个数字，不能继续用“账号最高光等”同时指代不同含义。

### 3.2 奖励掉落基准规则

- 候选包括所有角色的已装备、角色背包和账号仓库。
- 邮政官暂不参与计算，不能把尚未取回的物品当成账号可用装备。
- 只接受真实实例 ID、有效装备光等和明确八槽映射的装备。
- 不应用当前角色职业限制。
- 不应用武器或护甲只能同时装备一件异域的组合限制。
- 不把神器加成混入装备掉落基准。
- 同槽同光等时按稳定来源顺序选择展示实例：当前角色已装备、当前角色背包、仓库、其他角色，最后按实例 ID 排序。
- 数据缺槽、实例无效或 Profile 尚未完成时，显示“数据不完整 / 正在同步”，不得用 `0` 补齐。

DIM 只作为算法交叉核对来源，最终结果以同一次 Bungie Profile 的真实实例和位置为准。

### 3.3 现有方案中的缺口表达

继续复用现有八槽方案行和 `+N / -N` 展示，但必须明确差值是相对哪个基准：

- 可执行最高方案中的差值，服务于“一键装备”决策。
- 账号奖励掉落基准的差值，服务于 T44 的奖励价值判断。

两种差值不能混在同一列里。现有可执行方案继续显示面向装备决策的差值；奖励掉落基准使用独立的摘要和可展开构成视图，避免玩家把两个基准误认为同一个数字。

## 4. 实现范围

### 4.1 Core

- 在 `packages/core/src/account/power.ts` 提供独立的奖励掉落基准选择与计算结果。
- 结果包含完整性、整数、余数、精确均值、每槽贡献实例和稳定排序依据。
- 不用最高可装备选择结果冒充奖励掉落基准。

### 4.2 App ViewModel

- 在 `packages/app/src/workspaces/accountPower.ts` 的既有光等 ViewModel 中增加奖励掉落基准字段。
- 所有结果从统一账号快照派生，不增加页面私有缓存、额外 Profile 请求或轮询。
- 保留当前装备、可装备最高、可执行最高和一键装备的现有边界。

### 4.3 账号页

- 继续使用现有“最高光等方案”入口和浮层。
- 在现有摘要区域增加“账号奖励掉落基准”及简短解释。
- 当掉落基准与可装备最高不一致时，说明“掉落基准按整个账号每槽最高计算，不代表当前角色可以直接穿上这些装备”。
- 不新增独立“成长中心”、第二套八槽列表或新的写操作。

## 5. 页面设计方案

### 5.1 入口与信息层级

T42 不新增一级导航。玩家从账号页现有的“最高光等方案”入口打开同一个账号菜单浮层；入口文案可调整为“光等详情”，旁边保留独立的“一键装备最高光等”按钮，避免把只读分析误认为写操作。

浮层首屏必须在不滚动的情况下看到三项核心事实：

```text
当前角色装备       500
当前角色可装备最高   502 3/8
账号奖励掉落基准     504 1/8
```

三项数字使用相同的数值组件、不同的用途标签，不使用“账号最高光等”这一含义不明确的总称。

### 5.2 浮层结构

浮层只维护一棵页面结构，按以下顺序排列：

1. **标题与同步状态**：`光等详情`、当前角色名称、资料状态（已同步 / 正在同步 / 数据过期 / 无法确认）。
2. **三项光等摘要**：当前角色装备、可装备最高、账号奖励掉落基准。
3. **差异解释**：当两个最高值不一致时，用一到两句人话解释“其他角色或仓库的高光装备参与了奖励基准，但当前角色不一定能装备”。
4. **影响基准的装备**：只列出造成差异的前 1～3 个槽位，显示槽位、光等、来源角色或仓库和“当前角色可装备 / 不可直接装备”。没有差异时显示“当前可装备最高已达到账号奖励基准”。
5. **奖励基准构成**：默认折叠的“查看 8 个基准槽位”区域。展开后复用现有光等行组件，逐槽显示基准实例、光等、位置和当前角色可装备状态；不使用“八槽最高”或“理论方案”命名。
6. **可执行最高光等方案**：继续显示现有三武器、五护甲方案行、来源、光等和相对可执行方案均值的差值；一键装备入口保持在该区域之外。

“奖励基准构成”和“可执行最高光等方案”不能同时渲染两份平行表格。实现上使用同一个槽位行 ViewModel / 组件，通过明确的视图模式切换，保证字段和状态语义一致。

八个槽位使用一张连续表格：外框四边闭合，表头与数据行保持一致的横向留白，行间只使用统一单线分隔；武器与护甲不再额外叠加粗边框，也不通过放大弹窗宽度掩盖内部边框问题。

### 5.3 玩家看到的典型结果

```text
当前角色装备       500
当前角色可装备最高   502 3/8
账号奖励掉落基准     504 1/8

为什么不同？
账号奖励基准会参考整个账号每个位置的最高装备。
头盔 506 · 泰坦背包 · 当前角色不可直接装备
胸甲 505 · 仓库     · 当前角色可转移后装备

[查看 8 个基准槽位]
```

说明文字必须同时包含“奖励计算参考”和“不保证下一件掉落补最低槽位”两个边界，避免玩家把基准当成掉落承诺。

### 5.4 响应式与可访问性

- 使用容器、网格和自然换行布局，不使用依赖单一分辨率的绝对定位。
- 桌面宽屏使用覆盖内容区的浮层；窄窗口转为文档流内的抽屉，浮层主体限制最大高度并内部滚动。
- 三项摘要在宽屏横向排列；窄屏按“当前装备 → 可装备最高 → 奖励掉落基准”纵向排列，顺序不变。
- 关键状态不能只用颜色表达，同时显示文字和图标；正负差值保留正负号。
- 浮层打开时焦点进入标题后的第一个可操作控件（视图切换或“查看 8 个基准槽位”）；`Escape`、关闭按钮和返回操作关闭浮层并把焦点还给入口。
- 键盘 / 手柄可以按“摘要 → 差异来源 → 基准构成 → 可执行方案 → 关闭”的顺序移动；展开基准构成后焦点不得跳出浮层。
- 文案、数字和来源字段使用可伸缩容器，不能因中文、英文或较长角色名溢出。

### 5.5 状态与刷新体验

T42 只订阅中央账号 Store 的事件更新，不在浮层内轮询或单独请求 Profile：

- **首次读取**：保留页面骨架，摘要显示“正在读取账号装备”。
- **后台同步**：保留上一次已确认的三项数字和基准构成，同时显示明确的同步进度；不能静默停在旧结果。
- **同步完成**：以新服务器快照重新派生三项数字和来源，旧结果不能回写覆盖新结果。
- **部分数据 / 过期**：保留能确认的行，未确认槽位显示“待确认”，整体状态不显示为完成。
- **同步失败**：保留上一次真实结果，明确标记失败时间和“基于上次确认数据”；不清空成 `0`，也不伪装成最新。
- **装备或转移写操作后**：沿用中央 Store 的预计状态和服务器确认事件，局部更新 T42 结果；不触发整页 Loading。

### 5.6 设计边界

T42 的页面价值是“看懂光等状态和差异”，不是“推荐活动”。浮层中的唯一后续动作可以是进入 T44 的“光等提升路线”（在 T44 实现后接入）；T42 本身不显示固定活动、任务或“必定提升”标签。

## 6. 非目标

- 不重新实现当前装备、可装备最高、可执行最高和一键装备。
- 不在本需求推荐活动、任务或奖励优先级。
- 不预测下一件奖励一定掉落在哪个槽位。
- 不接入赛季等级、声望、成就或完整活动进度。
- 不实现仓库自动保护、自动锁定、分解或邮政官批量取回。

## 7. 验收标准

- 玩家能清楚区分当前装备、可装备最高和账号奖励掉落基准。
- 多角色光等不一致时，账号奖励掉落基准按全账号每槽最高值计算；不改变当前角色实际装备。
- 其他角色职业护甲可以影响账号奖励基准，但不会进入当前角色可执行装备方案。
- 每个基准槽位可追溯到真实实例 ID、光等和位置。
- 缺失或同步中的数据不会显示伪造的完整结果。
- 两台设备基于同一服务器 Profile 版本时计算结果一致。
- 现有最高光等方案和一键装备行为不回归。
- T44 可以直接消费类型化基准和逐槽缺口，不复制计算公式。
- 玩家打开浮层后无需查看日志，即可在首屏看到三项光等、差异原因和同步状态。
- 展开“奖励基准构成”后，八个槽位均可追溯到真实实例、来源和当前角色可装备状态。
- 宽屏、窄屏、键盘和手柄操作均能完成打开、切换、展开和关闭，关闭后焦点返回入口。
- 刷新或写操作确认过程中，页面不清空旧结果、不显示静默完成，也不产生第二套缓存结果。

## 8. 验收结果

- 2026-09-09，用户完成真实账号验收并确认通过。
- 三项光等、跨角色与仓库奖励基准、差异来源、刷新状态和一键装备回归均符合预期。
- 光等详情内部表格使用完整外框和统一行分隔；账号容量区域不再展示八张逐槽背包容量卡，仅保留携带风险汇总。
