# T45：商人真实推荐

> 状态：📝 候选方案，待细化与排期
> 优先级：P0
> 类型：推荐决策

## 1. 目标

让商人页的推荐状态建立在当前售卖武器的真实 Roll 与已启用推荐来源之上，使玩家可以可信地筛选值得检查的 Offer，不再把异域品质或稀有度误当成推荐结论。

## 2. 核心场景

- 玩家进入 Xur 或其他商人，只查看实际命中推荐来源的售卖武器。
- 卡片先显示短推荐结论，详情再展示来源、命中 Perk 和未满足条件。
- 推荐数据缺失或 Roll 不完整时，基础库存仍可浏览且状态明确降级。

## 3. 功能范围

### 3.1 推荐输入

- 只对能够确认物品身份和实际 Roll 的武器生成 Roll 推荐结论。
- 输入至少包含 `itemHash`、实际 Socket / Plug 和 `rollFingerprint`。
- 复用现有五来源推荐和 DIM Wishlist，不建立商人专用推荐真相。

### 3.2 推荐状态

内部至少区分：

- 完整符合推荐。
- 部分符合推荐。
- 接近 DIM 推荐，并说明缺少项数。
- 来源只推荐武器，没有指定 Roll。
- 明确未符合。
- 推荐未覆盖。
- Roll 数据不完整，无法判断。

卡片可以压缩为短标签，统一详情必须保留来源级解释。

### 3.3 推荐筛选

- “只看推荐”只保留有正向推荐证据的 Offer。
- “未覆盖”“未符合”和“数据不完整”不进入该筛选结果。
- “接近 DIM 推荐”是否进入主筛选必须显式决定，不能静默混入完整推荐。
- 筛选只影响当前商人展示结果，不修改目录总量和底层库存快照。

### 3.4 真实性

- 异域品质不得自动标记为高质量 Roll。
- 品质、稀有度和来源热度不能替代实际 Perk 匹配。
- 推荐失败或未覆盖不改变 Bungie 的购买状态。
- 社区推荐只提供决策证据，不宣称官方结论或绝对必买。

## 4. 数据与性能约束

- 推荐匹配进入现有 Worker 或领域索引，不在 React 渲染中遍历完整 Wishlist。
- 商人列表只消费轻量推荐摘要，来源规则和逐栏证据在统一详情按需加载。
- 推荐缓存至少受 `rollFingerprint`、Manifest 版本、推荐来源 revision 和算法版本约束。
- 推荐资源独立失败，不把商人基础库存降级为不可用。
- Offer 保持只读身份，不伪造账号实例 ID 以复用实例推荐接口。

## 5. 交互要求

- 卡片短标签必须能区分“推荐”“接近”“仅推荐武器”和“无法判断”。
- 状态不得只依赖颜色，并应提供可访问名称。
- “只看推荐”继续使用明确的按压状态与 `aria-pressed`。
- 详情打开后可以追溯推荐来源、命中要求和数据完整性。

## 6. 非目标

- 不为商人建立第二套推荐算法或推荐数据库。
- 不把所有异域、随机 Roll 或高稀有度物品自动视为推荐。
- 不自动购买、锁定或替换账号已有武器。
- 不在列表卡片常驻完整推荐证据。

## 7. 验收标准

- 一个不符合任何推荐的异域武器不会进入“只看推荐”。
- 一个完整命中 DIM Wishlist 的传奇武器会显示推荐摘要，并能在详情查看完整依据。
- 来源只推荐武器但未指定 Roll 时，不冒充完整 Roll 命中。
- Roll 缺失时显示数据不完整，不猜测推荐。
- 推荐资源失败时，商人目录、库存、成本和购买条件仍可使用。

## 8. 待细化问题

- “只看推荐”是否包含“接近 DIM 推荐”，还是另设筛选。
- 卡片短文案如何映射现有七种推荐状态。
- 多来源结论冲突时，列表首层显示“需要比较”还是优先显示最强正向证据。
- 商人 Offer 如何复用现有推荐 Worker 的轻量摘要契约而不引入伪实例。
