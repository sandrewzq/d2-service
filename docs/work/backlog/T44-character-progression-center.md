# T44：光等提升路线

> 状态：🟠 开发完成，待真实账号验收
> 优先级：P1
> 类型：账号页提光决策模块
> 账号菜单合同：[应用工作区账号章节](../references/ui-specs/application-workspaces.md#账号)
> 前置依赖：T42 光等状态与缺口、Bungie CharacterActivities 周挑战与可见奖励

## 1. 玩家要解决的问题

玩家最关心的是：

> 我现在应该刷什么、做哪个奖励，才有机会提高光等？

T44 把真实奖励来源、角色状态和 T42 的光等基线结合起来，给出可执行的优先顺序。

它不是完整的进度百科，也不是活动列表展示，而是一个“下一步做什么”的决策模块。

## 2. 输入与输出

### 2.1 输入

- T42 提供的当前装备、可装备最高、账号奖励掉落基准和逐槽缺口。
- Bungie 返回的 Milestone、活动奖励、完成状态、可用角色和奖励类型。
- Bungie 角色活动 Objective 提供的真实进度与完成状态。
- Manifest 中可见奖励的官方名称；只有明确标注“强力装备 / Powerful Gear”或“巅峰装备 / Pinnacle Gear / 高阶装备”的奖励才进入提光推荐。

### 2.2 输出

每个奖励项目至少要说明：

- 奖励名称和所属活动。
- 应由哪个角色完成。
- 当前状态：可做、已完成、不可用、已过期、读取失败或等待确认。
- 对当前账号光等的价值：可能补低槽、仍有提光机会、已完成或无法确认。
- 推荐优先级和原因。
- 数据来源和更新时间。

推荐文案必须让玩家知道“为什么推荐”，例如：

> 猎人巅峰奖励：当前可做。账号有两个装备槽低于掉落基准，完成后仍有提升机会。

不能写成“必定提升”，除非 Bungie 真实字段明确保证该奖励结果。

## 3. 推荐规则

- 以 T42 的账号奖励掉落基准作为奖励价值基线。
- 先排除已完成、已过期、不可用或明确不会提升的奖励。
- 在可执行奖励中，优先展示仍可能提升当前账号或当前角色的强力、巅峰奖励。
- 如果奖励只对某个角色有效，必须明确标出角色，不能让玩家误以为所有角色都能领取。
- 不能因为某个槽位较低就承诺下一件奖励一定掉该槽位。
- 奖励数据缺失时显示“无法确认奖励价值”，不能依据活动名称、图标或固定周期猜测。
- 推荐排序必须确定性一致，同一 Profile 和同一奖励状态在两台设备上顺序一致。

## 4. 页面位置与加载方式

- 账号页在光等详情与一键最高光等操作之后增加“当前角色提光路线”，位于详细装备列表之前。
- 首层最多展示三项，按“未完成巅峰 → 未完成强力 → 已完成 → 待确认”排序；其余项目进入同区折叠详情。
- 首页首期不增加 T44 卡片，避免重复信息和挤占首屏；账号页是唯一入口。
- 周奖励继续复用首页简报已经读取的 `WeeklySummary`，不由账号页新建刷新、缓存或轮询。
- 分区提供“刷新提光路线”，强制刷新同一份首页简报资源；请求复用既有 in-flight 合并，刷新期间保留旧结果，失败时显示错误但不清空路线。
- 加载中保留上一份已确认结果并显示同步阶段；失败只影响提升路线，不清空其他账号数据。
- 不增加定时轮询。由账号刷新、奖励状态变化或明确的后台进度事件触发更新。

## 5. 实现方案

### 5.1 真实状态

- `packages/core/src/weekly/liveData.ts` 在合并同一活动时保留每个角色的挑战 Objective、进度和完成状态。
- 同名活动如果由多个活动 Hash 返回，会合并奖励、证据 Hash 和角色状态，不因去重丢失某个角色的完成情况。
- 当前角色存在活动但没有对应 Objective，或 Bungie 没有返回该角色活动时，显示“当前无可领取挑战”；它可能已经完成或当前不可用，但不会被猜成“已完成”，也不会算作可做奖励。只有旧数据缺少整个角色状态字段时才显示“角色状态待确认”。

### 5.2 提光判断

- `packages/app/src/workspaces/accountPowerRoute.ts` 消费 T42 的奖励掉落基准和逐槽差值，不复制八槽光等算法。
- 周挑战奖励按匹配 Objective 从 Manifest 活动挑战的 `displayRewards[].itemQuantity` 读取，并兼容仍使用 `dummyRewards` 的旧定义；不再使用 `availableActivities.visibleRewards` 中的活动普通掉落代替周挑战奖励。
- 只有挑战奖励定义明确属于强力或巅峰、并且当前角色挑战未完成的项目，才计入“已确认奖励可做”。
- 有低于基准的槽位时解释为“可能补齐低光槽位”；八槽齐平时只说明“仍有提光机会”。两种情况都明确提示奖励槽位随机。
- “突袭装备”“深视武器”、日落武器等无法证明提光等级的普通奖励完全退出提光路线，不进入首层、折叠区、推荐数量和优先排序。

### 5.3 玩家可见结果

账号页会直接显示：

- 当前角色名称、奖励掉落基准和已确认可做数量。
- 推荐活动、活动类型、奖励类型、完成状态和 Objective 进度。
- 低光槽位及推荐原因。
- Bungie 数据来源和每周重置时间。

玩家不需要先理解八槽算法，就能看到“下一步做哪个已确认奖励”和“为什么推荐”。

## 6. 非目标

- 不复制 DIM 的完整 Progress、Milestones、Ranks 或 Pathfinder 页面。
- 不在 T44 重新实现光等计算；所有基准来自 T42。
- 不把 T43 的任务、赏金和赛季挑战全部混入提光路线；只有能证明奖励等级的周挑战属于 T44。
- 第一阶段不包含赛季等级、声望等级、成就树、收藏品和完整活动百科。
- 不提供自动领取、自动完成、自动装备或其他写操作。
- 不用固定活动周期、奖励图标或名称关键词伪造推荐。

## 7. 验收标准

- 玩家能在一个区域看到“现在做什么可能提高光等”。
- 每条建议都能解释所属角色、奖励状态、提升价值和推荐原因。
- 奖励价值与 T42 的真实掉落基准一致，不重复计算或使用固定标签。
- 已完成、过期、不可用和读取失败的奖励不会被显示为可执行提升项。
- 账号装备首屏不因奖励进度请求变慢或失败。
- 切换三个角色后，同一活动按各角色自己的 Objective 状态显示“本周可做 / 本周已完成 / 当前无可领取挑战”；只有旧数据缺少角色状态字段时才显示“角色状态待确认”。
- 同一账号的相同服务器 Profile 在两台设备上得到相同的结果和排序。

### 7.1 真实账号验收步骤

1. 打开账号页，确认角色切换区下方出现“提光路线”，掉落基准与光等详情一致。
2. 分别切换三个角色，核对可做数量和每项完成状态是否与游戏内周挑战一致。
3. 找一个已完成或当前不再返回挑战的活动，确认它不再被列为优先可做；仍能确认挑战奖励为强力或巅峰时，进入“当前无可领取挑战”区域。
4. 找一个挑战奖励明确写为强力或巅峰的未完成挑战，确认它进入推荐；活动普通掉落只写武器名、“突袭装备”或“深视武器”时不得出现在提光路线。
5. 核对低光槽位说明；页面只能写“可能补齐”，不能承诺掉到指定槽位。
