# T44：光等提升路线

> 状态：📝 需求已重新梳理，待排期
> 优先级：P1
> 类型：独立异步奖励分析
> 账号菜单合同：[应用工作区账号章节](../references/ui-specs/application-workspaces.md#账号)
> 前置依赖：T42 光等状态与缺口、T43 任务待处理状态

## 1. 玩家要解决的问题

玩家最关心的是：

> 我现在应该刷什么、做哪个奖励，才有机会提高光等？

T44 把真实奖励来源、角色状态和 T42 的光等基线结合起来，给出可执行的优先顺序。

它不是完整的进度百科，也不是活动列表展示，而是一个“下一步做什么”的决策模块。

## 2. 输入与输出

### 2.1 输入

- T42 提供的当前装备、可装备最高、账号奖励掉落基准和逐槽缺口。
- Bungie 返回的 Milestone、活动奖励、完成状态、可用角色和奖励类型。
- T43 提供的任务完成、追踪、过期和待领取状态。
- Manifest 中已确认的奖励类型、强力上限和巅峰上限。

### 2.2 输出

每个奖励项目至少要说明：

- 奖励名称和所属活动。
- 应由哪个角色完成。
- 当前状态：可做、已完成、不可用、已过期、读取失败或等待确认。
- 对当前账号光等的价值：可能提升、只补低槽、不会提升、无法确认。
- 推荐优先级和原因。
- 数据来源和更新时间。

推荐文案必须让玩家知道“为什么推荐”，例如：

> 猎人巅峰奖励：当前可做。账号有两个装备槽低于掉落基准，完成后仍有提升机会。

不能写成“必定提升”，除非 Bungie 真实字段明确保证该奖励结果。

## 3. 推荐规则

- 以 T42 的账号奖励掉落基准作为奖励价值基线。
- 先排除已完成、已过期、不可用或明确不会提升的奖励。
- 在可执行奖励中，优先展示仍可能提升当前账号或当前角色的强力、巅峰奖励。
- 如果奖励只对某个角色有效，必须明确标出角色，不能让玩家误以为所有角色都能领取。
- 不能因为某个槽位较低就承诺下一件奖励一定掉该槽位。
- 奖励数据缺失时显示“无法确认奖励价值”，不能依据活动名称、图标或固定周期猜测。
- 推荐排序必须确定性一致，同一 Profile 和同一奖励状态在两台设备上顺序一致。

## 4. 页面位置与加载方式

- 账号页增加“光等提升路线”分区，放在光等状态摘要之后、详细装备列表之前或作为同级折叠区。
- 首页只消费压缩后的前几项摘要，不复制完整奖励列表。
- 进度数据作为独立异步资源加载，不阻塞账号装备、容量和仓库首屏。
- 加载中保留上一份已确认结果并显示同步阶段；失败只影响提升路线，不清空其他账号数据。
- 不增加定时轮询。由账号刷新、奖励状态变化或明确的后台进度事件触发更新。

## 5. 非目标

- 不复制 DIM 的完整 Progress、Milestones、Ranks 或 Pathfinder 页面。
- 不在 T44 重新实现光等计算；所有基准来自 T42。
- 不在 T44 重新解析任务分类；任务状态来自 T43。
- 第一阶段不包含赛季等级、声望等级、成就树、收藏品和完整活动百科。
- 不提供自动领取、自动完成、自动装备或其他写操作。
- 不用固定活动周期、奖励图标或名称关键词伪造推荐。

## 6. 验收标准

- 玩家能在一个区域看到“现在做什么可能提高光等”。
- 每条建议都能解释所属角色、奖励状态、提升价值和推荐原因。
- 奖励价值与 T42 的真实掉落基准一致，不重复计算或使用固定标签。
- 已完成、过期、不可用和读取失败的奖励不会被显示为可执行提升项。
- 账号装备首屏不因奖励进度请求变慢或失败。
- 首页和账号页对同一奖励使用相同的标准化状态和价值说明。
- 同一账号的相同服务器 Profile 在两台设备上得到相同的结果和排序。
