# T24：账号菜单角色准备与风险中心需求组总览

> 状态：📝 需求组总览，不作为独立实施任务
> 优先级：P1
> 参考项目：DIM 8.139.0
> 影响边界：账号领域模型、账号共享 Store、Desktop 数据 adapter、`packages/app` 账号 workspace、`packages/ui` 账号菜单与 UI 合同

## 1. 产品结论

账号菜单不复制 DIM 的完整库存管理器，而是收敛为“角色状态与待处理中心”，优先回答：

1. 当前角色是否安全，是否存在邮政官、背包或仓库容量风险。
2. 当前角色是否已经准备好进入活动，光等和装备还缺什么。
3. 当前最需要处理哪些任务、奖励和进度。

跨角色库存浏览与整理继续归仓库菜单，配装列表、编辑和执行继续归配装菜单，活动总览继续归首页。账号菜单只承载当前角色状态、账号级风险和需要玩家立即处理的事项，避免再次形成职责重叠的“大而全”页面。

## 2. 当前基线

账号菜单已经具备：

- 三角色切换、当前装备光等和账号最高可装备光等。
- 当前装备与角色背包按槽位对比、统一装备详情入口。
- 最高光等方案预览和一键装备。
- 角色物品与配置、任务与赏金、邮政官、材料与货币、账号战绩。
- 账号、仓库和配装菜单共享同一账号 Store 与同步状态。

当前主要缺口不是更多库存卡片，而是缺少容量风险、可处理事项、掉落光等决策信息以及可靠的任务进度结构。

## 3. DIM 参考结论

DIM 中值得借鉴的账号相关能力包括：

- 角色背包、邮政官和仓库容量展示及接近满预警。
- 当前光等、最高可装备光等、掉落基准和各槽位贡献。
- 邮政官批量取回以及取回前的空间处理。
- 任务的到期、追踪、完成状态和目标进度。
- 强力与巅峰奖励、赛季等级、声望和角色进度。
- 新掉落 Feed 和跨角色状态概览。

本项目只借鉴这些能力解决的玩家问题，不照搬 DIM 的横向库存布局、拖拽交互、Farming Mode 或完整 Progress 页面结构。

## 4. 文档拆分与实施边界

T24 只统一产品方向、菜单边界和需求关系，不作为一次性大型开发任务，也不单独进入当前任务表。实际实施拆成五个拥有独立 T 编号、可持续细化、独立排期、独立验收和独立发布的大需求：

| 大需求 | 优先级 | 类型 | 主要交付 | 依赖 | 详细文档 |
|---|---:|---|---|---|---|
| T40 | P0 | 只读状态 | 邮政官、仓库、角色背包容量与风险 | 现有账号快照 | [账号容量与风险摘要](T40-account-capacity-risk.md) |
| T41 | P0 | 高风险写操作 | 邮政官安全批量取回计划与逐项确认 | T40 | [邮政官安全处理](T41-postmaster-safe-actions.md) |
| T42 | P0 | 领域计算 | 掉落基准、逐槽光等缺口与保留提示 | 账号实例与最高光等规则 | [光等成长分析](T42-power-growth-analysis.md) |
| T43 | P1 | 结构化读取 | 完成、到期、追踪和目标进度 | Objective 数据链 | [任务待处理中心](T43-pursuit-attention-center.md) |
| T44 | P2 | 独立异步资源 | 强力、巅峰、赛季和主要声望 | Progression 与活动数据链 | [角色进度中心](T44-character-progression-center.md) |

推荐交付顺序为 `T40 → T42 → T41 → T43 → T44`：先建立真实只读状态和光等解释，再扩大到邮政官批量写入；任务与进度数据最后独立扩展，避免阻塞账号装备首屏。

## 5. 聚合能力不单独立项

### 5.1 三角色待处理对比

三角色对比是五个大需求的聚合视图，不单独创建第六个实施任务：

- T40 完成后显示邮政官和背包容量风险。
- T42 完成后增加当前光等与最高可装备光等差距。
- T43 完成后增加待领取和即将过期数量。
- T44 完成后增加本周奖励与角色进度状态。

每个阶段只展示已经接入真实数据并可说明更新时间的字段，不预留假数字、空壳按钮或静态演示状态。

### 5.2 新装备同步摘要

新装备识别、历史记录和完整 Feed 不属于 T24。它们应由共享账号 Store 或仓库领域维护，账号菜单未来只能消费“本次同步发现 N 件新装备”的摘要，不能在账号菜单重新维护一套新装备状态。

## 6. 建议的信息架构

进入开发前，应评估把现有六个平级分区收敛为以下玩家意图：

1. **角色装备**：当前装备、角色背包、最高光等和掉落基准。
2. **待处理**：邮政官、容量风险、待领取奖励和即将过期任务。
3. **角色进度**：任务与赏金、强力与巅峰奖励、赛季和声望。
4. **账号资源**：材料、货币和账号级资源。

近期战绩作为次级入口或独立模块，不与角色成长进度混为一谈。

当前账号 UI 合同固定了六个目录分区。本 backlog 进入实现前，必须先更新 `docs/work/references/ui-specs/application-workspaces.md` 并确认新旧功能位置，不能直接删除、隐藏或合并现有真实能力。

## 7. 同步与真实性约束

- 所有能力继续消费账号、仓库和配装菜单共享的中央账号 Store，不建立账号菜单私有刷新模型。
- 容量、位置、光等和邮政官状态只能来自 Bungie Profile 与本地明确确认的写操作投影，不能根据 UI 是否出现卡片推断。
- 手动同步、后台同步和写后确认必须明确区分“请求完成”“服务器版本前进”“目标状态已确认”。
- 页面必须持续显示同步阶段和数据时间，不能在 Profile 尚未确认时让玩家误以为同步已经完成。
- 写操作成功但服务器 Profile 暂未反映时，保留预计状态并显示“等待游戏状态”；只有更新的服务器版本明确冲突时才撤销。
- 两台设备可能在不同时间拿到不同 Profile 版本，因此 UI 必须展示服务器数据时间或版本，并禁止旧快照覆盖新快照。
- 进度资源与装备资源独立失败，任何非核心进度请求不得阻塞角色装备和容量风险首屏。

## 8. 总体非目标

- 不在账号菜单复制仓库页的跨角色拖拽、筛选和库存整理。
- 不在账号菜单复制配装页的完整配装列表、编辑器和迁移工作台。
- 不把收藏品、成就树、催化剂和外观收藏塞入账号菜单，这些能力归资料库。
- 不在 T24 内实现新装备识别、历史记录或完整 Feed。
- 不实现持续自动搬运的 Farming Mode。
- 不实现随机配装。
- 不把所有 DIM Progress 内容一次性加入现有账号快照。
- 不使用 mock 数量、固定容量、关键词猜测或假进度冒充真实账号状态。

## 9. 总体验收标准

- 玩家无需进入多个页面即可判断当前角色是否存在容量风险和待处理事项。
- 邮政官、仓库及角色背包容量来自真实数据，状态与游戏内一致。
- 邮政官批量操作执行前有完整计划，执行后逐项显示真实结果和确认状态。
- 光等视图能够区分当前装备、最高可装备和掉落基准，并准确展示逐槽差值。
- 任务状态基于真实目标、完成、追踪和到期字段，不依赖名称关键词猜测。
- 三角色对比不会混淆角色级数据与账号级数据。
- 赛季与声望等扩展资源不会阻塞装备首屏或拖慢常规账号同步。
- 账号、仓库、配装和首页继续共享一致的数据真相与同步语义。
- Web 与 Desktop 继续消费 `packages/ui` 的同一账号页面，不复制产品实现。
- 加载、空、部分失败、过期、等待确认和明确冲突均有可区分的玩家状态。

## 10. 后续启动条件

1. 用户明确决定启动某一个独立大需求。
2. 启动 T40 前先确定容量字段是否已完整进入账号快照，缺失字段再设计领域和 transport 扩展。
3. 更新账号菜单 UI 合同，冻结“待处理”入口和现有六个分区的迁移方式。
4. 每次只把一个大需求加入当前开发范围，分别细化范围和维护验收结果，不把五个需求合并成一次大型改造。
