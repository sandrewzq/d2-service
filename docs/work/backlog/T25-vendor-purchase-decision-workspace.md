## 2. 产品结论

商人菜单下一阶段从“库存浏览器”升级为“购买决策页”，优先回答：

1. 当前售卖 Roll 是否符合已启用的推荐来源。
2. 玩家是否已经拥有或解锁，账号里是否有更好的同名实例。
3. 本次刷新后新增、变化和下架了什么。
4. 商人护甲能否改善当前 Armor 3.0 规划。
5. 关注的武器、Perk、收藏缺口或护甲条件出现时，是否需要提醒。

目录、搜索、分区、购买条件、成本、声望和统一详情继续保留。T25 不重新设计商人页基础布局，也不复制参考项目页面。

## 3. 稳定边界

- 商人页只展示账号页选定的当前角色。
- 不恢复商人页角色选择器，不合并多角色库存。
- 刷新由明确事件触发，不增加固定间隔轮询。
- Xur 到访 / 离开的低频边界定时器继续保留。
- Bungie API 和 Destiny Manifest 是库存、购买条件、材料、收藏和时间的官方事实来源。
- 社区推荐只提供购买决策证据，不覆盖 Bungie 事实。
- 商人物品保持 Offer 身份，不伪造账号实例 ID。
- 应用不直接购买商人物品；购买继续在游戏内完成。
- Web 与 Desktop 继续消费 `packages/ui` 的同一商人页面。

## 5. 当前基线

商人菜单已经具备：

- 地点目录和单商人详情两栏结构。
- 商人、物品和分类搜索。
- 当前角色与机灵护甲师模组上下文。
- 可负担筛选、推荐筛选、购买条件和材料持有量。
- 声望等级、完整库存分区、子库存、任务和服务。
- 武器与护甲 Roll、属性、插槽及统一详情入口。
- 商人切换短防抖、账号页角色变化、手动刷新和 Xur 边界刷新。
- 缓存优先、后台更新、后发请求优先和失败后保留已有库存。

当前关键问题：

- “只看推荐”没有消费真实推荐匹配；异域品质目前可能被直接当成高质量售卖实例。
- 卡片没有账号实际拥有数量、收藏解锁状态和同名实例差异。
- 刷新只表达整体是否变化，没有新增、Roll 变化和下架摘要。
- 商人护甲没有进入 Armor Planner。
- 没有持久化关注规则和事件驱动提醒。

## 6. 实施与验收原则

- 每次只启动一个切片，避免同时触碰推荐、账号资源、事件系统、配装和通知。
- 进入切片开发前，先从产品需求文档提取对应需求 ID 和验收场景。
- 涉及共享推荐、账号索引、同名比较或配装 DTO 时，先确定共享层边界，禁止 feature 直接互相依赖。
- 产品需求变化先更新独立需求文档；技术方案或交付状态变化再更新对应切片文档和本总纲。
- 每个切片完成后单独验收；不要求等待全部 T25 能力一起发布。
