# T49：商人关注与提醒

> 状态：📝 候选方案，等待前置需求
> 优先级：P2
> 类型：关注规则与事件驱动提醒
> 前置条件：[T46 商人账号上下文](T46-vendor-account-context.md)

## 1. 目标

允许玩家关注特定物品、收藏缺口或护甲条件，并只在明确商人刷新事件确认命中后提醒一次。它解决的是“我不想每周手动检查”，不是重复展示商人当前 Roll。

## 2. 可关注对象

- 指定武器、异域装备、模组或着色器身份。
- 指定尚未解锁或账号未拥有的物品。
- 满足职业、部位、总属性或关键属性条件的护甲。
- 指定商人或全部可读取商人。

不默认支持“推荐来源命中”作为关注条件；若未来确有需求，应先证明现有游戏信息和 T46/T48 派生数据无法满足，再另立需求。

规则必须明确身份范围、条件组合和适用商人，不能依赖中文名称模糊匹配。

## 3. 触发规则

- 只在现有明确商人刷新事件成功后运行匹配，不依赖商人历史差异或库存变更系统。
- 不为通知新增固定间隔轮询。
- 账号拥有、收藏、属性或购买条件数据不完整时，不发送肯定命中通知。
- 只对当前可确认的 Offer 运行匹配；过期缓存不能触发新提醒。
- 账号角色上下文变化时，打开提醒必须重新确认购买状态。

## 4. 去重与生命周期

- 使用关注规则 ID、Offer 身份、配置指纹和刷新周期去重。
- 同一 Offer 在同一刷新周期只提醒一次。
- Offer 配置、购买条件或刷新周期变化后可以重新评估。
- 规则可以创建、查看、停用和删除。
- 规则与最小去重状态本地持久化，不上传账号隐私或完整库存。

## 5. 提醒表达

- 应用内提醒包含商人、物品、命中原因、购买状态和截止时间。
- 系统通知为可选能力，遵循现有通知设置和平台权限。
- 点击提醒后定位到账号页当前角色对应的商人和 Offer。
- Offer 已过期、角色上下文变化或库存刷新失败时，打开页面必须重新确认。
- 提醒状态不得只用颜色，并允许玩家回到具体事实来源。

## 6. 性能与隐私约束

- 关注匹配复用账号拥有、收藏、变化和护甲派生结果，不重复计算完整库存。
- 不发送 OAuth Token、Cookie、会员 ID、角色长 ID 或完整库存到第三方通知服务。
- 系统通知不展示敏感诊断字段。
- 关注匹配不能阻塞商人库存刷新完成。

## 7. 非目标

- 不为提醒建立常驻高频商人轮询。
- 不在通知中提供直接购买动作。
- 不对数据不完整的 Offer 猜测命中。
- 不把关注规则与装备目标隐式合并。
- 不实现跨设备云同步，除非后续另立明确需求。

## 8. 验收标准

- 明确刷新完成并命中规则时提醒一次。
- 同一刷新周期重复进入商人页不会重复提醒。
- 账号上下文或护甲数据不完整时不会发送肯定命中通知。
- 通知点击后能定位到正确角色、商人和 Offer。
- Offer 已过期时不会继续表现为可购买。
- 停用或删除规则后不再产生新提醒。

## 9. 待细化问题

- 是否复用现有装备目标，还是保持独立的“售卖关注”模型。
- 应用内提醒进入后台任务 Dock、消息中心还是商人菜单局部状态。
- 系统通知的默认开关、平台权限失败和免打扰策略。
- 规则数量上限、复杂组合表达和导入导出需求。
