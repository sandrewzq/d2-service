# T46：商人账号上下文

> 状态：📝 候选方案，待细化与排期
> 优先级：P1
> 类型：账号事实与同名比较

## 1. 目标

让玩家在商人页准确区分账号实际拥有、收藏解锁、商人 Owned 状态和购买限制，并能把当前 Offer 与账号内同身份装备进行只读比较，减少重复购买和无依据判断。

## 2. 核心场景

- 玩家看到模组、着色器、异域装备或武器时，可以判断账号是否存在真实实例。
- 收藏已解锁但账号当前没有实例时，两个状态分别表达。
- 玩家可以比较售卖 Roll 与账号同身份实例，判断是否补齐新组合。
- 商人头部只显示当前库存实际使用的相关材料和缺口。

## 3. 实际拥有与收藏

### 3.1 账号实际拥有

- 汇总仓库、所有角色已装备、背包和邮政官中的同身份实例。
- 卡片显示“账号已有 N 件”；为零时可显示“账号未拥有”。
- 数量来自中央账号实体 Store，不建立商人页私有账号快照。
- 身份归并必须遵守发布身份和 canonical identity 规则，避免同名物品错误合并。

### 3.2 收藏解锁

- 使用 Bungie Collectibles 状态表达“已解锁 / 尚未解锁”。
- Collectibles 未读取、失败或不适用时显示未知或隐藏，不根据库存反推。
- Collectibles 作为独立异步资源，不阻塞商人库存与账号装备首屏。

### 3.3 状态区分

以下事实不得合并为一个“已拥有”勾选：

- 当前账号存在真实实例。
- 收藏中已解锁。
- 商人 API 标记 Owned。
- 当前 Offer 因购买上限或已领取而不可购买。

### 3.4 筛选

- “只看未拥有”使用账号真实实例数量。
- “只看未解锁”只有在 Collectibles 数据稳定后才开放。
- 筛选不修改底层快照、目录总量或其他商人的缓存状态。

## 4. 同名实例比较

- 武器和护甲统一详情显示账号内同身份实例数量。
- 商人 Offer 作为只读候选参加同名比较，没有玩家实例 ID。
- 武器比较实际 Perk、推荐来源命中和数据完整性，并显示账号实例真实位置。
- 可以说明“新增了账号内没有的推荐组合”，但无确定性规则时不得显示“绝对升级”。
- 护甲比较总属性、各项属性和同职业同部位实例；普通比较不等于 Armor Planner 结论。
- 商人 Offer 不显示转移、锁定、穿戴或拆解等实例操作。

## 5. 商人相关材料

- 商人头部只展示当前商人 Offer 实际使用的材料。
- 显示持有数量与主要缺口。
- 不根据余额推断“可购买 N 次”，因为购买上限和其他条件可能独立存在。
- 如后续增加“隐藏银币商品”，必须使用官方银币 Hash 和真实成本判断，不根据中文分类名猜测。

## 6. 数据与性能约束

- 账号拥有摘要按稳定身份建立可复用索引，位置 Patch 不重算无关 Offer。
- Collectibles 独立缓存和过期，不加入每次装备写操作的同步链。
- 商人列表消费轻量拥有摘要，同名实例和完整比较数据只在详情按需读取。
- 当前角色仍由账号页决定；账号页切换角色后，商人页不得继续展示旧角色购买上下文。
- 增强资源部分失败时，已成功的拥有数量、收藏或比较资源继续独立显示。

## 7. 非目标

- 不在商人页恢复角色选择器或合并多角色商人库存。
- 不根据库存反推 Collectibles 解锁状态。
- 不把商人 Offer 转换成可写账号实例。
- 不在本需求实现完整 Armor Planner 接入。
- 不提供应用内购买。

## 8. 验收标准

- 账号中存在三个同身份实例时显示“账号已有 3 件”。
- 收藏已解锁但账号无实例时，两个状态分别显示。
- Collectibles 请求失败时，账号实际拥有数量仍然可用。
- 从商人 Offer 可以打开账号同名比较，且不会出现实例写操作。
- 同名但不同发布身份的武器不会错误合并。
- 商人材料摘要只包含当前库存真实使用的货币或材料。

## 9. 待细化问题

- Collectibles 应按账号一次读取，还是按当前商人涉及的 Collectible 按需读取。
- 同名比较默认选择推荐最强实例，还是只按位置和时间排序。
- 卡片同时出现推荐、拥有、收藏和变化状态时的视觉优先级。
- 材料摘要的最大展示数量与缺口排序规则。
