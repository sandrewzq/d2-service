# T43：任务待处理中心

> 状态：📝 候选方案，待排期
> 优先级：P1
> 类型：结构化任务读取
> 账号菜单合同：[应用工作区账号章节](../references/ui-specs/application-workspaces.md#账号)
> 关联需求：T44 角色进度中心可以消费本需求形成的待处理摘要，但两者独立加载和失败

## 1. 目标

把账号页当前依赖名称关键词的任务分类升级为真实结构化状态，让玩家优先看到已经完成、即将过期和正在追踪的事项。

## 2. 范围

- 已完成待领取的任务、赏金或奖励。
- 即将过期事项及剩余时间。
- 当前正在追踪的事项。
- Objective 当前值、完成值和任务步骤。
- 所属活动、商人、赛季或任务链信息。
- 当前角色待处理摘要；三角色概览增加待领取和即将过期数量。

账号首屏只显示异常和待处理摘要，完整清单继续留在任务分区，不复制 DIM 的大型任务墙。

## 3. 数据与分类约束

- 优先使用 Objective、expiration、tracked、complete 和 Manifest 关系，不使用名称关键词作为业务真相。
- 如果当前快照缺少 `ItemObjectives`、`ItemPlugObjectives` 或其他必要组件，应扩展独立、明确的数据链并评估 payload。
- 任务、赏金、赛季神器和其他追踪物必须依据稳定 bucket、item type 与 definition 关系分类。
- 任务数据失败不能阻塞角色装备、容量或邮政官读取。
- 到期时间必须基于服务器字段和明确时区转换，不能使用本地猜测规则。

## 4. 非目标

- 不在本需求实现强力、巅峰、赛季等级或声望进度。
- 不把收藏品、成就树和催化剂进度迁入账号菜单。
- 不实现静态攻略或任务步骤百科。
- 不使用固定完成百分比或演示任务补齐空态。

## 5. 验收标准

- 完成、过期、追踪和目标进度均来自真实字段。
- 同名任务或本地化名称变化不会改变分类结果。
- 玩家可以一眼识别当前最需要领取或处理的事项。
- 三角色数量只聚合对应角色的真实任务状态，不混入账号级项目。
- 数据缺失和部分失败有明确说明，不回退到可能误判的名称猜测结果。
