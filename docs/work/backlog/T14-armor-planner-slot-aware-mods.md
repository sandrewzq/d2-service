# T14：应用配装与逐部位护甲规划

> 状态：✅ 已完成、已验收并随 v0.0.22 发布
> 范围：已冻结
> 优先级：P1

## 交付结果

T14 将配装功能收敛为两个明确对象：

- `游戏内配装`：读取和管理 Bungie 官方配装槽位。
- `应用配装`：保存、比较、编辑和安全穿戴本应用的完整构筑方案。

应用配装的主流程固定为：

```text
方案库
  → 查看或比较方案
  → 新建 / 编辑完整构筑
  → 按属性目标自动配甲
  → 接受候选
  → 穿戴前复核
  → 玩家确认执行
```

自动配甲是完整构筑编辑器内的护甲能力，不是独立一级页面、方案类型或来源。

## 最终产品合同

### 配装身份

- 游戏内配装与应用配装保持独立，不使用来源筛选混合两类对象。
- DIM、攻略、当前装备和游戏内槽位复制只作为创建应用配装的入口，不建立平行页面。
- 应用配装默认进入方案库；选择方案先显示只读详情，显式编辑后才创建草稿。
- 玩家可比较 2–3 个应用配装；比较不会修改草稿。

### 逐部位护甲规则

头盔、臂铠、胸甲、腿甲和职业物品分别保存真实规则：

- `自动`
- `不装`
- `+5`
- `+10`

选择 `+5 / +10` 后可以锁定具体属性。两个 `+5` 必须保存为两个独立部位、Socket 和 Plug 计划，不能只保存聚合数量。

- 求解前先扣除每件护甲已有功能模组的能量。
- 属性模组成本和兼容性来自当前资料库与版本化规则，不按部位硬编码。
- T5 护甲调整按零能量独立计算，不计入属性模组数量。
- 固定部位无法安装时不得自动移动、降级或删除要求。
- 数据不完整时返回不确定或不可执行状态，不使用默认值伪造候选。
- 修改目标、部位规则或其他模组后，旧候选立即失效。

### 保存与执行

- 草稿保存五件实例、逐部位规则、属性模组 Socket、Plug、能量成本和最终属性。
- 旧全局 `+5 / +10` 数量方案保持可读，但编辑和执行前必须确认具体部位。
- 穿戴前重新核对账号版本、实例位置、Socket、Plug、能量和异域限制。
- 任一固定规则无法满足时整份执行计划保持零写入。
- Bungie 不支持自动写入的 Plug 明确标记为需要玩家手动设置。
- 只有穿戴并刷新验证成功后，才允许将当前装备保存到游戏内槽位。

### 页面与交互

- 宽屏为配装设置和推荐方案两部分，方案摘要位于推荐结果顶部。
- 中等宽度收拢摘要；窄屏在设置、推荐和摘要之间切换，不纵向堆成长页面。
- 三件武器使用紧凑横排，五件护甲和逐部位模组规则是编辑器主内容。
- 装备选择使用可搜索抽屉，并在关闭后恢复来源槽位焦点。
- 普通玩家路径不展示 `Socket / Plug / Manifest` 等底层术语。
- Web 与 Desktop 消费同一份共享配装页面，不复制产品结构。

## 架构边界

- 领域模型、求解、可达性和执行计划位于 `packages/core`。
- 跨端 ViewModel 与页面状态位于 `packages/app`。
- 产品页面和响应式交互位于 `packages/ui/src/loadouts/`。
- Desktop 只接真实账号、资料库和 Bungie 写操作 adapter。
- 账号刷新、缓存和水位线统一遵循 [开发说明](../../development.md)，配装不得维护第二套账号状态。
- 共享页面结构遵循 [应用工作区合同](../references/ui-specs/application-workspaces.md)。

## 验收结论

- 游戏内配装与应用配装能够清楚区分。
- 五个部位可以独立设置自动、不装、`+5` 或 `+10`。
- 候选、摘要、保存恢复和穿戴复核使用同一套逐部位规则。
- 编辑器在宽屏、中屏和窄屏下保持可操作，焦点和未保存状态能够恢复。
- 真实账号流程和实窗交互已经验收，并随 v0.0.22 发布。

## 后续边界

T14 不再追加功能。新的配装编辑、护甲规则或 Bungie 写入能力建立独立任务；明确回归登记独立 Bug。
