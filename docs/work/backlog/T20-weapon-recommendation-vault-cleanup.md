# T20：武器推荐与仓库整理

> 状态：✅ 已完成、已验收并随 v0.0.22 发布
> 范围：已冻结
> 优先级：P1

## 交付结果

T20 建立了从推荐数据导入、实例 Roll 核对到仓库整理的完整玩家流程：

```text
浏览装备
  → 选择推荐来源
  → 查看核心 Perk x/y 与完整 x/y
  → 比较同名实例
  → 玩家标记、锁定、解锁或转移
  → 玩家在游戏内决定是否分解
```

应用只提供依据和安全操作，不自动生成“应该分解”的结论，也不自动锁定、解锁、转移或分解装备。

## 推荐数据合同

应用维护两条独立数据链：

- Aegis、LGpig、YXCRALLXY、Sayalarry 使用严格人工推荐 CSV，经当前资料库语义校验后写入本地 SQLite。
- DIM 使用原生 Wishlist 的 `itemHash + perkHash` 完整组合，不转换为人工 CSV，也不与人工候选池合并。

稳定规则：

- 普通玩家使用 13 列简表；维护者完整数据包保留 31 列兼容格式。
- 武器和推荐项只接受官方 Hash 或规范化后的官方全名精确匹配。
- 禁止简称、同义词、包含匹配和大师属性词干猜测。
- 异常行单独忽略；有效行合并更新，不要求玩家重新导入全部数据。
- 未经过当前语义版本验证的旧人工库标记为 `unverified`，不参与匹配、保护或整理。
- 来源停用和规则排除使用稳定规则 ID 保存，导入新 revision 时不得静默丢失。
- DIM 在线更新失败时继续使用上一版已激活数据。

## 匹配与展示合同

- 每个 `instanceId` 使用自身实际拥有的 Roll 独立计算。
- 人工来源按栏位保存候选池，同栏任选其一，不生成笛卡尔积组合。
- DIM 一行代表一套完整组合，多套组合互为备选，不跨组合累计 Perk。
- 玩家首层先看实际要求的 `Perk x/y`，再看全部明确要求栏位的 `完整 x/y`。
- DIM 显示“符合 n 套 · 最佳组合 x/y”，并固定排在人工来源之后。
- 未要求、未收录、无法判断和明确不符保持独立，不使用“待核对”“数据未获取”等含混文案。
- 推荐卡片、筛选、同名整理和详情复用同一份实例匹配结果。
- 资料库定义详情只展示来源原始的 Perk 池或完整组合，不显示玩家实例命中。

武器发布版本、专家、失时、痛苦和全息箔的受控身份关系属于 v0.0.22 之后的新能力，其已验收成果与下一版本性能依赖统一收敛到 [T22](T22-renderer-event-driven-performance.md)。

## 仓库工作流

- 浏览筛选、推荐筛选和批量选择保持独立职责。
- 整理状态只提供“保留 / 待定 / 清理”。
- 可按来源、核心 Perk 命中数、完整命中数或 DIM 最佳组合筛选。
- 实例卡支持加锁、解锁；仓库实例可以取出到当前角色。
- 同名整理优先比较 Perk 1 与 Perk 2，并保留完整来源证据入口。
- 批量操作只作用于当前正式筛选结果，并逐项返回成功、跳过和失败摘要。
- 锁定、配装引用、手动保留、独特 Roll、来源冲突、数据不完整和未覆盖装备受到保护。
- 最终分解始终由玩家在 Destiny 2 内完成。

## 同步、缓存与性能

- 账号、仓库、配装和首页消费同一份 Renderer 账号 Store。
- Bungie 写接口成功后立即应用返回的局部 `account_patch`，不创建逐实例 Profile 确认任务。
- 相同或更旧的 Profile 不得覆盖当前页面；后续正常同步负责自然校准。
- 推荐匹配按实例 Roll 指纹、资料库版本、来源 revision 和算法版本缓存。
- 位置、锁定、装备和标签变化不使相同 Roll 的匹配缓存失效。
- 推荐重算异步执行，不阻塞账号快照和仓库列表更新。
- 仓库筛选和卡片复用轻量事实索引，不在渲染热路径遍历完整 Wishlist。
- 列表保持稳定挂载或可见窗口渲染，滚动时不反复测量网格自身。
- 全局 Shell 不订阅普通写操作进度，后台任务更新不得使整个仓库持续重渲染。

账号状态、水位线和写后局部更新遵循 [开发说明](../../development.md)；仓库页面遵循 [应用工作区合同](../references/ui-specs/application-workspaces.md)，装备详情遵循 [装备详情合同](../references/ui-specs/equipment-details.md)。

## 验收结论

- 四个人工来源与 DIM 能够独立导入、启停、纠错和展示。
- 当前完整人工数据包严格校验达到 0 阻塞。
- 推荐状态、数量、Perk 图标和详情证据能够保持一致。
- 单件与批量锁定、解锁、取出和同名整理能够按保护规则执行。
- 后台同步、推荐刷新、来源筛选和列表滚动已经完成真实账号与实窗验收。
- T20 当前范围已经随 v0.0.22 发布。

## 后续边界

T20 不再追加功能。新的推荐来源、版本身份、仓库工作流或性能改造建立独立任务；明确回归登记独立 Bug。
