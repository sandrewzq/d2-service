# 安全说明

这份文档只讲 d2-tools 的安全边界和本地数据边界，不讲功能教程。

## 1. 本地保存了什么

d2-tools 默认把本地数据保存到：

```text
%APPDATA%\d2-tools
```

这里通常包括：

- Bungie 配置
- OAuth token
- 资料库缓存
- 仓库标签
- 本地备注
- DIM 愿望单导入
- 操作日志
- 诊断导出相关内容

## 2. 不会内置什么

公开分发包不会内置：

- 任何人的 Bungie `API Key`
- 任何人的 `Client ID`
- 任何人的 `Client Secret`
- 任何人的个人 token

每个玩家都需要使用自己的 Bungie Application。

## 3. AI 会读取什么

AI 是可选能力。只有你在设置页启用 AI、阅读数据发送范围并明确勾选同意后，模型请求才可能包含：

- 你的问题和当前页面上下文
- 角色摘要
- 背包和仓库摘要
- 装备 roll、perk、标签、备注
- 今日 / 本周摘要
- 活动摘要

请求从本机直接发送到你配置的 AI 服务，不经过 d2-tools 自建服务器。应用只发送完成当前分析所需的结构化摘要，不发送完整本地数据库。

## 4. AI 不会放进模型提示什么

以下内容不会进入模型提示正文：

- Bungie OAuth token
- `Client Secret`
- Bungie `API Key`
- AI 提供方自己的 API Key
- Bungie 账号名、Membership ID 或 Membership Type
- 角色 ID、装备实例 ID、物品 Hash 或 Plug Hash

AI 只负责解释、归纳和建议，不直接接触这些敏感凭据。

AI API Key 必须作为认证请求头发送到你配置的 AI 服务，否则该服务无法验证请求；它不会写入问题、游戏上下文或模型提示正文。Bungie OAuth token、Client Secret 和 Bungie API Key 不会发送到 AI 服务。

旧版本配置、便携备份恢复以及 API 格式或 Base URL 变化后都需要重新确认。玩家主动写进问题、备注或攻略正文的自由文本仍会作为其主动提供的内容发送。完整说明见 [隐私说明](privacy.md)。

## 5. 写操作能做什么

当前写操作包括：

- 锁定 / 解锁
- 装备到角色
- 从仓库取出到角色
- 从角色移入仓库
- 一键装备最高光等

应用不提供额外的本地写操作总开关。执行写操作仍然需要：

1. Bungie 授权具备对应 Scope
2. 当前对象和目标角色满足操作条件
3. 操作前确认；配装计划还需要执行前刷新和复核

## 6. 写操作不能做什么

当前明确不做：

- 直接分解装备
- AI 自动执行写操作
- 无确认的批量高风险操作

这不是暂时没做，而是当前产品边界的一部分。

## 7. 为什么不能直接分解装备

因为分解是不可逆操作，风险太高。

d2-tools 目前只负责：

- 识别疑似可清理装备
- 生成清理清单
- 帮你解锁
- 帮你转移到角色背包
- 提供更易核对的游戏内定位信息

最终分解仍需进游戏手动完成。

## 8. 覆盖安装会不会删掉数据

正常覆盖程序目录时，不会主动删除 `%APPDATA%\d2-tools` 里的本地数据。

也就是说，这些内容一般都能保留：

- Bungie 配置
- token
- 资料库缓存
- 标签和备注
- AI 配置
- 操作日志

真正危险的情况通常是你手动删除了数据目录，或者把整个目录误清空。

## 9. 诊断导出怎么处理敏感信息

诊断导出会尽量自动脱敏，例如：

- token
- `Client Secret`
- API Key 类字段

但任何导出文件在发给别人前，你最好仍然自己再看一眼，不要把完整个人环境目录直接打包外发。

## 10. 你应该怎么做

如果你想把风险降到最低，建议：

- 只在自己的电脑上保存配置
- 不公开包含配置字段的截图
- 不直接分享整个 `%APPDATA%\d2-tools` 目录
- 每次写操作前核对目标装备、角色和确认内容
- 把 AI 当分析助手，不把它当自动执行器
